@lesson Основы: объекты, переменные, строки
В Ruby всё — объект, даже числа: `5.times`, `nil.to_a`. Переменные не объявляют, тип определяется значением.
Строки в двойных кавычках поддерживают интерполяцию `"#{name}"`, в одинарных — нет. Символы `:name` — неизменяемые имена, часто служат ключами хэшей.
Только `nil` и `false` ложны. Ноль, пустая строка и пустой массив — истинны. Методы, возвращающие булево значение, по соглашению заканчиваются на `?`, а опасные (меняющие объект) — на `!`.
```ruby
name = "Ада"
age = 36
puts "#{name}, #{age + 1}"        # Ада, 37
puts 'без #{name}'                # без #{name}

puts 10.even?, 0 ? "истина" : "ложь"   # true, истина
s = "hello"
s.upcase                          # новая строка
s.upcase!                         # меняет s
puts s                            # HELLO
puts 7 / 2, 7.0 / 2, 7.fdiv(2)    # 3, 3.5, 3.5
```
! 0 и "" истинны — в отличие от многих языков
! Метод с ! обычно меняет объект на месте
! puts выводит с переводом строки, print — без

@lesson Условия, циклы и диапазоны
Кроме `if` есть `unless` (если не) и модификаторы в конце строки: `return if user.nil?`. `case/when` сравнивает через `===` и работает с диапазонами и классами.
Циклы `while` и `for` существуют, но идиоматично перебирать коллекции итераторами: `each`, `times`, `upto`, `each_with_index`.
Диапазоны: `1..5` включает 5, `1...5` — нет. Почти любое выражение возвращает значение, в том числе `if` и `case`.
```ruby
age = 20
puts "взрослый" if age >= 18
puts "ребёнок" unless age >= 18

grade = case 85
        when 90.. then "A"
        when 75...90 then "B"
        else "C"
        end
puts grade                          # B

3.times { |i| print i }             # 012
1.upto(3) { |i| print i }           # 123
%w[a b c].each_with_index { |ch, i| puts "#{i}:#{ch}" }
puts (1..10).step(3).to_a.inspect   # [1, 4, 7, 10]
```
! Модификатор `if` в конце строки — для коротких проверок
! `1...5` не включает 5
! %w[a b] — короткая запись массива строк

@lesson Массивы, хэши и блоки
Блок — кусок кода в `{ }` или `do...end`, который передают методу. Методы коллекций принимают блоки: `map`, `select`, `reject`, `reduce`, `find`, `sort_by`, `group_by`.
Хэш хранит пары ключ–значение. Современный синтаксис: `{ name: "Ада", age: 36 }` — ключи-символы. Отсутствующий ключ вернёт nil, `fetch` бросит ошибку или вернёт запасное значение.
Запись `&:method` — сокращение для блока `{ |x| x.method }`.
```ruby
nums = [1, 2, 3, 4, 5]
evens = nums.select(&:even?)                  # [2, 4]
squares = nums.map { |n| n * n }              # [1, 4, 9, 16, 25]
sum = nums.reduce(0) { |acc, n| acc + n }     # 15

users = [{ name: "Ада", city: "Лондон" }, { name: "Алан", city: "Лондон" }]
by_city = users.group_by { |u| u[:city] }
puts by_city["Лондон"].size                   # 2

counts = Hash.new(0)
"a b a".split.each { |w| counts[w] += 1 }
puts counts                                   # {"a"=>2, "b"=>1}
puts users.first.fetch(:email, "нет")         # нет
```
! Hash.new(0) задаёт значение по умолчанию для отсутствующих ключей
! select оставляет, reject убирает
! each возвращает исходную коллекцию, map — новую

@lesson Методы, классы и модули
Метод возвращает последнее вычисленное выражение. Параметры могут быть по умолчанию и именованными: `def greet(name, greeting: "Привет")`.
Класс: `initialize` — конструктор, `@var` — переменная экземпляра, `attr_reader` / `attr_accessor` создают геттеры и сеттеры. `self.method` — метод класса.
Модули группируют методы и подмешиваются в классы через `include` (методы экземпляра) или `extend` (методы класса). Так в Ruby переиспользуют поведение вместо множественного наследования.
```ruby
module Greetable
  def greet = "Привет, #{name}"
end

class User
  include Greetable
  attr_reader :name
  attr_accessor :email

  def initialize(name, email: nil)
    @name = name
    @email = email
  end

  def self.guest = new("Гость")

  def to_s = "User(#{name})"
end

u = User.new("Ада", email: "ada@mail.kz")
puts u.greet, User.guest, u.email
class Admin < User; end
puts Admin.new("Алан").is_a?(User)    # true
```
! attr_accessor создаёт и чтение, и запись
! include — методы экземпляра, extend — методы класса
! Однострочные методы `def x = ...` появились в Ruby 3

@lesson Исключения, файлы и гемы
Ошибки обрабатывают через `begin` / `rescue` / `ensure` (в методе `begin` можно опустить). Своё исключение наследуют от `StandardError`, выбрасывают через `raise`.
Файлы читают и пишут через `File.read`, `File.write` или блок `File.open(...) { |f| }` — файл закроется сам.
Библиотеки (гемы) ставят через `gem install` или описывают в `Gemfile` и устанавливают `bundle install`. Bundler фиксирует версии в `Gemfile.lock`.
```ruby
require "json"

class ConfigError < StandardError; end

def load_config(path)
  data = JSON.parse(File.read(path))
  raise ConfigError, "нет ключа api_key" unless data.key?("api_key")
  data
rescue Errno::ENOENT
  { "api_key" => nil }
rescue JSON::ParserError => e
  raise ConfigError, "битый JSON: #{e.message}"
ensure
  puts "проверка конфигурации завершена"
end

File.open("log.txt", "a") { |f| f.puts "запуск #{Time.now}" }
```

@lesson Rails: MVC и маршруты
Ruby on Rails следует MVC: модель (данные и правила), представление (шаблоны ERB), контроллер (обрабатывает запрос). Принцип «соглашения важнее конфигурации»: правильные имена избавляют от настройки.
Маршруты в `config/routes.rb`. `resources :posts` создаёт семь REST-маршрутов: index, show, new, create, edit, update, destroy.
Генераторы создают каркас: `rails generate model`, `rails generate controller`, `rails db:migrate`. Strong parameters (`params.require(...).permit(...)`) защищают от подмены полей.
```ruby
# config/routes.rb
Rails.application.routes.draw do
  resources :reservations, only: %i[index new create show]
  root "reservations#index"
end

# app/controllers/reservations_controller.rb
class ReservationsController < ApplicationController
  before_action :authenticate_user!

  def create
    @reservation = current_user.reservations.build(reservation_params)
    if @reservation.save
      redirect_to @reservation, notice: "Столик забронирован"
    else
      render :new, status: :unprocessable_entity
    end
  end

  private

  def reservation_params
    params.require(:reservation).permit(:table_id, :starts_at, :guests)
  end
end
```
! Без permit Rails не даст массово присвоить поля
! before_action выполняется перед действиями контроллера
! Логика данных — в моделях, не в контроллерах

@lesson Active Record
Active Record связывает классы с таблицами. Ассоциации: `belongs_to`, `has_many`, `has_one`, `has_many :through`. Валидации проверяют данные перед сохранением.
Запросы строятся цепочкой: `where`, `order`, `limit`, `joins`. Запрос ленивый и выполняется при обращении к данным. `includes` подгружает связи заранее и устраняет проблему N+1.
Scope — именованный запрос в модели. Колбэки (`before_save`) существуют, но злоупотреблять ими не стоит: скрытая логика усложняет отладку.
```ruby
class Reservation < ApplicationRecord
  belongs_to :user
  belongs_to :table

  validates :guests, numericality: { greater_than: 0 }
  validate :fits_table

  scope :upcoming, -> { where("starts_at > ?", Time.current).order(:starts_at) }

  private

  def fits_table
    errors.add(:guests, "больше мест за столом") if table && guests > table.seats
  end
end

Reservation.upcoming.includes(:user).limit(10).each do |r|
  puts "#{r.user.name}: #{r.starts_at}"
end
```
! Используйте ? в where для параметров — это защита от инъекций
! includes решает N+1
! save возвращает false при неудачной валидации, save! бросает исключение

@lesson Тестирование и фоновые задачи
RSpec — популярный фреймворк тестов в Ruby. Блоки `describe` и `it` описывают поведение, `expect(...).to` — проверки. Фабрики (FactoryBot) создают тестовые данные.
Request-спеки проверяют HTTP-запрос через всё приложение, модельные — валидации и методы модели.
Долгие операции (письма, обработка файлов) выносят в Active Job и выполняют фоновым обработчиком, например Sidekiq. Пользователь не ждёт, пока отправится письмо.
```ruby
RSpec.describe Reservation, type: :model do
  it "не даёт посадить больше гостей, чем мест" do
    table = Table.create!(seats: 2)
    r = Reservation.new(table: table, user: create(:user), guests: 4)
    expect(r).not_to be_valid
    expect(r.errors[:guests]).to be_present
  end
end

RSpec.describe "Reservations", type: :request do
  it "перенаправляет гостя на вход" do
    post reservations_path, params: { reservation: { guests: 2 } }
    expect(response).to redirect_to(new_user_session_path)
  end
end

class ConfirmationJob < ApplicationJob
  def perform(reservation_id)
    ReservationMailer.confirmed(Reservation.find(reservation_id)).deliver_now
  end
end
ConfirmationJob.perform_later(reservation.id)
```

! Тестируйте и успешный путь, и ошибки
