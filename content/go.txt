@lesson Переменные, типы и функции
Go компилируется в один исполняемый файл. `:=` объявляет переменную с выводом типа внутри функций, `var` — где угодно. Неиспользуемые переменные и импорты — ошибки компиляции.
У каждого типа есть нулевое значение: `0`, `""`, `false`, `nil`. Неинициализированных переменных в Go не бывает.
Функция может вернуть несколько значений — так в Go возвращают результат и ошибку. Имена с большой буквы экспортируются из пакета, с маленькой — видны только внутри.
```go
package main

import "fmt"

func divide(a, b float64) (float64, error) {
    if b == 0 {
        return 0, fmt.Errorf("деление на ноль")
    }
    return a / b, nil
}

func main() {
    name := "Ада"
    var count int          // 0
    res, err := divide(7, 2)
    if err != nil {
        fmt.Println(err)
        return
    }
    fmt.Println(name, count, res)  // Ада 0 3.5
    fmt.Println(7 / 2)             // 3
}
```

@lesson Управляющие конструкции
В Go один цикл — `for`. Он заменяет while (`for cond {}`), бесконечный цикл (`for {}`) и перебор (`for i, v := range slice`).
`if` может содержать короткое объявление: `if v, err := f(); err != nil {}`. Переменная видна только внутри if/else.
`switch` не проваливается без явного `fallthrough`, case может содержать несколько значений или условия. `defer` откладывает вызов до выхода из функции — так закрывают файлы и освобождают блокировки.
```go
for i := 0; i < 3; i++ { fmt.Print(i) }        // 012

n := 10
for n > 0 { n -= 4 }                            // while

for i, ch := range "го" { fmt.Println(i, string(ch)) }

switch day := "sat"; day {
case "sat", "sun":
    fmt.Println("выходной")
default:
    fmt.Println("работа")
}

f, err := os.Open("data.txt")
if err != nil {
    fmt.Println("ошибка:", err) // в функции, которая возвращает error, пишут return err
    return
}
defer f.Close()
```
! range по строке идёт по рунам, индекс — в байтах
! defer выполняются в обратном порядке (стек)
! Аргументы defer вычисляются в момент объявления

@lesson Срезы и map
Массив `[3]int` имеет фиксированную длину. Срез `[]int` — окно на массив: указатель, длина `len` и ёмкость `cap`. `append` добавляет элемент и при нехватке ёмкости создаёт новый массив.
Срезы одного массива делят память: изменение через один срез видно в другом. Независимую копию делают через `copy` или `slices.Clone`.
`map[K]V` — хэш-таблица. Чтение отсутствующего ключа вернёт нулевое значение, а форма `v, ok := m[k]` скажет, был ли ключ. Порядок перебора map случайный. Запись в nil-map вызывает панику.
```go
nums := []int{1, 2, 3}
nums = append(nums, 4)
part := nums[1:3]            // [2 3]
part[0] = 99
fmt.Println(nums)            // [1 99 3 4]

ages := map[string]int{"Ада": 36}
ages["Алан"] = 41
if age, ok := ages["Боб"]; !ok {
    fmt.Println("нет", age)  // нет 0
}
delete(ages, "Ада")

var m map[string]int
// m["x"] = 1               // паника: nil map
m = make(map[string]int)
```
! Результат append всегда присваивайте обратно
! Срез ссылается на общий массив — помните об этом при изменениях
! Не полагайтесь на порядок перебора map

@lesson Структуры, методы и интерфейсы
`struct` объединяет поля. Методы объявляют с ресивером: `func (u *User) Rename(...)`. Ресивер-указатель нужен, чтобы метод менял исходную структуру, а не копию.
Наследования нет. Вместо него — встраивание (embedding): поля и методы встроенной структуры доступны напрямую.
Интерфейсы в Go реализуются неявно: тип удовлетворяет интерфейсу, если у него есть нужные методы. Маленькие интерфейсы (`io.Reader`, `fmt.Stringer`) — идиома языка. Определяйте интерфейс там, где он используется.
```go
type User struct {
    Name string
    Age  int
}

func (u *User) Birthday()       { u.Age++ }
func (u User) String() string  { return fmt.Sprintf("%s (%d)", u.Name, u.Age) }

type Admin struct {
    User                 // встраивание
    Level int
}

type Notifier interface {
    Notify(to, msg string) error
}

a := Admin{User: User{"Ада", 36}, Level: 1}
a.Birthday()             // метод встроенного User
fmt.Println(a.Name, a)   // Ада Ада (37)
```

@lesson Ошибки и паника
Ошибки в Go — значения типа `error`. Их проверяют явно и возвращают наверх, добавляя контекст через `fmt.Errorf("...: %w", err)`. Глагол `%w` оборачивает ошибку, сохраняя исходную.
`errors.Is` проверяет, есть ли в цепочке конкретная ошибка, `errors.As` достаёт ошибку нужного типа. Сравнение через `==` не видит обёрнутые ошибки.
`panic` — для действительно невозможных ситуаций, не для обычных ошибок. `recover` в defer перехватывает панику, например чтобы HTTP-сервер не упал целиком.
```go
var ErrNotFound = errors.New("не найдено")

func FindUser(id int) (*User, error) {
    u, ok := store[id]
    if !ok {
        return nil, ErrNotFound
    }
    return u, nil
}

func LoadProfile(id int) error {
    if _, err := FindUser(id); err != nil {
        return fmt.Errorf("профиль %d: %w", id, err)
    }
    return nil
}

err := LoadProfile(7)
if errors.Is(err, ErrNotFound) {
    fmt.Println("404:", err)   // 404: профиль 7: не найдено
}
```
! Добавляйте контекст к ошибке, но не логируйте её на каждом уровне
! %w — оборачивает, %v — только текст
! Не используйте panic для ошибок ввода пользователя
? mc Чем `%w` отличается от `%v` в fmt.Errorf?
+ %w сохраняет исходную ошибку для errors.Is и errors.As
- %w выводит ошибку жирным
- Ничем
- %v быстрее и всегда лучше
= %v превращает ошибку в текст.

@lesson Горутины и каналы
Горутина — лёгкий поток, запускается словом `go`. Тысячи горутин — норма. Программа не ждёт горутины: при выходе из main они обрываются.
Каналы передают значения между горутинами: `ch <- v` отправляет, `v := <-ch` получает. Небуферизованный канал синхронизирует отправителя и получателя. `close(ch)` сообщает, что значений больше не будет, и `range ch` завершится.
`sync.WaitGroup` ждёт группу горутин. `select` ждёт сразу несколько каналов. Главный принцип: «не общайтесь через общую память — делитесь памятью через общение».
```go
func worker(id int, jobs <-chan int, results chan<- int, wg *sync.WaitGroup) {
    defer wg.Done()
    for j := range jobs {
        results <- j * j
    }
}

jobs := make(chan int, 10)
results := make(chan int, 10)
var wg sync.WaitGroup
for w := 1; w <= 3; w++ {
    wg.Add(1)
    go worker(w, jobs, results, &wg)
}
for i := 1; i <= 5; i++ { jobs <- i }
close(jobs)
wg.Wait()
close(results)
sum := 0
for r := range results { sum += r }
fmt.Println(sum)   // 55
```
! Закрывает канал только отправитель
! Чтение из закрытого канала вернёт нулевое значение сразу
! Запускайте тесты с -race: детектор гонок находит ошибки

@lesson HTTP, context и тесты
Пакет `net/http` позволяет написать сервер без фреймворков. Начиная с Go 1.22 маршрутизатор поддерживает методы и параметры пути: `mux.HandleFunc("GET /users/{id}", h)`.
`context.Context` передаёт дедлайны, отмену и значения запроса по цепочке вызовов. Его передают первым аргументом во все функции, которые ходят в сеть или базу.
Тесты лежат в файлах `_test.go` и запускаются `go test ./...`. Табличные тесты — идиома Go: срез случаев и один цикл. `httptest` проверяет хендлеры без настоящего сервера.
```go
func getUser(w http.ResponseWriter, r *http.Request) {
    id := r.PathValue("id")
    ctx, cancel := context.WithTimeout(r.Context(), 2*time.Second)
    defer cancel()
    u, err := repo.Find(ctx, id)
    if err != nil {
        http.Error(w, "not found", http.StatusNotFound)
        return
    }
    w.Header().Set("Content-Type", "application/json")
    json.NewEncoder(w).Encode(u)
}

// add_test.go
func TestAdd(t *testing.T) {
    cases := []struct{ a, b, want int }{
        {1, 2, 3}, {0, 0, 0}, {-1, 1, 0},
    }
    for _, c := range cases {
        if got := Add(c.a, c.b); got != c.want {
            t.Errorf("Add(%d,%d)=%d, want %d", c.a, c.b, got, c.want)
        }
    }
}
```

! Не забывайте defer cancel()
! После http.Error делайте return

@lesson Модули, generics и инструменты
Проект — это модуль с файлом `go.mod`. Зависимости добавляет `go get`, а `go mod tidy` убирает лишние. Стандартная структура: `cmd/` для точек входа, `internal/` для закрытого кода.
Generics (с Go 1.18) пишут функции для разных типов: `func Map[T, R any](s []T, f func(T) R) []R`. Ограничения задают интерфейсами, например `cmp.Ordered`.
Инструменты встроены: `go fmt`, `go vet`, `go test -race`, `go build`. Статические бинарники легко упаковать в маленький Docker-образ.
```go
func Map[T, R any](s []T, f func(T) R) []R {
    out := make([]R, 0, len(s))
    for _, v := range s {
        out = append(out, f(v))
    }
    return out
}

func Max[T cmp.Ordered](a, b T) T {
    if a > b { return a }
    return b
}

lengths := Map([]string{"go", "rust"}, func(s string) int { return len(s) })
fmt.Println(lengths, Max(3, 7), Max("a", "b"))   // [2 4] 7 b

// go mod init github.com/you/shortener
// go get github.com/jackc/pgx/v5
// go test -race ./...
```
