@lesson Синтаксис, переменные и типы
Код PHP пишут между `<?php` и `?>` (в файлах только с кодом закрывающий тег не ставят). Переменные начинаются с `$`, тип определяется значением.
Современный PHP поддерживает объявление типов: `function total(int $qty, float $price): float`. Строка `declare(strict_types=1);` в начале файла запрещает неявное приведение типов в вызовах.
Строки в двойных кавычках подставляют переменные, в одинарных — нет. Конкатенация — точка `.`. Сравнение `===` проверяет и значение, и тип.
```php
<?php
declare(strict_types=1);

$name = 'Ада';
$age = 36;
echo "Привет, $name! Через год: " . ($age + 1) . "\n";
echo 'Без подстановки: $name' . "\n";

function total(int $qty, float $price): float {
    return $qty * $price;
}
echo total(3, 9.5), "\n";          // 28.5

var_dump(0 == "a");    // false в PHP 8
var_dump("1" === 1);   // false
$city = $user['city'] ?? 'Алматы';
```
! Всегда используйте === вместо ==
! strict_types=1 в каждом файле ловит ошибки типов
! Оператор ?? не выдаёт предупреждение на несуществующий ключ
? out Что выведет код?
```php
$x = 5;
echo 'x = $x', " / ", "x = $x";
```
> x = $x / x = 5
= В одинарных кавычках подстановки нет.


@lesson Массивы и функции
Массив в PHP — упорядоченный словарь: и список `[1, 2, 3]`, и ассоциативный `['name' => 'Ада']`. Перебирают через `foreach ($arr as $key => $value)`.
Полезные функции: `count`, `in_array`, `array_map`, `array_filter`, `array_column`, `usort`, `array_key_exists`. Стрелочные функции `fn($x) => $x * 2` захватывают внешние переменные автоматически.
Массивы передаются в функции по значению (копия при изменении). Чтобы изменить исходный массив, нужен `&`.
```php
$orders = [
    ['id' => 1, 'total' => 120, 'paid' => true],
    ['id' => 2, 'total' => 80,  'paid' => false],
    ['id' => 3, 'total' => 200, 'paid' => true],
];

$paid = array_filter($orders, fn($o) => $o['paid']);
$revenue = array_sum(array_column($paid, 'total'));     // 320
$ids = array_map(fn($o) => $o['id'], $orders);          // [1, 2, 3]

usort($orders, fn($a, $b) => $b['total'] <=> $a['total']);
echo $orders[0]['id'];                                   // 3

foreach (['a' => 1, 'b' => 2] as $key => $value) {
    echo "$key=$value ";
}
```
! array_filter сохраняет ключи — для списка вызовите array_values
! Оператор `<=>` (spaceship) удобен для сортировки
! usort меняет массив по ссылке и возвращает bool
? out Что выведет код?
```php
$a = [1, 2, 3];
$b = $a;
$b[] = 4;
echo count($a);
```
> 3
= Массивы копируются по значению.

```php

```
> Array ( [0] => 2 [1] => 4 )
> Array([0]=>2[1]=>4)

@lesson ООП в PHP
Классы поддерживают типизированные свойства, модификаторы `public`, `protected`, `private` и `readonly`. Промоушен в конструкторе объявляет и заполняет свойства в одной строке.
Интерфейсы задают контракт, абстрактные классы — общую основу, трейты (`trait`) переиспользуют код в нескольких классах. `enum` (PHP 8.1) описывает фиксированный набор значений.
Классы загружаются автоматически через автозагрузку Composer по стандарту PSR-4: пространство имён соответствует папке.
```php
<?php
namespace App\Models;

enum Status: string {
    case Draft = 'draft';
    case Published = 'published';
}

interface HasSlug { public function slug(): string; }

final class Post implements HasSlug {
    public function __construct(
        public readonly int $id,
        public readonly string $title,
        private Status $status = Status::Draft,
    ) {}

    public function publish(): void { $this->status = Status::Published; }
    public function slug(): string {
        return strtolower(str_replace(' ', '-', $this->title));
    }
}

$post = new Post(1, 'Hello World');
echo $post->slug();        // hello-world
```
! readonly свойства нельзя изменить после инициализации
! Пространства имён + PSR-4 = порядок в проекте
! enum безопаснее строковых констант

@lesson HTTP, формы и безопасность
PHP получает данные запроса через `$_GET`, `$_POST`, `$_SERVER`, загрузки — через `$_FILES`. Сессии (`session_start()`, `$_SESSION`) хранят данные между запросами.
Любые входные данные — недоверенные. Выводя их в HTML, экранируйте через `htmlspecialchars`, иначе возможен XSS. Формы защищают CSRF-токеном.
Пароли храните только как хэш: `password_hash` и `password_verify`. Никогда не используйте md5 или sha1 для паролей.
```php
<?php
session_start();

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    if (!hash_equals($_SESSION['csrf'] ?? '', $_POST['csrf'] ?? '')) {
        http_response_code(419);
        exit('Неверный токен');
    }
    $email = filter_input(INPUT_POST, 'email', FILTER_VALIDATE_EMAIL);
    if ($email === false || $email === null) {
        exit('Некорректный email');
    }
    $hash = password_hash($_POST['password'], PASSWORD_DEFAULT);
}

$_SESSION['csrf'] ??= bin2hex(random_bytes(32));
$q = $_GET['q'] ?? '';
echo 'Вы искали: ' . htmlspecialchars($q, ENT_QUOTES, 'UTF-8');
```
! htmlspecialchars на любой вывод пользовательских данных
! password_hash сам добавляет соль
! Используйте hash_equals для сравнения токенов

@lesson Базы данных и PDO
PDO — единый интерфейс к разным СУБД. Подготовленные запросы (`prepare` + `execute`) передают значения отдельно от SQL и полностью защищают от SQL-инъекций.
Включайте режим исключений `PDO::ERRMODE_EXCEPTION`, чтобы ошибки базы не терялись. Связанные изменения объединяйте в транзакцию.
В Laravel эту работу берут на себя Eloquent ORM и Query Builder, но понимать PDO и SQL всё равно нужно.
```php
$pdo = new PDO('pgsql:host=localhost;dbname=blog', 'user', 'secret', [
    PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION,
    PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,
]);

$stmt = $pdo->prepare('SELECT id, title FROM posts WHERE author_id = :author AND status = :status');
$stmt->execute(['author' => $authorId, 'status' => 'published']);
$posts = $stmt->fetchAll();

$pdo->beginTransaction();
try {
    $pdo->prepare('UPDATE accounts SET balance = balance - ? WHERE id = ?')->execute([100, 1]);
    $pdo->prepare('UPDATE accounts SET balance = balance + ? WHERE id = ?')->execute([100, 2]);
    $pdo->commit();
} catch (Throwable $e) {
    $pdo->rollBack();
    throw $e;
}
```
! Никогда не вставляйте переменные в SQL через конкатенацию
! ERRMODE_EXCEPTION — обязательная настройка
! При ошибке в транзакции вызывайте rollBack

@lesson Composer и экосистема
Composer — менеджер зависимостей PHP. `composer require vendor/package` добавляет пакет, `composer.json` описывает зависимости, `composer.lock` фиксирует точные версии.
Автозагрузка PSR-4 подключает классы по пространствам имён без ручных require. Стандарты PSR описывают стиль кода (PSR-12), логирование, HTTP-сообщения.
Инструменты качества: PHPStan или Psalm для статического анализа, PHP-CS-Fixer для стиля, PHPUnit или Pest для тестов.
```php
// composer.json
// {
//   "require": { "php": "^8.3", "guzzlehttp/guzzle": "^7.8" },
//   "require-dev": { "phpunit/phpunit": "^11.0" },
//   "autoload": { "psr-4": { "App\\": "src/" } }
// }

require __DIR__ . '/vendor/autoload.php';

use App\Services\Weather;
use GuzzleHttp\Client;

$weather = new Weather(new Client(['timeout' => 5]));
echo $weather->today('Almaty');

// composer install          — поставить по lock-файлу
// vendor/bin/phpunit        — тесты
// vendor/bin/phpstan analyse src --level=8
```

@lesson Laravel: основы фреймворка
Laravel — самый популярный PHP-фреймворк. Маршруты в `routes/web.php` и `routes/api.php` ведут к контроллерам. Шаблоны пишут на Blade, данные — через Eloquent ORM.
Миграции описывают схему базы в коде, `php artisan migrate` применяет их. Валидация запросов — `$request->validate([...])` или Form Request классы.
Middleware обрабатывает запрос до контроллера: `auth` проверяет вход. Очереди (`dispatch`) выносят долгие задачи, например отправку писем, в фон.
```php
// routes/web.php
Route::middleware('auth')->group(function () {
    Route::resource('posts', PostController::class);
});

// app/Http/Controllers/PostController.php
public function store(Request $request)
{
    $data = $request->validate([
        'title' => ['required', 'string', 'max:200'],
        'body'  => ['required', 'string'],
    ]);
    $post = $request->user()->posts()->create($data);
    return redirect()->route('posts.show', $post);
}

// Eloquent
$latest = Post::with('author')->where('status', 'published')->latest()->paginate(10);

// php artisan make:model Post -mcr
// php artisan migrate
```

@lesson Тестирование и деплой
Тесты бывают юнит (одна функция или класс) и feature (HTTP-запрос через всё приложение). В Laravel feature-тест отправляет запрос и проверяет ответ и базу.
Для тестов используют отдельную базу и `RefreshDatabase`, а данные создают фабриками. Внешние сервисы подменяют фейками: `Mail::fake()`, `Http::fake()`.
Деплой: `composer install --no-dev --optimize-autoloader`, `php artisan migrate --force`, кэширование конфигурации и маршрутов. Ошибки в продакшене не показывают пользователю: `APP_DEBUG=false`.
```php
use Illuminate\Foundation\Testing\RefreshDatabase;

class PostTest extends TestCase
{
    use RefreshDatabase;

    public function test_author_can_create_post(): void
    {
        $user = User::factory()->create();

        $response = $this->actingAs($user)->post('/posts', [
            'title' => 'Первый пост',
            'body'  => 'Текст',
        ]);

        $response->assertRedirect();
        $this->assertDatabaseHas('posts', ['title' => 'Первый пост']);
    }

    public function test_guest_is_redirected(): void
    {
        $this->post('/posts', [])->assertRedirect('/login');
    }
}
```
! APP_DEBUG=true в продакшене раскроет секреты
! Фабрики делают тестовые данные короткими и читаемыми
! Тестируйте и успешные, и запрещённые сценарии
