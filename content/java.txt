@lesson Синтаксис, типы и main
Программа на Java состоит из классов. Точка входа — `public static void main(String[] args)`. Код компилируется в байт-код и выполняется на JVM, поэтому работает на любой ОС.
Примитивные типы: `int`, `long`, `double`, `boolean`, `char` и другие. У каждого примитива есть класс-обёртка (`Integer`, `Double`), а `String` — объект.
Целочисленное деление отбрасывает дробную часть. Переполнение `int` не вызывает ошибку, а молча «перекручивает» значение. Начиная с Java 10 тип локальной переменной можно вывести через `var`.
```code
public class Main {
    public static void main(String[] args) {
        int a = 7, b = 2;
        System.out.println(a / b);        // 3
        System.out.println(a / (double) b); // 3.5
        long big = Integer.MAX_VALUE + 1L;
        int overflow = Integer.MAX_VALUE + 1; // -2147483648
        var name = "Ада";                   // String
        System.out.printf("%s: %d%n", name, a);
    }
}
```
! Для больших чисел используйте long, а для денег — BigDecimal
! `char` — одиночные кавычки, `String` — двойные
! var работает только для локальных переменных с инициализацией

@lesson Условия, циклы и switch
`if`/`else`, `for`, `while` и `do-while` работают как в C. Цикл for-each `for (String s : list)` перебирает массивы и коллекции.
Современный `switch` со стрелками не проваливается в следующий case и может возвращать значение. Тернарный оператор `cond ? a : b` удобен для коротких выборов.
Строки сравнивают через `equals()`: `==` сравнивает ссылки, и две одинаковые по тексту строки могут оказаться разными объектами.
```code
int[] scores = {90, 45, 77};
for (int s : scores) {
    String grade = s >= 80 ? "A" : s >= 60 ? "B" : "C";
    System.out.println(s + " → " + grade);
}

String day = "SAT";
int hours = switch (day) {
    case "SAT", "SUN" -> 0;
    case "FRI" -> 6;
    default -> 8;
};

String a = new String("hi");
System.out.println(a == "hi");      // false
System.out.println(a.equals("hi")); // true
```
! Сравнение строк только через equals
! Старый switch с двоеточием проваливается без break
! `"текст".equals(x)` безопасен, даже если x — null

@lesson ООП: классы, инкапсуляция, наследование
Класс описывает состояние (поля) и поведение (методы). Поля делают `private`, а доступ дают через методы — это инкапсуляция: объект сам следит за корректностью своих данных.
`extends` наследует класс, `@Override` помечает переопределённый метод, `super` обращается к родителю. Java поддерживает одиночное наследование классов.
Полиморфизм: переменная типа родителя может хранить объект наследника, и вызов метода выполнит версию наследника. Для неизменяемых моделей данных удобны `record`.
```code
public abstract class Shape {
    public abstract double area();
}

public class Circle extends Shape {
    private final double r;
    public Circle(double r) {
        if (r <= 0) throw new IllegalArgumentException("r > 0");
        this.r = r;
    }
    @Override
    public double area() { return Math.PI * r * r; }
}

public record Point(int x, int y) {}

Shape s = new Circle(2);
System.out.println(s.area());              // 12.56...
System.out.println(new Point(1, 2));       // Point[x=1, y=2]
```
! @Override защищает от опечатки в имени метода
! record сам создаёт конструктор, геттеры, equals, hashCode и toString
! Валидируйте данные в конструкторе — объект не должен быть «сломанным»

@lesson Интерфейсы и абстракции
Интерфейс — контракт: список методов, которые класс обязуется реализовать. Класс может реализовать много интерфейсов через `implements`.
В интерфейсах бывают `default`-методы с реализацией. Интерфейс с одним абстрактным методом называют функциональным: его можно передать лямбдой.
Код зависит от интерфейсов, а не от конкретных классов. Так реализацию легко подменить, например на заглушку в тестах.
```code
public interface Notifier {
    void send(String to, String text);
    default void sendAll(List<String> to, String text) {
        to.forEach(t -> send(t, text));
    }
}

public class EmailNotifier implements Notifier {
    public void send(String to, String text) { /* SMTP */ }
}

public class OrderService {
    private final Notifier notifier;
    public OrderService(Notifier notifier) { this.notifier = notifier; }
}

Comparator<String> byLen = (a, b) -> a.length() - b.length();
```
! Передача зависимостей через конструктор — основа тестируемого кода
! Comparator, Runnable, Function — функциональные интерфейсы
! Абстрактный класс хранит состояние, интерфейс задаёт контракт

@lesson Коллекции и generics
`List` хранит элементы по порядку (`ArrayList`), `Set` — уникальные (`HashSet`), `Map` — пары ключ–значение (`HashMap`). Объявляйте переменную типом интерфейса: `List<String> list = new ArrayList<>()`.
Generics задают тип элементов в угловых скобках и работают только с объектами: `List<Integer>`, а не `List<int>`. Автоупаковка превращает int в Integer автоматически.
Объекты в `HashSet` и ключи `HashMap` должны правильно реализовывать `equals` и `hashCode` вместе. Изменять коллекцию во время перебора for-each нельзя — будет ConcurrentModificationException.
```code
List<String> langs = new ArrayList<>(List.of("Java", "Go"));
langs.add("Kotlin");

Map<String, Integer> count = new HashMap<>();
for (String w : "a b a c a".split(" ")) {
    count.merge(w, 1, Integer::sum);
}
System.out.println(count.get("a"));         // 3
System.out.println(count.getOrDefault("z", 0)); // 0

Set<Integer> uniq = new HashSet<>(List.of(1, 2, 2, 3));
System.out.println(uniq.size());            // 3

langs.removeIf(l -> l.startsWith("G"));     // безопасное удаление
```
! List.of создаёт неизменяемый список
! Переопределили equals — переопределите и hashCode
! Для удаления при переборе — removeIf или Iterator

@lesson Исключения
Проверяемые исключения (checked, например `IOException`) компилятор заставляет обработать или объявить через `throws`. Непроверяемые (`RuntimeException` и наследники) обычно сигнализируют об ошибке в коде.
`try-with-resources` автоматически закрывает ресурсы (файлы, соединения), реализующие `AutoCloseable`. `finally` выполняется всегда.
Не глотайте исключения пустым catch: залогируйте или пробросьте дальше с понятным сообщением. Свои исключения наследуют от `RuntimeException` или `Exception`.
```code
public class NotFoundException extends RuntimeException {
    public NotFoundException(String msg) { super(msg); }
}

public Book find(long id) {
    return repo.findById(id)
        .orElseThrow(() -> new NotFoundException("Книга " + id + " не найдена"));
}

try (BufferedReader r = Files.newBufferedReader(Path.of("data.txt"))) {
    System.out.println(r.readLine());
} catch (IOException e) {
    throw new UncheckedIOException("Не удалось прочитать файл", e);
}
```
! Пустой catch прячет баги
! Передавайте исходное исключение как cause
! NullPointerException почти всегда говорит об ошибке в логике

@lesson Stream API и Optional
Stream описывает обработку коллекции цепочкой: `filter` отбирает, `map` преобразует, `sorted` сортирует, `collect` собирает результат. Поток ленивый: ничего не выполняется до терминальной операции.
`Collectors.groupingBy` группирует элементы, `Collectors.toMap` строит словарь, `joining` склеивает строки. Поток одноразовый — повторно его не использовать.
`Optional` явно говорит «значения может не быть» и заставляет обработать этот случай через `orElse`, `orElseThrow`, `map`. Не возвращайте null там, где подходит Optional.
```code
record Order(String customer, double total, boolean paid) {}

List<Order> orders = List.of(
    new Order("Ада", 120, true),
    new Order("Алан", 80, false),
    new Order("Ада", 200, true));

double revenue = orders.stream()
    .filter(Order::paid)
    .mapToDouble(Order::total)
    .sum();                                   // 320.0

Map<String, Long> byCustomer = orders.stream()
    .collect(Collectors.groupingBy(Order::customer, Collectors.counting()));

Optional<Order> big = orders.stream().filter(o -> o.total() > 150).findFirst();
System.out.println(big.map(Order::customer).orElse("нет")); // Ада
```
! Без терминальной операции стрим ничего не делает
! `Optional.get()` без проверки — тот же NullPointerException
! Ссылки на методы `Order::paid` короче лямбд

@lesson Многопоточность и основы JVM
Поток (`Thread`) выполняет код параллельно. Создавать потоки вручную редко нужно: используют пулы `ExecutorService` и `CompletableFuture`. В Java 21 появились виртуальные потоки для тысяч одновременных задач.
Если несколько потоков меняют общие данные, возможна гонка. Защищаются через `synchronized`, атомарные классы (`AtomicInteger`) и потокобезопасные коллекции (`ConcurrentHashMap`).
Память JVM делится на стек (локальные переменные и вызовы) и кучу (объекты). Сборщик мусора сам удаляет объекты без ссылок, но утечки памяти всё равно возможны, если ссылки остаются, например в статических коллекциях.
```code
AtomicInteger counter = new AtomicInteger();
try (ExecutorService pool = Executors.newVirtualThreadPerTaskExecutor()) {
    for (int i = 0; i < 1000; i++) {
        pool.submit(counter::incrementAndGet);
    }
}
System.out.println(counter.get());     // 1000

CompletableFuture<String> user = CompletableFuture.supplyAsync(() -> loadUser());
CompletableFuture<String> stats = CompletableFuture.supplyAsync(() -> loadStats());
String page = user.thenCombine(stats, (u, s) -> u + s).join();
```
! `count++` не атомарен: при гонке часть увеличений потеряется
! ConcurrentHashMap вместо HashMap для общих данных
! Объекты в куче, ссылки на них и примитивы методов — в стеке
