@lesson Сложность алгоритмов: O-нотация
O-нотация описывает, как растёт время или память алгоритма при росте входных данных. Константы и младшие слагаемые отбрасывают: O(2n + 10) — это O(n).
Основные классы от быстрых к медленным: O(1) — доступ по индексу, O(log n) — бинарный поиск, O(n) — один проход, O(n log n) — хорошая сортировка, O(n²) — вложенные циклы, O(2ⁿ) — перебор подмножеств.
На собеседовании всегда называют сложность решения по времени и памяти и думают, можно ли быстрее. Часто O(n²) превращается в O(n) с помощью хэш-таблицы.
```python
# O(n²): проверяем все пары
def has_pair_slow(nums, target):
    for i in range(len(nums)):
        for j in range(i + 1, len(nums)):
            if nums[i] + nums[j] == target:
                return True
    return False

# O(n): запоминаем увиденное в множестве
def has_pair_fast(nums, target):
    seen = set()
    for x in nums:
        if target - x in seen:
            return True
        seen.add(x)
    return False
```
! Два вложенных цикла по n — O(n²)
! Деление задачи пополам на каждом шаге — O(log n)
! Память тоже считается: доп. множество — O(n) памяти

@lesson Массивы, строки и хэш-таблицы
Массив хранит элементы подряд: доступ по индексу O(1), вставка в начало O(n). Динамический массив (list, vector, ArrayList) растёт с запасом, поэтому добавление в конец в среднем O(1).
Хэш-таблица (dict, HashMap, Map) хранит пары ключ–значение. Хэш-функция вычисляет «корзину» для ключа, поэтому поиск, вставка и удаление в среднем O(1). При коллизиях несколько ключей попадают в одну корзину.
Типичные приёмы: подсчёт частот через хэш-таблицу, два указателя для отсортированного массива, скользящее окно для подстрок.
```python
# частоты символов
def is_anagram(a, b):
    if len(a) != len(b):
        return False
    count = {}
    for ch in a:
        count[ch] = count.get(ch, 0) + 1
    for ch in b:
        if count.get(ch, 0) == 0:
            return False
        count[ch] -= 1
    return True

# два указателя: палиндром
def is_palindrome(s):
    l, r = 0, len(s) - 1
    while l < r:
        if s[l] != s[r]:
            return False
        l, r = l + 1, r - 1
    return True
```
! Поиск в списке — O(n), в множестве — O(1)
! Два указателя часто убирают вложенный цикл
! Ключ хэш-таблицы должен быть неизменяемым

@lesson Стек, очередь, связный список
Стек работает по принципу LIFO — последним пришёл, первым вышел: `push` кладёт, `pop` снимает сверху. Применение: отмена действий, проверка скобок, обход в глубину, стек вызовов функций.
Очередь — FIFO, первым пришёл, первым вышел. Применение: обработка задач по порядку, обход в ширину. В Python для очереди используют `collections.deque`: `list.pop(0)` работает за O(n).
Связный список хранит узлы со ссылкой на следующий. Вставка и удаление при известном узле — O(1), а доступ по индексу — O(n).
```python
from collections import deque

def valid_brackets(s):
    pairs = {")": "(", "]": "[", "}": "{"}
    stack = []
    for ch in s:
        if ch in "([{":
            stack.append(ch)
        elif ch in pairs:
            if not stack or stack.pop() != pairs[ch]:
                return False
    return not stack

q = deque(["a", "b"])
q.append("c")
print(q.popleft())        # a
print(valid_brackets("([]{})"), valid_brackets("(]"))   # True False
```
! Скобки, «отмена», DFS — подумайте о стеке
! Порядок обработки, BFS — подумайте об очереди
! Переполнение стека вызовов — признак слишком глубокой рекурсии

@lesson Рекурсия, сортировка и поиск
Рекурсия — функция вызывает саму себя на меньшей задаче. Нужны базовый случай (когда остановиться) и шаг к нему. Без базового случая будет переполнение стека.
Сортировка слиянием делит массив пополам, сортирует половины и сливает их: O(n log n) всегда. Быстрая сортировка в среднем O(n log n), в худшем O(n²). В реальном коде используют встроенную сортировку языка.
Бинарный поиск работает только на отсортированных данных: сравниваем с серединой и отбрасываем половину. Мемоизация (запоминание результатов) превращает экспоненциальную рекурсию в линейную — это основа динамического программирования.
```python
from functools import lru_cache

def binary_search(arr, target):
    lo, hi = 0, len(arr) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if arr[mid] == target:
            return mid
        if arr[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1

@lru_cache(maxsize=None)
def fib(n):
    return n if n < 2 else fib(n - 1) + fib(n - 2)

print(binary_search([1, 3, 5, 7, 9], 7), fib(50))   # 3 12586269025
```
! Без базового случая рекурсия бесконечна
! Бинарный поиск — только по отсортированному массиву
! Наивный fib — O(2ⁿ), с мемоизацией — O(n)
? out Что вернёт binary_search([1, 3, 5, 7, 9], 4)?
> -1
= Элемента нет.

- Два параметра
= Иначе рекурсия не остановится.

- O(n log n)

@lesson Деревья и графы
Дерево — иерархия узлов: корень, дети, листья. Бинарное дерево поиска хранит слева меньшие значения, справа большие: поиск O(log n), если дерево сбалансировано, и O(n) в худшем случае.
Обходы дерева: в глубину (pre-order, in-order, post-order) и в ширину по уровням. In-order обход BST выдаёт значения в отсортированном порядке.
Граф — вершины и рёбра (соцсеть, карта дорог, зависимости). Его хранят списком смежности. BFS находит кратчайший путь по числу рёбер в невзвешенном графе, DFS — проверяет связность и ищет циклы.
```python
from collections import deque

graph = {
    "A": ["B", "C"],
    "B": ["D"],
    "C": ["D"],
    "D": [],
}

def shortest_path_len(g, start, goal):
    queue = deque([(start, 0)])
    seen = {start}
    while queue:
        node, dist = queue.popleft()
        if node == goal:
            return dist
        for nxt in g[node]:
            if nxt not in seen:
                seen.add(nxt)
                queue.append((nxt, dist + 1))
    return -1

print(shortest_path_len(graph, "A", "D"))   # 2
```
! Множество seen защищает от бесконечного обхода циклов
! In-order обход BST даёт отсортированные значения
! Кратчайший путь во взвешенном графе — алгоритм Дейкстры

@lesson Git и командная работа
Git хранит историю проекта снимками (коммитами). Базовый цикл: изменить файлы → `git add` → `git commit -m "..."` → `git push`. Хороший коммит — одно логическое изменение с понятным сообщением.
Ветки позволяют работать над задачей отдельно: `git switch -c feature/login`. Изменения попадают в main через Pull Request с код-ревью. Конфликт возникает, когда две ветки изменили одни строки — его решают вручную.
`git merge` объединяет истории с коммитом слияния, `git rebase` переписывает коммиты поверх другой ветки и даёт линейную историю. Не переписывайте историю общих веток.
```bash
git clone https://github.com/you/shop.git
cd shop
git switch -c feature/cart

# ...правки...
git status
git add src/cart.py tests/test_cart.py
git commit -m "Добавить расчёт скидки в корзине"
git push -u origin feature/cart
# открыть Pull Request на GitHub

git switch main
git pull
git log --oneline --graph -10
```
! Не коммитьте секреты, .env, node_modules — используйте .gitignore
! Маленькие PR ревьюят быстрее и внимательнее
! git restore отменяет незакоммиченные правки в файле

@lesson HTTP, REST и веб
HTTP — протокол запросов и ответов. Запрос: метод, адрес, заголовки, тело. Ответ: статус-код, заголовки, тело. HTTPS шифрует соединение через TLS.
Методы: GET — получить, POST — создать, PUT — заменить, PATCH — частично изменить, DELETE — удалить. GET, PUT и DELETE идемпотентны: повтор не меняет результат.
Коды ответа: 2xx — успех (200, 201, 204), 3xx — перенаправление, 4xx — ошибка клиента (400, 401, 403, 404, 422), 5xx — ошибка сервера. REST API строится вокруг ресурсов: `GET /users/42`, `POST /users`.
```http
POST /api/orders HTTP/1.1
Host: shop.kz
Authorization: Bearer eyJhbGciOi...
Content-Type: application/json

{"product_id": 7, "qty": 2}

HTTP/1.1 201 Created
Location: /api/orders/105
Content-Type: application/json

{"id": 105, "status": "new", "total": 37980}
```
! 401 — не авторизован, 403 — авторизован, но нет доступа
! Сервер не хранит состояние между запросами — авторизация в каждом запросе
! Пароли и токены передают только по HTTPS

@lesson Архитектура, тесты и собеседование
Чистый код: понятные имена, маленькие функции с одной задачей, отсутствие дублирования. Принципы SOLID, особенно единственная ответственность и зависимость от абстракций, помогают коду расти без переписывания.
Пирамида тестов: много быстрых юнит-тестов, меньше интеграционных, мало сквозных. Тест проверяет поведение, а не реализацию.
На собеседовании джуниора обычно проверяют: основы языка, структуры данных, SQL, Git, HTTP и умение рассуждать вслух. Решая задачу, сначала уточните условия, назовите простое решение и его сложность, затем улучшайте. Рассказывайте о своих проектах: что делали сами, какие были трудности, что бы улучшили.
```text
Схема ответа на задачу:
1. Повторить условие своими словами, уточнить ограничения
2. Разобрать пример вручную, включая крайние случаи (пусто, один элемент)
3. Назвать простое решение и его сложность
4. Предложить оптимизацию (хэш-таблица, два указателя, сортировка)
5. Написать код, проговаривая шаги
6. Прогнать пример и крайние случаи, назвать итоговую сложность
```

? mc Вы случайно закоммитили пароль и запушили. Что правильно сделать в первую очередь?
+ Сменить (отозвать) пароль, затем убрать его из истории
- Удалить файл новым коммитом и забыть
- Сделать репозиторий приватным
- Переименовать файл
= Секрет уже скомпрометирован, история хранит его.
? mc Какая сложность у вставки в сбалансированное бинарное дерево поиска?
+ O(log n)
- O(1)
- O(n)
- O(n log n)
= Высота дерева логарифмическая.
? mc Что такое идемпотентность?
+ Повторный одинаковый запрос не меняет результат после первого
- Запрос выполняется быстро
- Запрос кэшируется
- Запрос без тела
= Важно для повторов при сбоях сети.
? mc Что значит DRY?
+ Не повторяйся: одна логика — в одном месте
- Пиши сухие комментарии
- Удаляй тесты
- Не используй рекурсию
= Don't Repeat Yourself.
? mc Как лучше ответить, если на собеседовании не знаете ответ?
+ Честно сказать и порассуждать, как бы вы это выяснили
- Придумать уверенный ответ
- Сменить тему
- Промолчать
= Интервьюеры ценят честность и ход мысли.
