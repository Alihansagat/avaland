@lesson Зачем TypeScript и базовые типы
TypeScript — надстройка над JavaScript: компилятор `tsc` проверяет типы и выдаёт обычный JS. Ошибки вроде опечатки в имени поля ловятся до запуска программы.
Тип указывают после двоеточия: `let age: number`. Часто тип выводится сам: `let name = "Ада"` уже `string`. Базовые типы: `string`, `number`, `boolean`, массивы `number[]`, кортежи `[string, number]`.
`any` отключает проверку и сводит пользу TS к нулю. Для неизвестных данных используйте `unknown`: его нужно сузить проверкой перед использованием.
```code
let count: number = 0;
const tags: string[] = ["ts", "node"];
const pair: [string, number] = ["Ада", 36];

function parse(input: unknown): number {
  if (typeof input === "number") return input;
  if (typeof input === "string") return Number(input);
  throw new Error("Не число");
}

// count = "10";  // Ошибка: string не присваивается number
```
! Включайте `"strict": true` в tsconfig.json с первого дня
! unknown безопаснее any: его нельзя использовать без проверки
! Типы существуют только при компиляции, в рантайме их нет

@lesson Интерфейсы и type
`interface` и `type` описывают форму объекта. Поле со знаком `?` необязательное, `readonly` запрещает изменение.
`type` умеет больше: объединения `"a" | "b"`, пересечения `A & B`, псевдонимы для любых типов. `interface` можно расширять через `extends` и дополнять повторным объявлением.
TypeScript использует структурную типизацию: объект подходит под тип, если у него есть нужные поля, независимо от того, как он создан.
```code
interface User {
  readonly id: number;
  name: string;
  email?: string;
}

interface Admin extends User {
  permissions: string[];
}

type Status = "draft" | "published" | "archived";
type WithTimestamps<T> = T & { createdAt: Date };

const u: User = { id: 1, name: "Ада" };
// u.id = 2;  // Ошибка: readonly
```
! Объединение строковых литералов заменяет enum во многих случаях
! Лишнее поле в объектном литерале — ошибка, а в переменной — нет
! Для публичных моделей обычно выбирают interface

@lesson Функции и сужение типов
Параметры и результат функции типизируют явно: `function f(a: number): string`. Тип `void` значит «ничего не возвращает», `never` — «никогда не завершается нормально».
Сужение (narrowing): после проверок `typeof`, `instanceof`, `in` или сравнения с литералом TypeScript понимает более точный тип внутри ветки.
Размеченное объединение — объекты с общим полем-меткой (`kind`). Проверка метки в `switch` сужает тип, а `never` в default гарантирует, что обработаны все варианты.
```code
type Shape =
  | { kind: "circle"; r: number }
  | { kind: "rect"; w: number; h: number };

function area(s: Shape): number {
  switch (s.kind) {
    case "circle": return Math.PI * s.r ** 2;
    case "rect":   return s.w * s.h;
    default: {
      const check: never = s;   // ошибка, если забыли вариант
      return check;
    }
  }
}
```
! Проверка через never ловит забытые case при добавлении нового варианта
! Опциональный параметр `x?: number` ставится после обязательных
! Пользовательский type guard: `function isUser(x): x is User`

@lesson Дженерики
Дженерик — тип-параметр, который делает функцию или класс универсальными без потери типов. `function first<T>(arr: T[]): T | undefined` вернёт число для массива чисел и строку для массива строк.
Ограничение `T extends ...` требует, чтобы тип имел нужные поля. `keyof T` — объединение ключей типа, а `T[K]` — тип значения по ключу.
Дженерики используются везде: `Array<T>`, `Promise<T>`, `Map<K, V>`, ответы API `ApiResponse<T>`.
```code
function first<T>(arr: T[]): T | undefined {
  return arr[0];
}
const n = first([1, 2, 3]);     // number | undefined

function pluck<T, K extends keyof T>(items: T[], key: K): T[K][] {
  return items.map(i => i[key]);
}
const names = pluck([{ name: "Ада", age: 36 }], "name"); // string[]

interface ApiResponse<T> { data: T; error?: string; }
async function getJSON<T>(url: string): Promise<ApiResponse<T>> {
  const res = await fetch(url);
  return { data: (await res.json()) as T };
}
```
! Не плодите дженерики там, где хватит конкретного типа
! `as T` — это обещание компилятору, а не проверка
! keyof с extends защищает от опечаток в именах полей

@lesson Утилитарные типы
TypeScript содержит готовые преобразования типов. `Partial<T>` делает все поля необязательными, `Required<T>` — обязательными, `Readonly<T>` — только для чтения.
`Pick<T, K>` оставляет выбранные поля, `Omit<T, K>` убирает. `Record<K, V>` описывает объект с ключами K и значениями V. `ReturnType<F>` достаёт тип результата функции.
С ними модели для форм, обновлений и ответов API выводятся из одной сущности, и при изменении сущности всё обновляется автоматически.
```code
interface User { id: number; name: string; email: string; password: string; }

type PublicUser = Omit<User, "password">;
type UserUpdate = Partial<Pick<User, "name" | "email">>;
type RoleMap = Record<"admin" | "user", string[]>;

function update(id: number, patch: UserUpdate) { /* ... */ }
update(1, { name: "Ада" });           // ок: email не обязателен

function makeUser() { return { id: 1, ok: true }; }
type Made = ReturnType<typeof makeUser>; // { id: number; ok: boolean }
```
! Выводите типы из одной модели, а не копируйте поля
! Omit удобен, чтобы не отдать пароль в ответе API
! Readonly поверхностный: вложенные объекты можно менять

@lesson Классы и модификаторы доступа
В классах TypeScript есть модификаторы `public`, `private`, `protected` и `readonly`. Параметр конструктора с модификатором сразу становится полем.
`abstract` класс нельзя создать напрямую: он задаёт каркас и абстрактные методы для наследников. `implements` проверяет, что класс выполняет контракт интерфейса.
`private` в TS проверяется только при компиляции. Для настоящей приватности в рантайме используйте поля `#`.
```code
interface Repo<T> {
  find(id: number): T | undefined;
  save(item: T): void;
}

abstract class Base {
  constructor(protected readonly name: string) {}
  abstract describe(): string;
}

class MemoryRepo<T extends { id: number }> extends Base implements Repo<T> {
  private items = new Map<number, T>();
  find(id: number) { return this.items.get(id); }
  save(item: T) { this.items.set(item.id, item); }
  describe() { return `${this.name}: ${this.items.size}`; }
}
```
! Сокращённая запись полей в конструкторе экономит много строк
! protected доступен в наследниках, private — только в самом классе
! Программируйте против интерфейсов, а не конкретных классов

@lesson Модули, tsconfig и сборка
Каждый файл с `import` или `export` — модуль. `export type` и `import type` подключают только типы, они полностью исчезают из итогового JS.
`tsconfig.json` управляет компиляцией: `strict` включает строгие проверки, `target` — версию JS на выходе, `module` — формат модулей, `outDir` — папку сборки.
Типы для JS-библиотек ставят отдельными пакетами `@types/имя`, если библиотека не поставляет их сама. Во фронтенде TS собирают Vite или Next.js, в Node.js — `tsc` или `tsx` для разработки.
```code
// models.ts
export interface Note { id: string; text: string; }
export const MAX_LEN = 500;

// service.ts
import type { Note } from "./models";
import { MAX_LEN } from "./models";

export function validate(n: Note): boolean {
  return n.text.length <= MAX_LEN;
}

// tsconfig.json
// { "compilerOptions": { "strict": true, "target": "ES2022",
//   "module": "NodeNext", "outDir": "dist" } }
```
! Не коммитьте папку dist — её создаёт сборка
! `noUncheckedIndexedAccess` делает arr[i] типом T | undefined
! Ошибки компиляции нужно чинить, а не глушить через // @ts-ignore

@lesson Валидация данных и типизация API
Типы TypeScript исчезают при компиляции, поэтому данные из сети, форм и файлов нужно проверять в рантайме. Библиотека zod описывает схему один раз и даёт и проверку, и тип через `z.infer`.
`schema.parse(data)` бросает ошибку при несоответствии, `safeParse` возвращает объект с `success` — удобно для ответов API без исключений.
Хорошая практика — проверять данные на границе системы (входящий HTTP-запрос, ответ внешнего API), а внутри приложения работать уже с проверенными типами.
```ts
import { z } from "zod";

const NoteSchema = z.object({
  id: z.string().uuid(),
  text: z.string().min(1).max(500),
  tags: z.array(z.string()).default([]),
});
type Note = z.infer<typeof NoteSchema>;

async function loadNote(id: string): Promise<Note> {
  const res = await fetch(`/api/notes/${id}`);
  if (!res.ok) throw new Error(`HTTP ${res.status}`);
  return NoteSchema.parse(await res.json());
}

const result = NoteSchema.safeParse({ id: "x", text: "" });
if (!result.success) console.log(result.error.issues.length); // 2
```
! Проверяйте данные на границах: запросы, ответы, localStorage
! z.infer избавляет от дублирования интерфейса и схемы
! safeParse не бросает исключение
