@lesson Переменные, типы и строки
`val` — значение только для чтения, `var` — изменяемая переменная. Предпочитайте `val`: код с неизменяемыми данными проще понимать.
Тип выводится автоматически, но его можно указать: `val age: Int = 36`. Всё в Kotlin — объекты, при этом компилятор сам использует примитивы JVM там, где можно.
Строковые шаблоны подставляют значения: `"$name"` или `"${user.name}"`. Тройные кавычки создают многострочную строку. `if` и `when` — выражения и возвращают значение.

```kotlin
val name = "Ада"

score += 5
val level: Int = 3

val text = """
    Многострочный
    текст
""".trimIndent()

println(7 / 2.0)      // 3.5
```

@lesson Условия, циклы и when
`when` — мощная замена switch: сравнивает со значениями, диапазонами (`in 1..9`), типами (`is String`) или работает без аргумента как цепочка условий. Как и if, это выражение.
Циклы: `for (x in collection)`, диапазоны `1..10`, `until`, `downTo`, `step`. `while` и `do-while` тоже есть. `forEachIndexed` и `withIndex()` дают индекс.
Метки `break@outer` выходят из вложенного цикла. В лямбдах `return@forEach` пропускает текущий элемент.
```kotlin
fun grade(score: Int) = when (score) {
    in 90..100 -> "A"
    in 75 until 90 -> "B"
    else -> "C"
}

fun describe(x: Any) = when (x) {
    is Int -> "число $x"
    is String -> "строка длиной ${x.length}"
    else -> "что-то ещё"
}

for (i in 10 downTo 0 step 5) print("$i ")   // 10 5 0
for ((i, v) in listOf("a", "b").withIndex()) println("$i:$v")
println(grade(80))   // B
```
! when без else должен покрывать все варианты, если используется как выражение
! `until` не включает верхнюю границу
! is в when сразу делает smart cast


@lesson Null-безопасность
Типы делятся на не-nullable (`String`) и nullable (`String?`). В обычную переменную нельзя положить null — компилятор не даст.
Безопасный вызов `?.` вернёт null вместо падения. Элвис-оператор `?:` подставляет значение по умолчанию. `!!` утверждает, что значения не null, и бросает исключение, если вы ошиблись.
После проверки `if (x != null)` компилятор сам считает x не-null (smart cast). Функция `let` выполняет блок только для не-null значения.
```kotlin
var email: String? = null
val length = email?.length ?: 0        // 0
email?.let { sendTo(it) }              // не выполнится

fun greet(name: String?) {
    if (name == null) return
    println(name.uppercase())          // smart cast к String
}

val port = System.getenv("PORT")?.toIntOrNull() ?: 8080
```
! `!!` — почти всегда признак плохого кода
! `?:` удобно сочетать с return и throw: `val u = find(id) ?: return`
! Java-методы возвращают «платформенные» типы — проверяйте их
? mc Что вернёт `s?.length`, если s = null?
- 0
+ null
- NullPointerException
- -1
= Безопасный вызов не падает.
? out Что выведет код?
```kotlin

```
> -1
= Элвис подставил значение по умолчанию.

> ?:
= Элвис-оператор.
? mc Что делает `x!!`?
- Проверяет x на null и возвращает false
+ Возвращает x или бросает NullPointerException, если x — null
- Делает x неизменяемым
- Копирует x
= Используйте только когда null действительно невозможен.

@lesson Функции и лямбды
Функции объявляют через `fun`. Однострочная функция пишется через `=`. Параметры могут иметь значения по умолчанию, а аргументы — передаваться по имени.
Функции высшего порядка принимают или возвращают функции. Лямбду пишут в фигурных скобках, единственный параметр доступен как `it`. Если лямбда — последний аргумент, её выносят за скобки.
Функции-расширения добавляют методы к существующим классам без наследования: `fun String.isEmail(): Boolean`.
```kotlin
fun area(w: Int, h: Int = w) = w * h

fun String.initials() = split(" ").joinToString("") { it.first().uppercase() }

fun repeatTimes(n: Int, action: (Int) -> Unit) {
    for (i in 1..n) action(i)
}

println(area(3))              // 9
println(area(w = 2, h = 5))   // 10
println("ада лавлейс".initials())  // АЛ
repeatTimes(2) { println("Шаг $it") }
```
! Именованные аргументы делают вызовы понятнее
! it удобен только в коротких лямбдах
! Расширения не меняют класс — это синтаксический сахар над статической функцией

@lesson Коллекции
Коллекции бывают только для чтения (`List`, `Set`, `Map`) и изменяемые (`MutableList` и др.). Создают их через `listOf`, `mutableListOf`, `mapOf("a" to 1)`.
Богатая стандартная библиотека: `filter`, `map`, `groupBy`, `associateBy`, `sumOf`, `sortedBy`, `firstOrNull`, `partition`.
`Sequence` вычисляет цепочку лениво, по элементу, — полезно для больших коллекций и длинных цепочек операций.
```kotlin
data class Order(val customer: String, val total: Int, val paid: Boolean)

val orders = listOf(
    Order("Ада", 120, true),
    Order("Алан", 80, false),
    Order("Ада", 200, true),
)

val revenue = orders.filter { it.paid }.sumOf { it.total }       // 320
val byCustomer = orders.groupBy { it.customer }                   // Map<String, List<Order>>
val (paid, unpaid) = orders.partition { it.paid }
val top = orders.maxByOrNull { it.total }?.customer               // Ада
val ages = mapOf("Ада" to 36, "Алан" to 41)
```

! firstOrNull безопаснее first
! `to` создаёт пару для mapOf

@lesson Классы, data class, sealed
Основной конструктор пишут в заголовке класса: `class User(val name: String)`. Классы по умолчанию `final`, для наследования их помечают `open`.
`data class` автоматически получает `equals`, `hashCode`, `toString`, `copy` и деструктуризацию. Это стандарт для моделей данных.
`sealed` класс или интерфейс ограничивает набор наследников. `when` по sealed-типу проверяется компилятором на полноту — удобно для состояний экрана. `object` — синглтон.
```kotlin
data class User(val id: Int, val name: String)

val u = User(1, "Ада")
val renamed = u.copy(name = "Ада Л.")
println(u == User(1, "Ада"))      // true

sealed interface UiState {
    object Loading : UiState
    data class Success(val items: List<String>) : UiState
    data class Error(val message: String) : UiState
}

fun render(s: UiState) = when (s) {
    UiState.Loading -> "Загрузка"
    is UiState.Success -> "Элементов: ${s.items.size}"
    is UiState.Error -> "Ошибка: ${s.message}"
}
```
! Классы final по умолчанию — для наследования нужен open
! copy создаёт новый объект, исходный не меняется
! when по sealed без else ловит забытые состояния при компиляции

@lesson Корутины
Корутины — лёгкие задачи, которые приостанавливаются без блокировки потока. Функция с `suspend` может вызывать другие suspend-функции, например сетевые запросы.
Корутины запускают в области (scope): `launch` — без результата, `async` — с результатом через `await()`. Структурная конкурентность: при отмене scope отменяются все его корутины.
Диспетчеры выбирают поток: `Dispatchers.Main` для UI, `IO` для сети и диска, `Default` для вычислений. В Android используют `viewModelScope`.
```kotlin
suspend fun loadUser(id: Int): User = withContext(Dispatchers.IO) {
    api.getUser(id)
}

class ProfileViewModel : ViewModel() {
    fun load() = viewModelScope.launch {
        try {
            val user = async { loadUser(1) }
            val stats = async { loadStats(1) }
            show(user.await(), stats.await())   // параллельно
        } catch (e: IOException) {
            showError(e.message)
        }
    }
}
```
! suspend-функцию можно вызвать только из корутины или другой suspend-функции
! Не используйте GlobalScope: корутина переживёт экран и утечёт
! Два async подряд выполняются параллельно, два обычных вызова — по очереди
? mc Что значит модификатор suspend?
- Функция выполняется в отдельном потоке
+ Функция может приостанавливаться, не блокируя поток
- Функция запускается позже
- Функция не возвращает значение
= Приостановка не занимает поток.

+ async возвращает результат через await()
- launch быстрее
- async блокирует поток
- Ничем
= launch возвращает Job без результата.

@lesson Flow и архитектура приложения
`Flow` — асинхронный поток значений. Он холодный: начинает работать при сборе через `collect`. Операторы `map`, `filter`, `combine`, `debounce` преобразуют поток.
`StateFlow` хранит текущее состояние и сразу отдаёт его новым подписчикам — идеально для состояния экрана в ViewModel. Room и DataStore умеют возвращать Flow.
Архитектура MVVM: экран (Compose) только рисует состояние и передаёт события, ViewModel держит логику и StateFlow, репозиторий решает, откуда брать данные.
```kotlin
class SearchViewModel(private val repo: Repo) : ViewModel() {
    private val query = MutableStateFlow("")

    val results: StateFlow<List<Item>> = query
        .debounce(300)
        .map { q -> repo.search(q) }
        .stateIn(viewModelScope, SharingStarted.WhileSubscribed(5000), emptyList())

    fun onQueryChange(q: String) { query.value = q }
}

@Composable
fun SearchScreen(vm: SearchViewModel) {
    val items by vm.results.collectAsStateWithLifecycle()
    LazyColumn { items(items) { Text(it.title) } }
}
```
! Экран не должен ходить в сеть или базу напрямую
! Наружу отдавайте StateFlow, а MutableStateFlow держите приватным
! debounce экономит запросы при наборе текста
? mc Что значит «холодный» Flow?
+ Он начинает выдавать значения только при сборе
- Он работает медленно
- Он не меняется
- Он хранит последнее значение
= Каждый collect запускает поток заново.
? mc Что отличает StateFlow?
- Он холодный
+ Всегда имеет текущее значение и сразу отдаёт его подписчикам
- Он только для UI-потока
- Он не поддерживает map
= Это держатель состояния.
