@lesson Константы, переменные и опционалы
`let` объявляет константу, `var` — переменную. Swift советует `let` везде, где значение не меняется. Тип выводится автоматически, но можно указать явно.
Опционал `String?` хранит значение или `nil`. Достать значение безопасно можно через `if let`, `guard let` или подставить значение по умолчанию через `??`.
Принудительное разворачивание `!` падает при nil — избегайте его. Интерполяция строк: `"Привет, \(name)"`.
```swift
let name = "Ада"
var score = 0
score += 10

var nickname: String? = nil
print(nickname ?? "Гость")             // Гость

func greet(_ user: String?) {
    guard let user else {
        print("Нет пользователя")
        return
    }
    print("Привет, \(user)")
}

if let age = Int("36") {
    print(age + 1)                      // 37
}
```
! guard let выходит из функции рано и оставляет основной код без вложенности
! Int("abc") вернёт nil, а не 0
! `!` только когда nil действительно невозможен

@lesson Управление потоком и коллекции
`for-in` перебирает диапазоны (`1...5` включительно, `1..<5` без последнего) и коллекции. `switch` должен быть исчерпывающим и не проваливается в следующий case.
Коллекции: `Array`, `Set`, `Dictionary`. Они значимые типы: присваивание копирует (оптимизировано через copy-on-write).
Функции высшего порядка: `map`, `filter`, `reduce`, `compactMap` (убирает nil), `sorted(by:)`.
```swift
for i in 1...3 { print(i) }

let scores = ["Ада": 90, "Алан": 72]
for (name, score) in scores.sorted(by: { $0.value > $1.value }) {
    print(name, score)
}

let raw = ["1", "x", "3"]
let numbers = raw.compactMap { Int($0) }            // [1, 3]
let total = numbers.reduce(0, +)                    // 4

let grade = switch total {
    case 0..<3: "low"
    case 3...10: "mid"
    default: "high"
}
print(grade)                                        // mid
```
! Словарь не упорядочен — сортируйте перед выводом
! compactMap удобно отбрасывает неудачные преобразования
! Массив копируется при присваивании, в отличие от NSArray

@lesson Функции и замыкания
У параметров есть внешние метки для читаемых вызовов: `move(from: a, to: b)`. `_` убирает метку. Параметры по умолчанию и variadic `Int...` поддерживаются.
Замыкание — функция без имени в фигурных скобках. Короткие аргументы `$0`, `$1`. Если замыкание — последний аргумент, его пишут после скобок (trailing closure).
Замыкание, которое вызовется позже (после возврата функции), помечается `@escaping`. Захват `self` в таких замыканиях может создать цикл ссылок — используйте `[weak self]`.
```swift
func send(_ text: String, to user: String, urgent: Bool = false) -> String {
    "\(urgent ? "СРОЧНО: " : "")\(user) ← \(text)"
}
print(send("Привет", to: "Ада"))

func sum(_ nums: Int...) -> Int { nums.reduce(0, +) }
print(sum(1, 2, 3))                       // 6

let sorted = ["bb", "a", "ccc"].sorted { $0.count < $1.count }

class Loader {
    var onDone: (() -> Void)?
    func load(completion: @escaping (String) -> Void) {
        DispatchQueue.global().async { completion("данные") }
    }
}
```
! Однострочная функция возвращает выражение без return
! [weak self] в escaping-замыканиях предотвращает утечки
! Метки аргументов — часть имени функции

@lesson struct, class и enum
`struct` — значимый тип: копируется при передаче. Методы, меняющие структуру, помечаются `mutating`. Apple рекомендует начинать со struct.
`class` — ссылочный тип с наследованием и подсчётом ссылок (ARC). Используйте класс, когда нужна общая изменяемая сущность или идентичность.
`enum` с ассоциированными значениями описывает варианты состояния. Через `switch` их разбирают полностью.
```swift
struct Counter {
    var value = 0
    mutating func increment() { value += 1 }
}

final class Session {
    let user: String
    init(user: String) { self.user = user }
}

enum LoadState {
    case idle
    case loading
    case loaded([String])
    case failed(Error)
}

func describe(_ s: LoadState) -> String {
    switch s {
    case .idle: "Ожидание"
    case .loading: "Загрузка"
    case .loaded(let items): "Загружено: \(items.count)"
    case .failed(let error): "Ошибка: \(error.localizedDescription)"
    }
}
```
! mutating нужен методам struct, которые меняют поля
! final запрещает наследование и ускоряет вызовы
! enum с данными — лучший способ описать состояние экрана

@lesson Протоколы и расширения
Протокол — контракт с требованиями к методам и свойствам. Его реализуют struct, class и enum. Протоколы — основа Swift: `Equatable`, `Hashable`, `Codable`, `Identifiable`.
`extension` добавляет методы существующим типам и реализации по умолчанию протоколам. Так строят протокольно-ориентированный код.
`some Protocol` — непрозрачный тип: функция возвращает конкретный тип, но скрывает его. `any Protocol` — коробка с любым типом, реализующим протокол.
```swift
protocol Shape {
    var area: Double { get }
}

extension Shape {
    func describe() -> String { "Площадь \(area)" }
}

struct Square: Shape { let side: Double; var area: Double { side * side } }
struct Circle: Shape { let r: Double; var area: Double { .pi * r * r } }

extension Int {
    var isEven: Bool { self % 2 == 0 }
}

let shapes: [any Shape] = [Square(side: 2), Circle(r: 1)]
print(shapes.map { $0.describe() })
print(4.isEven)                         // true

struct User: Codable, Hashable, Identifiable {
    let id: Int
    let name: String
}
```
! Codable даёт кодирование в JSON без ручного кода
! Identifiable нужен спискам в SwiftUI
! some — один конкретный тип, any — любой подходящий

+ Новую функциональность существующему типу

- Новое хранимое свойство
- Приватность
= Хранимые свойства в extension добавить нельзя.

@lesson Ошибки и async/await
Функция, которая может вернуть ошибку, помечается `throws`. Вызов пишут через `try` внутри `do`/`catch`. `try?` превращает ошибку в nil.
Асинхронные функции помечаются `async` и вызываются через `await`. `async let` запускает несколько операций параллельно. `Task { }` запускает асинхронную работу из синхронного кода.
`@MainActor` гарантирует выполнение на главном потоке — обновлять UI можно только там. Акторы (`actor`) защищают своё состояние от гонок данных.
```swift
enum APIError: Error { case badStatus(Int) }

struct Exercise: Decodable { let name: String }

func loadExercises() async throws -> [Exercise] {
    let url = URL(string: "https://example.com/exercises.json")!
    let (data, response) = try await URLSession.shared.data(from: url)
    guard let http = response as? HTTPURLResponse, http.statusCode == 200 else {
        throw APIError.badStatus((response as? HTTPURLResponse)?.statusCode ?? 0)
    }
    return try JSONDecoder().decode([Exercise].self, from: data)
}

@MainActor
func refresh() async {
    async let a = loadExercises()
    async let b = loadExercises()
    do {
        let all = try await a + b
        print(all.count)
    } catch {
        print("Ошибка: \(error)")
    }
}
```
! Обновление UI — только на MainActor
! try? удобен, когда причина ошибки не важна
! async let запускает задачи параллельно, обычные await — по очереди
? mc Как вызвать функцию с throws?
- Просто по имени
+ Через try внутри do/catch или в другой throws-функции
- Через await
- Через catch без try
= try помечает место возможной ошибки.

@lesson SwiftUI: состояние и архитектура
SwiftUI описывает интерфейс декларативно: `View` — функция от состояния. Изменилось состояние — SwiftUI сам перерисует нужные части.
`@State` хранит локальное состояние экрана, `@Binding` передаёт его дочернему View для изменения. Модели с макросом `@Observable` отслеживаются автоматически. `@Environment` даёт доступ к общим значениям.
MVVM: View отображает состояние модели и передаёт действия, модель содержит логику и ходит в сеть или базу. Навигация через `NavigationStack`, списки — `List` и `ForEach`.
```swift
import SwiftUI

@Observable
final class WorkoutsModel {
    var items: [String] = []
    var isLoading = false
    func add(_ name: String) { items.append(name) }
}

struct WorkoutsView: View {
    @State private var model = WorkoutsModel()
    @State private var newName = ""

    var body: some View {
        NavigationStack {
            List {
                ForEach(model.items, id: \.self) { Text($0) }
            }
            .navigationTitle("Тренировки")
            .toolbar {
                TextField("Новая", text: $newName)
                Button("Добавить") { model.add(newName); newName = "" }
            }
        }
    }
}
```
! `$value` передаёт Binding — двустороннюю связь
! Не держите сетевую логику прямо во View
! body пересчитывается часто — он должен быть быстрым и без побочных эффектов

@lesson ARC, память и сборка в Xcode
Swift управляет памятью через ARC — автоматический подсчёт ссылок. Объект класса освобождается, когда на него не осталось сильных ссылок. Сборщика мусора нет.
Цикл сильных ссылок (A держит B, B держит A) не освободится никогда — это утечка. Разрывают его через `weak` (опциональная, обнуляется) или `unowned` (не опциональная, объект должен жить дольше).
Приложение собирают в Xcode. Зависимости подключают через Swift Package Manager. Для публикации нужны аккаунт Apple Developer, подпись, архив (Product → Archive) и загрузка в App Store Connect. Тестируют через TestFlight.
```swift
final class Person {
    let name: String
    var apartment: Apartment?
    init(name: String) { self.name = name }
    deinit { print("\(name) освобождён") }
}

final class Apartment {
    weak var tenant: Person?            // слабая ссылка разрывает цикл
}

var p: Person? = Person(name: "Ада")
let flat = Apartment()
p?.apartment = flat
flat.tenant = p
p = nil                                 // "Ада освобождён"
```
! Делегаты почти всегда объявляют weak
! deinit помогает проверить, что объект освобождается
! Instruments → Leaks находит утечки
? mc Как Swift управляет памятью объектов классов?
- Сборщиком мусора
+ Автоматическим подсчётом ссылок (ARC)
- Вручную через free
- Не управляет
= Объект освобождается при нулевом счётчике.
