@lesson Миграции
Миграции описывают структуру базы кодом и хранятся в Git: `php artisan make:migration create_courses_table`. В методе `up` создают таблицу, в `down` — откатывают.
Схема: `$table->id()`, `string('title')`, `integer('price')`, `foreignId('user_id')->constrained()->cascadeOnDelete()`, `timestamps()` (created_at и updated_at), `unique`, `index`.
`php artisan migrate` применяет новые миграции, `migrate:rollback` откатывает последнюю пачку. Уже применённую на сервере миграцию не меняют — пишут новую.
```code
<?php
use Illuminate\Database\Migrations\Migration;
use Illuminate\Database\Schema\Blueprint;
use Illuminate\Support\Facades\Schema;

return new class extends Migration {
    public function up(): void
    {
        Schema::create('courses', function (Blueprint $table) {
            $table->id();
            $table->foreignId('user_id')->constrained()->cascadeOnDelete();   // автор
            $table->string('title', 120)->unique();
            $table->unsignedInteger('price')->default(0);
            $table->enum('level', ['beginner', 'middle', 'advanced'])->index();
            $table->timestamp('published_at')->nullable();
            $table->timestamps();
        });
    }

    public function down(): void
    {
        Schema::dropIfExists('courses');
    }
};
```
! Применённые миграции не редактируют — создают новые
! Внешние ключи — `foreignId()->constrained()`
! Столбцы для частых фильтров — с индексом

@lesson Модели и запросы
Модель Eloquent — класс, связанный с таблицей: `Course` → `courses`. Создание — `php artisan make:model Course -mf` (с миграцией и фабрикой).
Запросы строят цепочкой: `Course::where('level', 'beginner')->orderByDesc('price')->paginate(20)`. `find($id)`, `findOrFail($id)` (сам вернёт 404), `first()`, `count()`, `exists()`.
Массовое заполнение защищено: разрешённые поля перечисляют в `$fillable`. `$casts` превращает столбцы в нужные типы (`'published_at' => 'datetime'`, `'meta' => 'array'`).
```code
<?php
namespace App\Models;

use Illuminate\Database\Eloquent\Builder;
use Illuminate\Database\Eloquent\Factories\HasFactory;
use Illuminate\Database\Eloquent\Model;

class Course extends Model
{
    use HasFactory;

    protected $fillable = ['title', 'price', 'level', 'published_at'];
    protected $casts = ['published_at' => 'datetime', 'price' => 'integer'];

    public function scopePublished(Builder $q): Builder      // Course::published()
    {
        return $q->whereNotNull('published_at');
    }
}

// $cheap = Course::published()->where('price', '<', 10000)->orderBy('price')->get();
// $course = Course::findOrFail($id);
// $course->update(['price' => 7000]);
// Course::where('level', 'advanced')->count();
```
! `findOrFail` вместо ручной проверки на null
! `$fillable` защищает от записи лишних полей
! Повторяющиеся условия — в scope-методы

@lesson Связи и проблема N+1
Связи описывают методами: `hasMany` (у автора много курсов), `belongsTo` (курс принадлежит автору), `belongsToMany` (студенты и курсы через таблицу `course_user`), `hasOne`.
Обращение `$course->author` загружает связь отдельным запросом. В цикле по 50 курсам это 51 запрос — проблема N+1. Решение — жадная загрузка: `Course::with('author')->get()` — два запроса.
`withCount('lessons')` добавляет количество без загрузки самих уроков; `Model::preventLazyLoading()` в разработке сообщает о забытом `with`.
```code
<?php
class User extends Model
{
    public function courses() { return $this->hasMany(Course::class); }
    public function enrolled() { return $this->belongsToMany(Course::class)->withTimestamps(); }
}

class Course extends Model
{
    public function author() { return $this->belongsTo(User::class, 'user_id'); }
    public function lessons() { return $this->hasMany(Lesson::class); }
}

// плохо: 1 + N запросов
// foreach (Course::all() as $c) echo $c->author->name;

// хорошо: 2 запроса + количество уроков одним подзапросом
$courses = Course::with('author')->withCount('lessons')->get();
// foreach ($courses as $c) echo "$c->title — {$c->author->name}, уроков: $c->lessons_count";

// запись в связь многие-ко-многим
// $user->enrolled()->attach($courseId);
// $user->enrolled()->syncWithoutDetaching([$courseId]);
```
! В списках всегда `with()` для используемых связей
! `withCount` вместо `count()` в цикле
! `preventLazyLoading` в разработке ловит N+1
? mc Сколько запросов сделает цикл по 50 курсам с `$c->author->name` без with?
+ 51
- 1

- 50

@lesson Фабрики, сидеры и транзакции
Фабрики генерируют тестовые записи: `Course::factory()->count(10)->create()`. В `definition()` описывают поля через Faker. Состояния — `->state(['level' => 'advanced'])` или методы `published()`.
Сидеры наполняют базу для разработки: `php artisan db:seed`, а `migrate:fresh --seed` пересоздаёт базу с нуля.
Несколько связанных изменений делают в транзакции: `DB::transaction(function () {...})` — при исключении всё откатится. Для денег и остатков нужна блокировка `lockForUpdate()`.
```code
<?php
namespace Database\Factories;

use Illuminate\Database\Eloquent\Factories\Factory;

class CourseFactory extends Factory
{
    public function definition(): array
    {
        return [
            'user_id' => \App\Models\User::factory(),
            'title' => fake()->unique()->sentence(3),
            'price' => fake()->numberBetween(0, 50) * 1000,
            'level' => fake()->randomElement(['beginner', 'middle', 'advanced']),
        ];
    }

    public function published(): static
    {
        return $this->state(fn () => ['published_at' => now()]);
    }
}
```
