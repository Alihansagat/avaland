@lesson App Router и страницы
В Next.js маршруты задаются папками внутри `app/`: файл `app/page.tsx` — главная, `app/blog/page.tsx` — страница `/blog`. Динамический сегмент — папка в квадратных скобках: `app/blog/[slug]/page.tsx` отвечает на `/blog/hello`.
`layout.tsx` оборачивает все страницы своей папки: шапка и меню рисуются один раз и не перерисовываются при переходах. `loading.tsx` показывается во время загрузки, `error.tsx` — при ошибке, `not-found.tsx` — для 404.
Ссылки между страницами делает компонент `<Link href="/blog">` — переход происходит без перезагрузки, а Next.js заранее подгружает страницы из видимых ссылок.
```code
// app/layout.tsx
export default function RootLayout({ children }) {
  return (
    <html lang="ru">
      <body>
        <header><a href="/">AVALAND Blog</a></header>
        {children}
      </body>
    </html>
  );
}

// app/blog/[slug]/page.tsx
import Link from "next/link";
import { notFound } from "next/navigation";

const posts = { hello: "Первый пост", react: "Почему React" };

export default async function Post({ params }) {
  const { slug } = await params;
  const title = posts[slug];
  if (!title) notFound();
  return <article><h1>{title}</h1><Link href="/blog">← все посты</Link></article>;
}
```
! Папка — сегмент URL, `page.tsx` делает его страницей
! `layout.tsx` сохраняет состояние при переходах между дочерними страницами
! Внутренние ссылки — через `<Link>`, а не `<a>`

@lesson Серверные и клиентские компоненты
В App Router компоненты по умолчанию серверные: они выполняются на сервере, могут быть `async`, напрямую ходить в базу и не попадают в JavaScript браузера. Это быстрее и безопаснее: секретные ключи остаются на сервере.
Если компоненту нужны состояние, эффекты или обработчики кликов, в начале файла пишут `"use client"` — это клиентский компонент. Хорошая практика — держать клиентские компоненты маленькими «островками» интерактивности внутри серверных страниц.
Серверный компонент может передать клиентскому данные через props, но только сериализуемые: строки, числа, объекты, массивы — не функции.
```code
// app/products/page.tsx — серверный компонент
import AddToCart from "./AddToCart";

async function getProducts() {
  const res = await fetch("https://api.example.com/products", { next: { revalidate: 60 } });
  return res.json();
}

export default async function Products() {
  const products = await getProducts();          // выполняется на сервере
  return (
    <ul>
      {products.map(p => (
        <li key={p.id}>{p.name} — {p.price} ₸ <AddToCart id={p.id} /></li>
      ))}
    </ul>
  );
}

// app/products/AddToCart.tsx — клиентский островок
"use client";
import { useState } from "react";
export default function AddToCart({ id }) {
  const [added, setAdded] = useState(false);
  return <button onClick={() => setAdded(true)}>{added ? "В корзине" : "В корзину"}</button>;
}
```
! По умолчанию компонент серверный; `"use client"` — только где нужна интерактивность
! В серверных компонентах нельзя `useState`, `useEffect` и обработчики событий
! Секреты (ключи API, пароли БД) — только в серверном коде и переменных окружения без префикса `NEXT_PUBLIC_`

@lesson Данные, кэш и Server Actions
`fetch` в серверных компонентах Next.js умеет кэшировать: `{ cache: "force-cache" }` — статично, `{ next: { revalidate: 60 } }` — обновлять раз в минуту, `{ cache: "no-store" }` — каждый раз свежие данные. Это определяет, будет страница статической или динамической.
Server Actions — функции с `"use server"`, которые можно вызвать из формы: `<form action={createPost}>`. Они выполняются на сервере, могут писать в базу и после изменения вызывают `revalidatePath`, чтобы страница показала новые данные.
Route Handlers (`app/api/.../route.ts`) — обычные API-эндпоинты с функциями `GET`, `POST`, возвращающими `Response`. Их используют для вебхуков и внешних клиентов.
```code
// app/posts/page.tsx
import { revalidatePath } from "next/cache";
import { db } from "@/lib/db";

async function createPost(formData) {
  "use server";
  const title = String(formData.get("title") || "").trim();
  if (title.length < 3) return;
  await db.post.create({ data: { title } });
  revalidatePath("/posts");
}

export default async function Posts() {
  const posts = await db.post.findMany({ orderBy: { id: "desc" } });
  return (
    <>
      <form action={createPost}><input name="title" /><button>Создать</button></form>
      <ul>{posts.map(p => <li key={p.id}>{p.title}</li>)}</ul>
    </>
  );
}

// app/api/health/route.ts
export async function GET() {
  return Response.json({ ok: true, time: Date.now() });
}
```
! Всегда проверяйте данные в Server Action: это открытый эндпоинт
! После изменения данных — `revalidatePath` или `revalidateTag`
! `no-store` для персональных данных, `revalidate` — для каталога и блога
? mc Что делает `{ next: { revalidate: 60 } }` в fetch?

@lesson Оптимизация и деплой
Next.js оптимизирует ресурсы: `next/image` сжимает и подгоняет картинки под экран, `next/font` загружает шрифты без скачков текста, метаданные страниц задаются через `export const metadata` или `generateMetadata` — это важно для SEO.
Перед деплоем запускают `next build`: он покажет, какие страницы статические, какие динамические, и найдёт ошибки типов. Переменные окружения задают в `.env.local` локально и в настройках хостинга в проде.
Проще всего деплоить на Vercel (подключить репозиторий GitHub), также подходят Docker на любом сервере или `output: "export"` для полностью статического сайта.
```code
// app/blog/[slug]/page.tsx
import Image from "next/image";

export async function generateMetadata({ params }) {
  const { slug } = await params;
  return { title: `${slug} — блог`, description: "Статья в блоге AVALAND" };
}

export default async function Page({ params }) {
  const { slug } = await params;
  return (
    <article>
      <Image src={`/covers/${slug}.jpg`} alt="Обложка" width={800} height={400} priority />
    </article>
  );
}

// package.json
// "scripts": { "dev": "next dev", "build": "next build", "start": "next start" }
```
! Всегда задавайте `alt`, `width` и `height` для `Image`
! `next build` перед каждым деплоем — ловит ошибки до продакшена
! Секреты — в переменных окружения хостинга, не в репозитории
