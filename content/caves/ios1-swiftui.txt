@lesson View и модификаторы
Экран в SwiftUI — структура, реализующая протокол `View` со свойством `body`. Интерфейс собирают из стеков: `VStack` — сверху вниз, `HStack` — слева направо, `ZStack` — наложение; `Spacer` раздвигает элементы.
Внешний вид меняют модификаторами: `.font(.title)`, `.padding()`, `.foregroundStyle(.secondary)`, `.background(...)`. Каждый модификатор возвращает новый View, поэтому порядок важен.
Превью в Xcode — макрос `#Preview { ContentView() }`: изменения видны сразу, без запуска симулятора.
```code
import SwiftUI

struct Course {
    let title: String
    let done: Int
    let total: Int
    var progress: Double { Double(done) / Double(total) }
}

struct CourseCard: View {
    let course: Course

    var body: some View {
        VStack(alignment: .leading, spacing: 8) {
            Text(course.title).font(.headline)
            ProgressView(value: course.progress)
            HStack {
                Text("\(course.done) из \(course.total) уроков")
                    .font(.caption)
                    .foregroundStyle(.secondary)
                Spacer()
                Image(systemName: course.progress == 1 ? "checkmark.seal.fill" : "chevron.right")
            }
        }
        .padding()
        .background(.thinMaterial, in: RoundedRectangle(cornerRadius: 16))
        .padding(.horizontal)
    }
}

#Preview {
    CourseCard(course: Course(title: "Swift", done: 3, total: 8))
}
```
! View — структура, `body` описывает, что показать
! Порядок модификаторов меняет результат
! Иконки — SF Symbols через `Image(systemName:)`

@lesson Состояние: @State и @Binding
Данные, от которых зависит экран, хранят в `@State` — SwiftUI перерисует body при их изменении. `@State` принадлежит View и делается `private`.
Дочернему View, который должен менять значение родителя, передают `@Binding` через знак доллара: `Toggle("Уведомления", isOn: $notifications)`. Так у значения один владелец.
Поле ввода `TextField("Имя", text: $name)` тоже связывается биндингом; модификатор `.onChange(of:)` реагирует на изменение значения.
```code
import SwiftUI

struct QuantityStepper: View {
    @Binding var qty: Int                          // значение принадлежит родителю
    var body: some View {
        HStack {
            Button("−") { qty = max(0, qty - 1) }
            Text("\(qty)").monospacedDigit()
            Button("+") { qty += 1 }
        }
    }
}

struct CartRow: View {
    let title: String
    let price: Int
    @State private var qty = 1
    @State private var giftWrap = false

    var total: Int { qty * price + (giftWrap ? 500 : 0) }

    var body: some View {
        VStack(alignment: .leading) {
            Text(title)
            QuantityStepper(qty: $qty)
            Toggle("Подарочная упаковка", isOn: $giftWrap)
            Text("Итого: \(total) ₸").bold()
        }
        .padding()
    }
}
```
! `@State` — для простого локального состояния, всегда `private`
! `$value` передаёт биндинг — дочерний View сможет менять значение
! Вычисляемые свойства пересчитываются при каждой перерисовке

@lesson Списки и навигация
`List` показывает прокручиваемый список, элементы должны быть `Identifiable` (свойство `id`) или указывать `id: \.self`. Свайп для удаления добавляет `.onDelete`, подтягивание для обновления — `.refreshable`.
Навигацию строит `NavigationStack`: `NavigationLink(value: item)` и `.navigationDestination(for: Item.self) { ... }` описывают переходы, `.navigationTitle` задаёт заголовок. Путь навигации можно хранить в состоянии и переходить программно.
Модальные окна — `.sheet(isPresented:)`, предупреждения — `.alert`.
```code
import SwiftUI

struct Lesson: Identifiable, Hashable {
    let id: Int
    let title: String
}

struct LessonsView: View {
    @State private var lessons = [Lesson(id: 1, title: "Переменные"), Lesson(id: 2, title: "Функции")]
    @State private var showAdd = false

    var body: some View {
        NavigationStack {
            List {
                ForEach(lessons) { lesson in
                    NavigationLink(lesson.title, value: lesson)
                }
                .onDelete { lessons.remove(atOffsets: $0) }
            }
            .navigationTitle("Уроки")
            .navigationDestination(for: Lesson.self) { lesson in
                Text("Урок \(lesson.id): \(lesson.title)")
            }
            .toolbar { Button("Добавить") { showAdd = true } }
            .sheet(isPresented: $showAdd) {
                Text("Новый урок")
            }
        }
    }
}
```
! Элементы `List` и `ForEach` — `Identifiable` со стабильным `id`
! `NavigationStack` + `navigationDestination(for:)` — современная навигация
! Модальные экраны управляются булевым состоянием

@lesson Observation и архитектура экрана
Состояние, общее для нескольких экранов, хранят в классе модели с макросом `@Observable`: SwiftUI сам отслеживает, какие свойства читает View, и перерисовывает только нужное. Модель создают через `@State private var model = Model()` или передают через `.environment(model)`.
Логику загрузки и действий держат в модели (подход MVVM): View вызывает `model.load()`, а показывает `model.state`. Асинхронную загрузку запускают модификатором `.task { await model.load() }` — он отменится, когда экран исчезнет.
Код, меняющий интерфейс, выполняется на главном потоке — модели экрана помечают `@MainActor`.
```code
import SwiftUI
import Observation

@MainActor
@Observable
final class CoursesModel {
    enum State { case loading, loaded([String]), failed(String) }
    var state: State = .loading

    func load() async {
        state = .loading
        do {
            try await Task.sleep(for: .milliseconds(300))     // имитация сети
            state = .loaded(["Swift", "SwiftUI", "SwiftData"])
        } catch {
            state = .failed("Не удалось загрузить")
        }
    }
}

struct CoursesView: View {
    @State private var model = CoursesModel()
    var body: some View {
        Group {
            switch model.state {
            case .loading: ProgressView()
            case .loaded(let titles): List(titles, id: \.self) { Text($0) }
            case .failed(let msg): ContentUnavailableView(msg, systemImage: "wifi.slash")
            }
        }
        .task { await model.load() }
    }
}
```
! `@Observable` — современная замена ObservableObject и @Published
! `.task` для загрузки при появлении экрана, с автоматической отменой
! Модели интерфейса — `@MainActor`
? mc Чем `.task { }` лучше запуска Task в onAppear?
+ Задача автоматически отменяется, когда View исчезает
- Работает без async
- Быстрее загружает данные
- Ничем
= Нет утечек и лишней работы после ухода с экрана.

+ Позволяет SwiftUI отслеживать чтение свойств и перерисовывать зависимые View
- Сохраняет класс в базу
- Делает класс потокобезопасным
- Превращает класс в структуру
