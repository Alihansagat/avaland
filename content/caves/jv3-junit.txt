@lesson Модульные тесты на JUnit 5
Тест — метод с аннотацией `@Test` в классе из `src/test/java`. Проверки делают через `assertEquals(expected, actual)`, `assertTrue`, `assertThrows`. AssertJ даёт более читаемый стиль: `assertThat(list).hasSize(3).contains("a")`.
`@BeforeEach` выполняется перед каждым тестом — для подготовки объектов. `@DisplayName` даёт тесту понятное название, `@ParameterizedTest` прогоняет один тест на многих входах.
Тесты запускает `./mvnw test`. Хорошее имя теста описывает поведение: `discountIsZeroForSmallOrders`.
```code
import org.junit.jupiter.api.*;
import org.junit.jupiter.params.ParameterizedTest;
import org.junit.jupiter.params.provider.CsvSource;
import static org.junit.jupiter.api.Assertions.*;

class PriceCalculator {
    int total(int sum, int discountPercent) {
        if (discountPercent < 0 || discountPercent > 100) throw new IllegalArgumentException("скидка 0..100");
        return sum * (100 - discountPercent) / 100;
    }
}

class PriceCalculatorTest {
    PriceCalculator calc;

    @BeforeEach
    void setUp() { calc = new PriceCalculator(); }

    @Test
    void appliesDiscount() { assertEquals(900, calc.total(1000, 10)); }

    @Test
    void rejectsWrongDiscount() {
        var e = assertThrows(IllegalArgumentException.class, () -> calc.total(100, 150));
        assertTrue(e.getMessage().contains("0..100"));
    }

    @ParameterizedTest
    @CsvSource({"1000,0,1000", "1000,50,500", "0,30,0"})
    void table(int sum, int d, int expected) { assertEquals(expected, calc.total(sum, d)); }
}
```
! Порядок в assertEquals: сначала ожидаемое, потом фактическое
! `@BeforeEach` — новый объект для каждого теста, тесты независимы
! Параметризованные тесты убирают копипасту

@lesson Моки с Mockito
Mockito создаёт подставные объекты: `@Mock PaymentGateway gateway` — объект, у которого все методы ничего не делают. Поведение задают через `when(gateway.charge(100)).thenReturn(true)`, проверяют вызовы — `verify(gateway).charge(100)`.
`@InjectMocks` создаёт тестируемый класс и подставляет в него моки. Класс тестов помечают `@ExtendWith(MockitoExtension.class)`.
Мокают внешние зависимости: платёжный шлюз, отправку почты, репозиторий. Саму логику тестируемого класса не мокают.
```code
import org.junit.jupiter.api.*;
import org.junit.jupiter.api.extension.ExtendWith;
import org.mockito.*;
import org.mockito.junit.jupiter.MockitoExtension;
import static org.mockito.Mockito.*;
import static org.junit.jupiter.api.Assertions.*;

interface PaymentGateway { boolean charge(long amount); }
interface Mailer { void send(String to, String text); }

class OrderService {
    private final PaymentGateway gateway; private final Mailer mailer;
    OrderService(PaymentGateway g, Mailer m) { gateway = g; mailer = m; }
    String pay(String email, long amount) {
        if (!gateway.charge(amount)) return "DECLINED";
        mailer.send(email, "Оплата " + amount + " ₸ прошла");
        return "PAID";
    }
}

@ExtendWith(MockitoExtension.class)
class OrderServiceTest {
    @Mock PaymentGateway gateway;
    @Mock Mailer mailer;
    @InjectMocks OrderService service;

    @Test
    void sendsReceiptWhenPaid() {
        when(gateway.charge(5000)).thenReturn(true);
        assertEquals("PAID", service.pay("ada@mail.kz", 5000));
        verify(mailer).send(eq("ada@mail.kz"), contains("5000"));
    }

    @Test
    void noEmailWhenDeclined() {
        when(gateway.charge(anyLong())).thenReturn(false);
        assertEquals("DECLINED", service.pay("ada@mail.kz", 5000));
        verifyNoInteractions(mailer);
    }
}
```
! Мокайте внешний мир, а не тестируемую логику
! `verify` проверяет, что нужный вызов произошёл, `verifyNoInteractions` — что не было вызовов
! Если для теста нужно 10 моков — класс делает слишком много
? mc Что делает `when(repo.findById(1L)).thenReturn(Optional.of(user))`?
+ Задаёт, что мок вернёт этот Optional при вызове findById(1L)
- Сохраняет пользователя в базу
- Проверяет, что метод был вызван
- Удаляет пользователя
= Это настройка поведения заглушки.
? mc Как проверить, что письмо НЕ отправлялось?
+ verifyNoInteractions(mailer) или verify(mailer, never()).send(any(), any())
- assertNull(mailer)
- when(mailer).thenThrow()
- Никак
= Mockito умеет проверять отсутствие вызовов.
? out Что выведет код?

@lesson Тесты Spring-контроллеров
`@WebMvcTest(ProductController.class)` поднимает только веб-слой: контроллеры, валидацию, обработчики ошибок — без базы и сервисов. Сервисы подменяют моками через `@MockitoBean`.
`MockMvc` отправляет запросы без настоящего сервера: `mvc.perform(get("/api/products/1"))` и проверяет ответ: `andExpect(status().isOk())`, `jsonPath("$.name").value("Ноутбук")`.
Такие тесты проверяют маршруты, статусы, формат JSON и валидацию — быстро, за доли секунды.
```code
import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.autoconfigure.web.servlet.WebMvcTest;
import org.springframework.test.context.bean.override.mockito.MockitoBean;
import org.springframework.test.web.servlet.MockMvc;
import static org.mockito.Mockito.when;
import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.*;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.*;

@WebMvcTest(ProductController.class)
class ProductControllerTest {
    @Autowired MockMvc mvc;
    @MockitoBean ProductService service;

    @Test
    void returnsProduct() throws Exception {
        when(service.find(1L)).thenReturn(new Product(1, "Ноутбук", 450000));
        mvc.perform(get("/api/products/1"))
           .andExpect(status().isOk())
           .andExpect(jsonPath("$.name").value("Ноутбук"));
    }

    @Test
    void validatesBody() throws Exception {
        mvc.perform(post("/api/products").contentType("application/json").content("{\"name\":\"\"}"))
           .andExpect(status().isBadRequest());
    }
}
```
! `@WebMvcTest` — только веб-слой, быстрый тест
! Сервисы в веб-тестах — моки через `@MockitoBean`
! `jsonPath` проверяет поля ответа
? mc Что поднимает `@WebMvcTest`?

- Всё приложение с базой

@lesson Интеграционные тесты и Testcontainers
`@SpringBootTest` поднимает приложение целиком. Чтобы проверить работу с настоящей базой, используют Testcontainers: тест запускает PostgreSQL в Docker-контейнере, а Spring подключается к нему через `@ServiceConnection`.
`@DataJpaTest` — облегчённый вариант только для репозиториев: проверяет, что запросы и связи работают на реальной СУБД, а не на H2, которая ведёт себя иначе.
Тесты гоняют в CI на каждый pull request; отчёт о покрытии строит JaCoCo. Цель — не 100% покрытия, а уверенность в важных сценариях.
```code
import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.autoconfigure.orm.jpa.DataJpaTest;
import org.springframework.boot.test.autoconfigure.jdbc.AutoConfigureTestDatabase;
import org.springframework.boot.testcontainers.service.connection.ServiceConnection;
import org.testcontainers.containers.PostgreSQLContainer;
import org.testcontainers.junit.jupiter.*;
import static org.assertj.core.api.Assertions.assertThat;

@DataJpaTest
@Testcontainers
@AutoConfigureTestDatabase(replace = AutoConfigureTestDatabase.Replace.NONE)
class BookRepositoryIT {
    @Container @ServiceConnection
    static PostgreSQLContainer<?> pg = new PostgreSQLContainer<>("postgres:17");

    @Autowired BookRepository repo;

    @Test
    void findsByTitleIgnoringCase() {
        repo.save(new Book("Effective Java", 2018));
        repo.save(new Book("Java Concurrency", 2006));
        assertThat(repo.findByTitleContainingIgnoreCase("JAVA")).hasSize(2);
    }
}
```
! Тестируйте запросы на той же СУБД, что в проде, — Testcontainers
! `@DataJpaTest` — для репозиториев, `@SpringBootTest` — для полного сценария
! Интеграционных тестов меньше, чем модульных: они медленнее
? mc Зачем Testcontainers вместо H2 в тестах?
+ Тест идёт на настоящем PostgreSQL, поэтому ловит ошибки, которых H2 не покажет
- H2 платная
- Testcontainers быстрее модульных тестов
- H2 не поддерживает Java
= Разные СУБД отличаются диалектом и поведением.

+ @SpringBootTest
- @WebMvcTest
- @DataJpaTest

= SpringBootTest загружает весь контекст.
