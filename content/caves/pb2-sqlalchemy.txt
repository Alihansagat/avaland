@lesson Модели и сессии
SQLAlchemy 2.0 описывает таблицы классами: наследник `DeclarativeBase`, имя таблицы в `__tablename__`, столбцы — аннотации `Mapped[тип]` и `mapped_column(...)`. `Mapped[str | None]` — столбец может быть пустым.
`create_engine("postgresql+psycopg://user:pass@host/db")` подключает базу (для учёбы — `sqlite://` в памяти). `Base.metadata.create_all(engine)` создаёт таблицы — в настоящих проектах вместо этого миграции Alembic.
Работа с данными идёт через `Session`: `session.add(obj)` готовит вставку, `session.commit()` сохраняет, `session.rollback()` откатывает. После commit у объекта появляется `id` из базы.
```code
from sqlalchemy import String, create_engine
from sqlalchemy.orm import DeclarativeBase, Mapped, Session, mapped_column

class Base(DeclarativeBase):
    pass

class Course(Base):
    __tablename__ = "courses"
    id: Mapped[int] = mapped_column(primary_key=True)
    title: Mapped[str] = mapped_column(String(100), unique=True)
    price: Mapped[int] = mapped_column(default=0)
    description: Mapped[str | None]

engine = create_engine("sqlite://", echo=False)    # echo=True покажет SQL
Base.metadata.create_all(engine)

with Session(engine) as session:
    py = Course(title="Python", price=0)
    session.add(py)
    session.add_all([Course(title="FastAPI", price=4990), Course(title="SQL", price=2990)])
    session.commit()
    print(py.id, py.title)                         # 1 Python

    course = session.get(Course, 2)                # поиск по первичному ключу
    course.price = 3990                            # изменение отслеживается
    session.commit()
    print(session.get(Course, 2).price)            # 3990
```
! `Mapped[...]` + `mapped_column` — стиль SQLAlchemy 2.0
! Ничего не сохранится без `commit()`
! `with Session(...)` закрывает сессию сам

@lesson Запросы: select
Запросы строят функцией `select(...)`: `select(Course).where(Course.price < 5000).order_by(Course.title).limit(10)`. Выполнение — `session.scalars(stmt).all()` (список объектов) или `session.scalar(stmt)` (одно значение).
Условия: `==`, `!=`, `<`, `.in_([...])`, `.like("%py%")`, `.is_(None)`, несколько условий через запятую в `where` (это AND) или `or_(...)`.
Агрегаты — из `sqlalchemy.func`: `select(func.count()).select_from(Course)`, `select(Course.level, func.avg(Course.price)).group_by(Course.level)`. Параметры подставляются безопасно — SQL-инъекции невозможны.
```code
from sqlalchemy import create_engine, func, or_, select
from sqlalchemy.orm import DeclarativeBase, Mapped, Session, mapped_column

class Base(DeclarativeBase):
    pass

class Course(Base):
    __tablename__ = "courses"
    id: Mapped[int] = mapped_column(primary_key=True)
    title: Mapped[str]
    level: Mapped[str]
    price: Mapped[int]

engine = create_engine("sqlite://")
Base.metadata.create_all(engine)
with Session(engine) as s:
    s.add_all([Course(title="Python", level="junior", price=0),
               Course(title="FastAPI", level="middle", price=4990),
               Course(title="SQL", level="junior", price=2990),
               Course(title="Docker", level="middle", price=3990)])
    s.commit()

    cheap = s.scalars(select(Course.title).where(Course.price < 4000).order_by(Course.price.desc())).all()
    print(cheap)                                                     # ['Docker', 'SQL', 'Python']

    print(s.scalar(select(func.count()).select_from(Course).where(Course.level == "middle")))   # 2

    rows = s.execute(select(Course.level, func.avg(Course.price)).group_by(Course.level).order_by(Course.level)).all()
    print([(lvl, round(avg)) for lvl, avg in rows])                 # [('junior', 1495), ('middle', 4490)]

    q = "py"
    found = s.scalars(select(Course).where(or_(Course.title.ilike(f"%{q}%"), Course.price == 0))).all()
    print([c.title for c in found])                                  # ['Python']
```
! `scalars(...).all()` — список объектов или значений
! Значения в `where` передаются параметрами — безопасно
! Агрегаты — через `func`

@lesson Связи и проблема N+1
Связи описывают `ForeignKey` и `relationship`: у курса много уроков — `lessons: Mapped[list["Lesson"]] = relationship(back_populates="course")`, у урока — `course_id: Mapped[int] = mapped_column(ForeignKey("courses.id"))` и `course: Mapped["Course"] = relationship(back_populates="lessons")`.
По умолчанию связь загружается лениво: обращение `course.lessons` в цикле по 50 курсам делает 50 отдельных запросов — проблема N+1. Решение — жадная загрузка: `select(Course).options(selectinload(Course.lessons))` — всего два запроса.
`cascade="all, delete-orphan"` удаляет уроки вместе с курсом. Для «многие ко многим» используют промежуточную таблицу (студенты ↔ курсы).
```code
from sqlalchemy import ForeignKey, create_engine, event, select
from sqlalchemy.orm import DeclarativeBase, Mapped, Session, mapped_column, relationship, selectinload

class Base(DeclarativeBase):
    pass

class Course(Base):
    __tablename__ = "courses"
    id: Mapped[int] = mapped_column(primary_key=True)
    title: Mapped[str]
    lessons: Mapped[list["Lesson"]] = relationship(back_populates="course", cascade="all, delete-orphan")

class Lesson(Base):
    __tablename__ = "lessons"
    id: Mapped[int] = mapped_column(primary_key=True)
    title: Mapped[str]
    course_id: Mapped[int] = mapped_column(ForeignKey("courses.id"))
    course: Mapped[Course] = relationship(back_populates="lessons")

engine = create_engine("sqlite://")
Base.metadata.create_all(engine)
queries = []
event.listen(engine, "before_cursor_execute", lambda *a: queries.append(1))

with Session(engine) as s:
    for name in ["Python", "FastAPI", "SQL"]:
        s.add(Course(title=name, lessons=[Lesson(title=f"{name} {i}") for i in range(1, 4)]))
    s.commit()

with Session(engine) as s:
    queries.clear()
    for c in s.scalars(select(Course)):
        _ = len(c.lessons)
    print("лениво:", len(queries))                 # лениво: 4  (1 + 3)

with Session(engine) as s:
    queries.clear()
    for c in s.scalars(select(Course).options(selectinload(Course.lessons))):
        _ = len(c.lessons)
    print("selectinload:", len(queries))           # selectinload: 2
```
! В списках — всегда `selectinload` для используемых связей
! `back_populates` связывает обе стороны отношения
! `cascade="all, delete-orphan"` — дочерние записи удаляются с родителем

@lesson FastAPI + база данных
Сессию отдают обработчикам зависимостью с `yield`: она открывается на время запроса и закрывается после него, даже при ошибке. Обработчик получает `db: Session = Depends(get_db)`.
Схемы ответа читают данные прямо из объектов ORM: `model_config = ConfigDict(from_attributes=True)` в Pydantic-модели — тогда можно вернуть объект `Course`, а `response_model` превратит его в JSON.
Код работы с базой выносят в функции-«репозитории» (`crud.py`): обработчики остаются короткими, а логику легко тестировать. Уникальность проверяют до вставки или ловят `IntegrityError` и отвечают 409.
```code
from typing import Annotated
from fastapi import Depends, FastAPI, HTTPException
from fastapi.testclient import TestClient
from pydantic import BaseModel, ConfigDict, Field
from sqlalchemy import String, create_engine, select
from sqlalchemy.orm import DeclarativeBase, Mapped, Session, mapped_column
from sqlalchemy.pool import StaticPool

class Base(DeclarativeBase):
    pass

class Course(Base):
    __tablename__ = "courses"
    id: Mapped[int] = mapped_column(primary_key=True)
    title: Mapped[str] = mapped_column(String(100), unique=True)
    price: Mapped[int] = mapped_column(default=0)

engine = create_engine("sqlite://", poolclass=StaticPool, connect_args={"check_same_thread": False})
Base.metadata.create_all(engine)

def get_db():
    with Session(engine) as session:
        yield session

DB = Annotated[Session, Depends(get_db)]

class CourseIn(BaseModel):
    title: str = Field(min_length=2)
    price: int = Field(default=0, ge=0)

class CourseOut(BaseModel):
    model_config = ConfigDict(from_attributes=True)
    id: int
    title: str
    price: int

app = FastAPI()

@app.post("/courses", response_model=CourseOut, status_code=201)
def create(data: CourseIn, db: DB):
    if db.scalar(select(Course.id).where(Course.title == data.title)):
        raise HTTPException(409, "Такой курс уже есть")
    course = Course(**data.model_dump())
    db.add(course)
    db.commit()
    db.refresh(course)
    return course

@app.get("/courses", response_model=list[CourseOut])
def list_courses(db: DB, max_price: int | None = None):
    stmt = select(Course).order_by(Course.id)
    if max_price is not None:
        stmt = stmt.where(Course.price <= max_price)
    return db.scalars(stmt).all()

c = TestClient(app)
print(c.post("/courses", json={"title": "FastAPI", "price": 4990}).json())
print(c.post("/courses", json={"title": "FastAPI"}).status_code)       # 409
c.post("/courses", json={"title": "Python"})
print([x["title"] for x in c.get("/courses?max_price=1000").json()])   # ['Python']
```
! Сессия — зависимость с `yield`, одна на запрос
! `from_attributes=True` — схема читает объект ORM
! Повторная вставка уникального значения — ответ 409
? mc Зачем `get_db` написана с `yield`, а не `return`?
+ Чтобы закрыть сессию после ответа, даже если обработчик упал
- Чтобы ускорить запрос
- Так требует SQLite
- Чтобы получить несколько сессий
= Код после yield выполняется после обработки запроса.

@lesson Миграции Alembic и PostgreSQL
В продакшене таблицы не создают `create_all`: структура базы меняется миграциями, которые хранятся в Git. Alembic — стандарт для SQLAlchemy: `alembic init migrations`, в `env.py` указывают `target_metadata = Base.metadata`.
Новая миграция: `alembic revision --autogenerate -m "add level to courses"` — Alembic сравнит модели с базой и сгенерирует `upgrade()` и `downgrade()`. Применить — `alembic upgrade head`, откатить — `alembic downgrade -1`. Автогенерацию всегда просматривают глазами.
Для PostgreSQL ставят драйвер `psycopg` (или `asyncpg` для асинхронного режима), адрес берут из переменной окружения `DATABASE_URL`. Пул соединений настраивают `pool_size`, `pool_pre_ping=True`.
```code
# терминал
# pip install sqlalchemy alembic "psycopg[binary]"
# alembic init migrations
# alembic revision --autogenerate -m "create courses"
# alembic upgrade head

# migrations/versions/20261018_add_level.py
from alembic import op
import sqlalchemy as sa

revision = "a1b2c3d4"
down_revision = "9f8e7d6c"

def upgrade() -> None:
    op.add_column("courses", sa.Column("level", sa.String(20), nullable=False, server_default="junior"))
    op.create_index("ix_courses_level", "courses", ["level"])

def downgrade() -> None:
    op.drop_index("ix_courses_level", table_name="courses")
    op.drop_column("courses", "level")

# app/db.py
# import os
# engine = create_engine(os.environ["DATABASE_URL"], pool_size=10, pool_pre_ping=True)
# DATABASE_URL=postgresql+psycopg://app:secret@db:5432/school
```
! Структура базы — только миграциями, не `create_all`
! Автогенерированную миграцию проверяйте перед применением
! Новый NOT NULL столбец — с `server_default`, иначе миграция упадёт на старых строках
? mc Что делает `alembic upgrade head`?
+ Применяет к базе все ещё не выполненные миграции до последней
- Создаёт новую миграцию
- Откатывает последнюю миграцию
- Удаляет базу
= Alembic хранит текущую версию в таблице alembic_version.

- Без этого не работает индекс
