@lesson Composable-функции и разметка
Интерфейс в Compose описывают функциями с аннотацией `@Composable`. Функция не возвращает View, а описывает, что показать: `Text`, `Button`, `Image`. Когда данные меняются, Compose заново вызывает функцию и обновляет только изменившиеся части.
Раскладку строят контейнерами: `Column` — сверху вниз, `Row` — слева направо, `Box` — наложение. Внешний вид задают модификаторы в цепочке: `Modifier.padding(16.dp).fillMaxWidth().clickable { }` — порядок важен.
Цвета и шрифты берут из `MaterialTheme`, превью экрана в Android Studio показывает функция с `@Preview`.
```code
import androidx.compose.foundation.layout.*
import androidx.compose.material3.*
import androidx.compose.runtime.Composable
import androidx.compose.ui.Modifier
import androidx.compose.ui.tooling.preview.Preview
import androidx.compose.ui.unit.dp

data class Course(val title: String, val lessons: Int, val done: Int)

@Composable
fun CourseCard(course: Course, onOpen: () -> Unit) {
    Card(modifier = Modifier.fillMaxWidth().padding(horizontal = 16.dp, vertical = 8.dp)) {
        Column(Modifier.padding(16.dp)) {
            Text(course.title, style = MaterialTheme.typography.titleMedium)
            Text("${course.done} из ${course.lessons} уроков", style = MaterialTheme.typography.bodySmall)
            Spacer(Modifier.height(8.dp))
            LinearProgressIndicator(progress = { course.done / course.lessons.toFloat() }, modifier = Modifier.fillMaxWidth())
            Row(Modifier.fillMaxWidth(), horizontalArrangement = Arrangement.End) {
                TextButton(onClick = onOpen) { Text("Продолжить") }
            }
        }
    }
}

@Preview
@Composable
fun CourseCardPreview() = CourseCard(Course("Kotlin", 8, 3)) {}
```
! Composable-функции называют с большой буквы, как компоненты
! Порядок модификаторов важен: `padding` до `background` и после дают разный результат
! Размеры — в `dp`, текст — в `sp`

@lesson Состояние и рекомпозиция
Состояние в Compose хранят в `mutableStateOf`, обёрнутом в `remember`, чтобы значение пережило перерисовку: `var count by remember { mutableStateOf(0) }`. Изменение состояния вызывает рекомпозицию — повторный вызов функций, которые его читают.
`remember` теряет значение при повороте экрана; `rememberSaveable` сохраняет простые значения и после пересоздания Activity.
Хорошая практика — поднятие состояния (state hoisting): компонент получает значение и колбэк изменения снаружи, а не хранит их сам. Тогда его легко переиспользовать и тестировать.
```code
import androidx.compose.material3.*
import androidx.compose.runtime.*
import androidx.compose.foundation.layout.*

@Composable
fun QuantityPicker(value: Int, onChange: (Int) -> Unit) {          // без своего состояния
    Row {
        Button(onClick = { onChange((value - 1).coerceAtLeast(0)) }) { Text("−") }
        Text(" $value ")
        Button(onClick = { onChange(value + 1) }) { Text("+") }
    }
}

@Composable
fun CartItem(title: String, price: Int) {
    var qty by rememberSaveable { mutableStateOf(1) }                  // состояние наверху
    Column {
        Text(title)
        QuantityPicker(qty, onChange = { qty = it })
        Text("Итого: ${qty * price} ₸")
    }
}
```
! `remember` без `mutableStateOf` не вызовет перерисовку при изменении
! `rememberSaveable` — чтобы состояние пережило поворот экрана
! Поднимайте состояние: компонент получает `value` и `onChange`
? mc Что произойдёт при изменении значения в `mutableStateOf`?
+ Compose перерисует функции, которые читают это значение
- Приложение перезапустится
- Ничего
- Вызовется onCreate
= Это рекомпозиция.
? mc Зачем `remember`?
+ Чтобы значение сохранялось между рекомпозициями, а не создавалось заново
- Чтобы сохранить данные в базу
- Чтобы ускорить сеть
- Для анимации
= Без remember состояние сбрасывалось бы при каждой перерисовке.
? out Что выведет код?


@lesson Списки и ввод
Длинные списки рисует `LazyColumn`: создаются только видимые элементы, поэтому прокрутка тысяч строк остаётся плавной. Элементы задают через `items(list, key = { it.id })` — ключ помогает анимациям и сохранению состояния.
Поле ввода — `TextField` или `OutlinedTextField` со значением из состояния и `onValueChange`. Клавиатуру настраивают через `keyboardOptions` (тип почты, числа), ошибку показывают параметром `isError` и `supportingText`.
Пустое состояние, загрузка и ошибка — отдельные ветки `when`, как и в любом интерфейсе.
```code
import androidx.compose.foundation.lazy.*
import androidx.compose.material3.*
import androidx.compose.runtime.*
import androidx.compose.foundation.text.KeyboardOptions
import androidx.compose.ui.text.input.KeyboardType

data class Note(val id: Long, val text: String)

@Composable
fun Notes() {
    var notes by remember { mutableStateOf(listOf<Note>()) }
    var input by remember { mutableStateOf("") }
    val valid = input.trim().length >= 2

    OutlinedTextField(
        value = input, onValueChange = { input = it },
        label = { Text("Заметка") },
        isError = input.isNotEmpty() && !valid,
        keyboardOptions = KeyboardOptions(keyboardType = KeyboardType.Text),
    )
    Button(enabled = valid, onClick = { notes = notes + Note(System.nanoTime(), input.trim()); input = "" }) { Text("Добавить") }

    if (notes.isEmpty()) Text("Пока пусто")
    else LazyColumn {
        items(notes, key = { it.id }) { note -> Text(note.text) }
    }
}
```
! Для длинных списков — `LazyColumn`, не `Column` с `forEach`
! Давайте элементам стабильный `key`
! Список в состоянии заменяйте новым (`notes + item`), а не изменяйте на месте
? mc Почему для списка из 5000 элементов нужен LazyColumn?
+ Он создаёт только видимые элементы, поэтому экран не тормозит
- Column не поддерживает списки
- LazyColumn сортирует элементы
- Это одно и то же
= Ленивый список экономит память и время отрисовки.

@lesson Навигация и тема
Переходы между экранами делает Navigation Compose: `NavHost` с маршрутами и `navController.navigate("course/42")`. Аргументы маршрута читают из `backStackEntry`. В новых версиях маршруты задают типобезопасно сериализуемыми классами.
Кнопка «назад» работает автоматически через back stack, а `popBackStack()` возвращает на предыдущий экран.
Оформление задаёт `MaterialTheme` с цветовой схемой: светлая и тёмная тема, динамические цвета Android 12+. Цвета берут из `MaterialTheme.colorScheme`, а не пишут вручную в каждом экране.
```code
import androidx.compose.runtime.Composable
import androidx.compose.material3.*
import androidx.navigation.compose.*
import androidx.navigation.NavType
import androidx.navigation.navArgument

@Composable
fun AppNav() {
    val nav = rememberNavController()
    NavHost(navController = nav, startDestination = "courses") {
        composable("courses") {
            CourseList(onOpen = { id -> nav.navigate("course/$id") })
        }
        composable("course/{id}", arguments = listOf(navArgument("id") { type = NavType.LongType })) { entry ->
            val id = entry.arguments?.getLong("id") ?: 0L
            CourseScreen(id = id, onBack = { nav.popBackStack() })
        }
    }
}

@Composable
fun AvalandTheme(dark: Boolean, content: @Composable () -> Unit) {
    MaterialTheme(colorScheme = if (dark) darkColorScheme() else lightColorScheme(), content = content)
}
```
! Экран получает колбэки навигации (`onOpen`, `onBack`), а не сам NavController
! Аргументы — простые id, данные экран загружает сам
! Цвета — из `MaterialTheme.colorScheme`, чтобы работала тёмная тема

- Так быстрее
- Это требование Kotlin
= Поднятие событий — тот же принцип, что и поднятие состояния.
