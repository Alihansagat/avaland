@lesson Тензоры
Тензор — многомерный массив, как в NumPy: у него есть `shape`, `dtype` и операции с broadcasting. Отличия: тензор может лежать на видеокарте (`device`) и запоминать операции для вычисления градиентов.
Создают через `torch.tensor`, `torch.zeros`, `torch.rand`, `torch.arange`. Целые числа по умолчанию `int64`, дробные — `float32` (а не float64, как в NumPy): нейросетям хватает одинарной точности, и она быстрее.
Матричное умножение — `@`, изменение формы — `view` или `reshape`, перевод в NumPy — `.numpy()`, из NumPy — `torch.from_numpy`. Одно число из тензора достают через `.item()`.
```code
import torch

x = torch.tensor([[1., 2.], [3., 4.]])
print(x.shape, x.dtype)          # torch.Size([2, 2]) torch.float32
print(x @ x)                     # tensor([[ 7., 10.], [15., 22.]])
print(x.sum().item())            # 10.0
print(x.view(-1))                # tensor([1., 2., 3., 4.])
print(torch.arange(6).reshape(2, 3).shape)   # torch.Size([2, 3])

device = "cuda" if torch.cuda.is_available() else "cpu"
x = x.to(device)                 # на видеокарту, если она есть
print(x.mean(dim=0))             # tensor([2., 3.])
```
! В PyTorch ось называется `dim`, а не `axis`
! Тензоры для одной операции должны быть на одном устройстве, иначе ошибка
! `.item()` превращает тензор из одного элемента в обычное число Python

@lesson Autograd: градиенты автоматически
Обучение нейросети — это подбор весов, уменьшающих ошибку. Для этого нужны производные ошибки по каждому весу. PyTorch считает их сам: тензор с `requires_grad=True` запоминает операции, а `loss.backward()` вычисляет градиенты и складывает их в `.grad`.
Градиенты накапливаются: перед каждым новым шагом их обнуляют (`optimizer.zero_grad()`). В режиме проверки модели градиенты не нужны — код оборачивают в `with torch.no_grad():`, это экономит память и время.
Шаг градиентного спуска: вес сдвигается против градиента на величину learning rate: `w = w - lr * w.grad`.
```code
import torch

x = torch.tensor(3.0, requires_grad=True)
y = x ** 2 + 2 * x            # y = x² + 2x
y.backward()
print(x.grad)                 # tensor(8.) — производная 2x + 2 при x = 3

w = torch.tensor(0.0, requires_grad=True)
for step in range(50):        # подбираем w, чтобы w * 2 ≈ 10
    loss = (w * 2 - 10) ** 2
    loss.backward()
    with torch.no_grad():
        w -= 0.1 * w.grad
    w.grad.zero_()
print(round(w.item(), 3))     # 5.0
```
! Без `zero_grad` градиенты с прошлых шагов складываются, и обучение ломается
! `torch.no_grad()` — для валидации и предсказаний
! Learning rate слишком большой — ошибка скачет, слишком маленький — обучение очень долгое

? mc Зачем оборачивать предсказания в `with torch.no_grad():`?
+ Чтобы не строить граф вычислений для градиентов и экономить память и время
- Чтобы модель обучалась быстрее
- Чтобы обнулить веса
- Иначе предсказания будут случайными
= При инференсе градиенты не нужны.

- Ничего не изменится
- Градиенты станут нулевыми
= Шаги перепрыгивают минимум.

@lesson Слои и nn.Module
Модель — это класс, наследник `nn.Module`. В `__init__` объявляют слои, в `forward` описывают, как данные проходят через них. Веса слоёв регистрируются автоматически и доступны через `model.parameters()`.
`nn.Linear(in, out)` — полносвязный слой: `y = x @ W.T + b`, у него `in * out + out` параметров. Между линейными слоями ставят нелинейность — `nn.ReLU()`, иначе сеть из многих слоёв равна одному линейному слою.
Для простых сетей есть `nn.Sequential` — список слоёв по порядку. На выходе классификатора обычно сырые оценки (логиты) — функция потерь сама превратит их в вероятности.
```code
import torch
from torch import nn

class Net(nn.Module):
    def __init__(self):
        super().__init__()
        self.hidden = nn.Linear(4, 16)
        self.act = nn.ReLU()
        self.out = nn.Linear(16, 3)

    def forward(self, x):
        return self.out(self.act(self.hidden(x)))

model = Net()
x = torch.rand(8, 4)                  # батч из 8 объектов по 4 признака
print(model(x).shape)                 # torch.Size([8, 3])
print(sum(p.numel() for p in model.parameters()))   # 131 = 4*16+16 + 16*3+3

seq = nn.Sequential(nn.Linear(4, 16), nn.ReLU(), nn.Linear(16, 3))
print(len(list(seq.parameters())))    # 4 — две матрицы весов и два смещения
```
! Вызывайте `model(x)`, а не `model.forward(x)` — так работают хуки PyTorch
! Без нелинейности между слоями глубокая сеть не мощнее линейной модели
! Первая размерность входа — размер батча


@lesson Цикл обучения
Обучение повторяется по эпохам: для каждого батча — прямой проход, функция потерь, `zero_grad`, `backward`, шаг оптимизатора `optimizer.step()`. Для регрессии берут `nn.MSELoss`, для классификации — `nn.CrossEntropyLoss` (на вход логиты и номера классов).
Оптимизатор обновляет веса по градиентам: `torch.optim.SGD` — классический спуск, `Adam` — адаптивный и хороший выбор по умолчанию.
Режимы модели переключают явно: `model.train()` перед обучением, `model.eval()` перед проверкой — это важно для слоёв Dropout и BatchNorm. После каждой эпохи смотрят ошибку на валидации, чтобы поймать переобучение.
```code
import torch
from torch import nn

torch.manual_seed(0)
X = torch.linspace(-1, 1, 64).unsqueeze(1)       # форма (64, 1)
y = 3 * X + 0.5 + 0.05 * torch.randn_like(X)

model = nn.Linear(1, 1)
loss_fn = nn.MSELoss()
opt = torch.optim.Adam(model.parameters(), lr=0.1)

for epoch in range(200):
    model.train()
    pred = model(X)
    loss = loss_fn(pred, y)
    opt.zero_grad()
    loss.backward()
    opt.step()

model.eval()
with torch.no_grad():
    w, b = model.weight.item(), model.bias.item()
print(round(w, 1), round(b, 1))     # 3.0 0.5
print(loss.item() < 0.01)           # True
```
! Порядок в цикле: forward → loss → zero_grad → backward → step
! `CrossEntropyLoss` ждёт логиты, softmax перед ним не нужен
! `model.eval()` и `torch.no_grad()` — при каждой проверке модели
? mc Какой порядок шагов в цикле обучения правильный?
+ forward, loss, zero_grad, backward, step
- step, backward, loss, forward
- backward, forward, step, loss
- zero_grad, step, forward, backward
= Сначала считают ошибку, потом градиенты, потом обновляют веса.

@lesson Данные: Dataset и DataLoader
Данные редко помещаются в один тензор. `Dataset` описывает, как получить один пример: методы `__len__` и `__getitem__`. Для готовых тензоров есть `TensorDataset`.
`DataLoader` нарезает датасет на батчи, перемешивает их (`shuffle=True` для обучения) и может загружать данные параллельно. Размер батча — компромисс: больше батч — быстрее эпоха, но больше памяти.
Для картинок есть `torchvision`: готовые датасеты (MNIST, CIFAR-10), преобразования (`transforms.ToTensor`, `Normalize`, аугментации) и предобученные модели.
```code
import torch
from torch.utils.data import TensorDataset, DataLoader, Dataset

X = torch.arange(10, dtype=torch.float32).unsqueeze(1)
y = (X.squeeze() > 4).long()
ds = TensorDataset(X, y)
print(len(ds), ds[7])                 # 10 (tensor([7.]), tensor(1))

loader = DataLoader(ds, batch_size=4, shuffle=False)
print([xb.shape[0] for xb, yb in loader])   # [4, 4, 2]

class Squares(Dataset):
    def __len__(self):
        return 5
    def __getitem__(self, i):
        return torch.tensor([float(i)]), torch.tensor([float(i * i)])

xb, yb = next(iter(DataLoader(Squares(), batch_size=5)))
print(yb.squeeze().tolist())          # [0.0, 1.0, 4.0, 9.0, 16.0]
```
! `shuffle=True` для обучающего загрузчика, `False` — для валидации
! Последний батч может быть меньше остальных
! Тяжёлые преобразования делайте в `__getitem__` — тогда DataLoader распараллелит их
? out Что выведет код?
```code

```
> 3

- Чтобы уменьшить размер батча

= Перемешивание делает градиентный спуск устойчивее.

@lesson Свёрточные сети, готовые модели и сохранение
Для картинок используют свёрточные слои `nn.Conv2d`: они ищут локальные узоры (края, текстуры) одним и тем же фильтром по всему изображению. Вход имеет форму (батч, каналы, высота, ширина). `nn.MaxPool2d(2)` уменьшает высоту и ширину вдвое.
Обучать большую сеть с нуля дорого. Transfer learning берёт предобученную модель из `torchvision.models` (например, ResNet), замораживает её слои и обучает только новый последний слой под свои классы — хватает нескольких сотен картинок.
Сохраняют обычно не всю модель, а её веса: `torch.save(model.state_dict(), "model.pt")`, загружают через `model.load_state_dict(torch.load("model.pt"))`. Для продакшена модель экспортируют в TorchScript или ONNX.
```code
import torch
from torch import nn

conv = nn.Sequential(
    nn.Conv2d(3, 16, kernel_size=3, padding=1),   # 3 канала RGB → 16 карт признаков
    nn.ReLU(),
    nn.MaxPool2d(2),                               # 32×32 → 16×16
    nn.Conv2d(16, 32, kernel_size=3, padding=1),
    nn.ReLU(),
    nn.AdaptiveAvgPool2d(1),
    nn.Flatten(),
    nn.Linear(32, 10),
)
images = torch.rand(4, 3, 32, 32)
print(conv(images).shape)                  # torch.Size([4, 10])
print(conv[2](conv[1](conv[0](images))).shape)   # torch.Size([4, 16, 16, 16])

# transfer learning (нужен интернет для загрузки весов):
# from torchvision.models import resnet18, ResNet18_Weights
# model = resnet18(weights=ResNet18_Weights.DEFAULT)
# for p in model.parameters(): p.requires_grad = False
# model.fc = nn.Linear(model.fc.in_features, 5)    # 5 своих классов

torch.save(conv.state_dict(), "cnn.pt")
conv.load_state_dict(torch.load("cnn.pt"))
print("веса сохранены и загружены")
```
! Порядок осей картинки в PyTorch: (батч, каналы, высота, ширина)
! `padding=1` при `kernel_size=3` сохраняет размер картинки
! Сохраняйте `state_dict`, а не весь объект модели


? mc Что такое transfer learning?
+ Взять модель, обученную на большом наборе данных, и дообучить её под свою задачу

- Скопировать данные из одной таблицы в другую
- Обучить модель с нуля на маленьких данных
= Предобученные слои уже умеют находить общие признаки, остаётся обучить последний слой.
