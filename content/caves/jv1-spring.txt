@lesson Приложение и REST-контроллер
Spring Boot-приложение создают на start.spring.io: выбирают Java, Maven или Gradle и зависимости (Spring Web, Validation, Data JPA). Точка входа — класс с `@SpringBootApplication` и методом `main`; встроенный Tomcat запускается сам на порту 8080.
`@RestController` отмечает класс, методы которого отвечают JSON. Маршруты задают `@GetMapping`, `@PostMapping`, `@PutMapping`, `@DeleteMapping`; данные из пути — `@PathVariable`, из строки запроса — `@RequestParam`, из тела — `@RequestBody`.
Объекты Java автоматически превращаются в JSON библиотекой Jackson. Для данных ответа удобны `record`.
```code
import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.web.bind.annotation.*;
import java.util.*;

@SpringBootApplication
public class ShopApplication {
    public static void main(String[] args) { SpringApplication.run(ShopApplication.class, args); }
}

record Product(long id, String name, int price) {}

@RestController
@RequestMapping("/api/products")
class ProductController {
    private final Map<Long, Product> store = new HashMap<>(Map.of(1L, new Product(1, "Ноутбук", 450000)));

    @GetMapping
    List<Product> all(@RequestParam(defaultValue = "0") int minPrice) {
        return store.values().stream().filter(p -> p.price() >= minPrice).toList();
    }

    @GetMapping("/{id}")
    Product one(@PathVariable long id) {
        return Optional.ofNullable(store.get(id)).orElseThrow(() -> new NoSuchElementException("нет товара " + id));
    }
}
```
! `@RestController` = `@Controller` + ответ в JSON
! `@PathVariable` — из пути, `@RequestParam` — после `?`, `@RequestBody` — тело
! Запуск: `./mvnw spring-boot:run` или `./gradlew bootRun`

@lesson Бины и внедрение зависимостей
Spring управляет объектами-бинами: создаёт их и связывает. Классы с `@Service`, `@Repository`, `@Component`, `@RestController` становятся бинами при сканировании пакета.
Зависимости передают через конструктор: если у класса один конструктор, Spring сам найдёт нужные бины. Поля делают `final`, а `@Autowired` на поле — устаревший стиль, его трудно тестировать.
Слои приложения: контроллер (HTTP) → сервис (бизнес-логика, транзакции) → репозиторий (база). Контроллер не ходит в базу напрямую.
```code
import org.springframework.stereotype.*;
import org.springframework.web.bind.annotation.*;

interface PriceRules { int discountPercent(int total); }

@Component
class HolidayRules implements PriceRules {
    public int discountPercent(int total) { return total >= 100_000 ? 10 : 0; }
}

@Service
class CartService {
    private final PriceRules rules;
    CartService(PriceRules rules) { this.rules = rules; }      // внедрение через конструктор

    int total(int sum) { return sum * (100 - rules.discountPercent(sum)) / 100; }
}

@RestController
class CartController {
    private final CartService cart;
    CartController(CartService cart) { this.cart = cart; }

    @GetMapping("/api/cart/total")
    int total(@RequestParam int sum) { return cart.total(sum); }
}
```
! Внедряйте зависимости через конструктор и делайте поля `final`
! Зависите от интерфейсов — реализацию легко заменить в тестах
! Слои: Controller → Service → Repository

@lesson Валидация и обработка ошибок
Входные данные описывают DTO-record с аннотациями Bean Validation: `@NotBlank`, `@Email`, `@Size(min = 8)`, `@Positive`. Перед `@RequestBody` ставят `@Valid` — при нарушении Spring вернёт 400.
Ошибки обрабатывают централизованно в классе `@RestControllerAdvice` с методами `@ExceptionHandler`: каждое исключение превращается в понятный ответ с нужным статусом.
Для ответов с явным статусом и заголовками используют `ResponseEntity`: `ResponseEntity.status(201).body(dto)`.
```code
import jakarta.validation.Valid;
import jakarta.validation.constraints.*;
import org.springframework.http.*;
import org.springframework.web.bind.MethodArgumentNotValidException;
import org.springframework.web.bind.annotation.*;
import java.util.*;

record SignupRequest(@NotBlank @Email String email, @Size(min = 8) String password) {}

@RestController
class AuthController {
    @PostMapping("/api/signup")
    ResponseEntity<Map<String, String>> signup(@Valid @RequestBody SignupRequest req) {
        return ResponseEntity.status(HttpStatus.CREATED).body(Map.of("email", req.email()));
    }
}

@RestControllerAdvice
class ApiErrors {
    @ExceptionHandler(NoSuchElementException.class)
    ResponseEntity<Map<String, String>> notFound(NoSuchElementException e) {
        return ResponseEntity.status(404).body(Map.of("error", e.getMessage()));
    }
    @ExceptionHandler(MethodArgumentNotValidException.class)
    ResponseEntity<Map<String, String>> invalid(MethodArgumentNotValidException e) {
        var f = e.getBindingResult().getFieldErrors().get(0);
        return ResponseEntity.badRequest().body(Map.of("error", f.getField() + ": " + f.getDefaultMessage()));
    }
}
```
! Без `@Valid` аннотации на полях не проверяются
! Один `@RestControllerAdvice` на всё приложение — единый формат ошибок
! Не отдавайте клиенту стектрейсы

@lesson Конфигурация, профили и запуск
Настройки лежат в `application.yml` (или `.properties`): порт, адрес базы, логирование. Значения можно брать из переменных окружения: `${DB_URL}`. Секреты в файл не пишут.
Профили (`application-dev.yml`, `application-prod.yml`) меняют настройки под окружение; активный профиль задаёт `SPRING_PROFILES_ACTIVE=prod`.
Spring Boot Actuator добавляет эндпоинты `/actuator/health` и метрики для мониторинга. Приложение собирают в один исполняемый jar: `./mvnw package`, запускают `java -jar target/shop.jar` или в Docker.
```code
# src/main/resources/application.yml
server:
  port: 8080
spring:
  datasource:
    url: ${DB_URL:jdbc:postgresql://localhost:5432/shop}
    username: ${DB_USER:shop}
    password: ${DB_PASSWORD}
app:
  free-delivery-from: 50000
management:
  endpoints.web.exposure.include: health,info

# Java:
# @ConfigurationProperties(prefix = "app")
# record AppProps(int freeDeliveryFrom) {}

# Dockerfile
# FROM eclipse-temurin:21-jre
# COPY target/shop.jar /app.jar
# ENTRYPOINT ["java", "-jar", "/app.jar"]
```
! Секреты — только через переменные окружения
! Профили dev и prod вместо ручной правки настроек
! `/actuator/health` — проверка живости для балансировщика и Kubernetes
