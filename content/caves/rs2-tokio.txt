@lesson async/await и рантайм
`async fn` возвращает Future — описание работы, которое само ничего не делает. Его выполняет рантайм, и результат получают через `.await`: в этот момент задача уступает поток другим, пока ждёт сеть или таймер.
Рантайм Tokio подключают макросом `#[tokio::main]` над `async fn main`. Он запускает пул потоков и выполняет тысячи задач на нескольких ядрах.
Нельзя блокировать асинхронный код долгими синхронными операциями (`std::thread::sleep`, тяжёлые вычисления, синхронное чтение файла): весь поток рантайма встанет. Для них есть `tokio::time::sleep`, `tokio::fs` и `spawn_blocking`.
```code
use std::time::{Duration, Instant};

async fn fetch_price(sku: &str) -> u64 {
    tokio::time::sleep(Duration::from_millis(200)).await;    // имитация сети
    if sku == "A1" { 1500 } else { 999 }
}

#[tokio::main]
async fn main() {
    let start = Instant::now();
    let a = fetch_price("A1").await;                          // последовательно: ~200 мс
    let b = fetch_price("B2").await;                          // ещё ~200 мс
    println!("{} {}", a + b, start.elapsed() >= Duration::from_millis(400));

    let start = Instant::now();
    let (x, y) = tokio::join!(fetch_price("A1"), fetch_price("B2"));   // параллельно: ~200 мс
    println!("{} {}", x + y, start.elapsed() < Duration::from_millis(350));
}
```
! Future ленивые: без `.await` или запуска ничего не произойдёт
! `tokio::join!` — дождаться нескольких Future одновременно
! Никакого `std::thread::sleep` и тяжёлых вычислений внутри async — только `spawn_blocking`

+ Ничего не выполнится: Future ленивый, компилятор предупредит о неиспользованном значении
- Запрос выполнится в фоне
- Программа упадёт
- Выполнится синхронно
= Future нужно дождаться или запустить как задачу.
? mc Почему нельзя вызывать `std::thread::sleep` в async-функции на Tokio?

@lesson Задачи и каналы
`tokio::spawn(async move { ... })` запускает независимую задачу и возвращает `JoinHandle`; `.await` на нём даёт результат. Задачи лёгкие — можно запускать десятки тысяч.
Задачи общаются каналами: `mpsc` — много отправителей, один получатель (очередь работы), `oneshot` — один ответ, `broadcast` — сообщение всем подписчикам, `watch` — последнее значение настройки.
`async move` забирает переменные во владение задачи: данные должны жить столько, сколько задача, поэтому в задачи передают владеемые значения или `Arc`.
```code
use tokio::sync::mpsc;

#[tokio::main]
async fn main() {
    let (tx, mut rx) = mpsc::channel::<u32>(100);

    for worker in 0..3u32 {
        let tx = tx.clone();
        tokio::spawn(async move {
            for i in 0..5 {
                tx.send(worker * 10 + i).await.unwrap();
            }
        });
    }
    drop(tx);                          // иначе rx будет ждать вечно

    let mut sum = 0;
    let mut count = 0;
    while let Some(v) = rx.recv().await {
        sum += v;
        count += 1;
    }
    println!("{count} {sum}");         // 15 180

    let handle = tokio::spawn(async { 6 * 7 });
    println!("{}", handle.await.unwrap());   // 42
}
```
! `recv()` вернёт `None`, только когда все отправители удалены — не забудьте `drop(tx)`
! В `tokio::spawn` передаётся `async move` с владеемыми данными
! Ограниченный канал (`channel(100)`) даёт обратное давление: быстрый отправитель подождёт
? mc Когда `rx.recv().await` вернёт None?
+ Когда все отправители (tx и его клоны) удалены и сообщения закончились
- Через 100 сообщений
- Сразу после первого сообщения
- Никогда
= Поэтому исходный tx нужно удалить после раздачи клонов.
? out Что выведет код?

@lesson Общее состояние: Arc и Mutex
Данные, которые нужны нескольким задачам, оборачивают в `Arc` (счётчик ссылок для многопоточности). Изменяемые данные — в `Arc<Mutex<T>>` или `Arc<RwLock<T>>`.
`std::sync::Mutex` подходит, если блокировка короткая и не держится через `.await`. Если нужно ждать внутри блокировки — `tokio::sync::Mutex`. Счётчики и флаги — атомики `AtomicU64`.
Компилятор Rust не даст передать в другой поток то, что для этого не предназначено (`Send`/`Sync`) — гонки данных отлавливаются при компиляции.
```code
use std::sync::{Arc, Mutex};
use std::sync::atomic::{AtomicU64, Ordering};
use std::collections::HashMap;

#[derive(Default)]
struct AppState {
    visits: AtomicU64,
    carts: Mutex<HashMap<u64, Vec<String>>>,
}

#[tokio::main]
async fn main() {
    let state = Arc::new(AppState::default());
    let mut handles = vec![];
    for user in 0..4u64 {
        let st = Arc::clone(&state);
        handles.push(tokio::spawn(async move {
            st.visits.fetch_add(1, Ordering::Relaxed);
            let mut carts = st.carts.lock().unwrap();          // короткая блокировка без .await внутри
            carts.entry(user % 2).or_default().push(format!("item{user}"));
        }));
    }
    for h in handles { h.await.unwrap(); }
    let carts = state.carts.lock().unwrap();
    println!("{} {}", state.visits.load(Ordering::Relaxed), carts[&0].len());   // 4 2
}
```
! `Arc` — общий доступ, `Mutex`/`RwLock` — изменение
! Не держите `std::sync::Mutex` через `.await`
! Для счётчиков — атомики, без мьютекса
? mc Зачем `Arc` при передаче состояния в несколько задач?

@lesson Таймауты, select и корректное завершение
Любой сетевой вызов оборачивают таймаутом: `tokio::time::timeout(Duration::from_secs(2), fut).await` вернёт ошибку, если не успели.
`tokio::select!` ждёт несколько Future и выполняет ветку того, что завершился первым, — так реализуют отмену, гонку запросов, остановку по сигналу.
Для плавной остановки слушают `tokio::signal::ctrl_c()` или SIGTERM и рассылают сигнал задачам через `CancellationToken` или `watch`-канал: задачи доделывают текущую работу и выходят.
```code
use std::time::Duration;
use tokio::time::{sleep, timeout};

async fn slow() -> &'static str { sleep(Duration::from_millis(500)).await; "медленный" }
async fn fast() -> &'static str { sleep(Duration::from_millis(50)).await; "быстрый" }

#[tokio::main]
async fn main() {
    match timeout(Duration::from_millis(100), slow()).await {
        Ok(v) => println!("{v}"),
        Err(_) => println!("таймаут"),                 // таймаут
    }

    let winner = tokio::select! {
        v = slow() => v,
        v = fast() => v,
    };
    println!("{winner}");                              // быстрый

    let (stop_tx, mut stop_rx) = tokio::sync::watch::channel(false);
    let worker = tokio::spawn(async move {
        let mut ticks = 0;
        loop {
            tokio::select! {
                _ = sleep(Duration::from_millis(10)) => ticks += 1,
                _ = stop_rx.changed() => break,
            }
        }
        ticks
    });
    sleep(Duration::from_millis(55)).await;
    stop_tx.send(true).unwrap();
    println!("{}", worker.await.unwrap() >= 3);       // true
}
```
! Таймаут на каждый внешний вызов
! `select!` отменяет проигравшие ветки — их Future просто удаляются
! Плавная остановка: сигнал всем задачам и ожидание их завершения
