@lesson Миграции и модели
Миграции меняют схему базы кодом: `bin/rails g migration AddLevelToCourses level:string`. Внутри — `create_table`, `add_column`, `add_index`, `add_reference`. Итоговая схема записывается в `db/schema.rb`.
Модель наследует `ApplicationRecord` и сразу умеет `create`, `find`, `update`, `destroy`. Атрибуты берутся из столбцов таблицы автоматически.
Перечисления — `enum :level, { beginner: 0, middle: 1, advanced: 2 }`: появляются методы `course.advanced?` и scope `Course.advanced`.
```code
# db/migrate/20261016_create_courses.rb
class CreateCourses < ActiveRecord::Migration[8.0]
  def change
    create_table :courses do |t|
      t.references :author, null: false, foreign_key: { to_table: :users }
      t.string :title, null: false, limit: 120
      t.integer :price, null: false, default: 0
      t.integer :level, null: false, default: 0
      t.datetime :published_at
      t.timestamps
    end
    add_index :courses, :title, unique: true
  end
end

# app/models/course.rb
class Course < ApplicationRecord
  enum :level, { beginner: 0, middle: 1, advanced: 2 }
  scope :published, -> { where.not(published_at: nil) }
  scope :free, -> { where(price: 0) }
end

# Course.create!(title: "ActiveRecord", author: user, level: :middle)
# Course.published.free.order(created_at: :desc).limit(10)
```
! Ограничения дублируйте в базе: `null: false`, уникальные индексы
! Повторяющиеся условия — в `scope`
! Применённые миграции не меняют — пишут новую

@lesson Валидации и колбэки
Валидации проверяют данные перед сохранением: `validates :title, presence: true, length: { maximum: 120 }, uniqueness: true`, `validates :price, numericality: { greater_than_or_equal_to: 0 }`.
`save` вернёт false и заполнит `errors`, `save!` бросит исключение. `course.errors.full_messages` — тексты для формы.
Колбэки (`before_validation`, `after_create_commit`) запускают код в жизненном цикле записи. Ими нормализуют данные; тяжёлые действия (письма) ставят в очередь в `after_commit`, чтобы не отправить письмо о записи, которую откатили.
```code
class User < ApplicationRecord
  has_secure_password                                # bcrypt: password, authenticate
  normalizes :email, with: ->(e) { e.strip.downcase }

  validates :email, presence: true, uniqueness: true, format: { with: URI::MailTo::EMAIL_REGEXP }
  validates :password, length: { minimum: 8 }, allow_nil: true

  after_create_commit -> { WelcomeMailer.with(user: self).welcome.deliver_later }
end

# user = User.new(email: "  ADA@Mail.KZ ", password: "123")
# user.valid?               → false
# user.email                → "ada@mail.kz"
# user.errors.full_messages → ["Password is too short (minimum is 8 characters)"]
```
! Валидации в модели + ограничения в базе
! `save!` в скриптах и тестах, `save` с проверкой в контроллерах
! Письма — в `after_commit` и через `deliver_later`

+ save возвращает false при ошибке, save! бросает исключение
- Ничем
- save! не проверяет валидации

@lesson Связи и N+1
Связи: `belongs_to :author, class_name: "User"`, `has_many :lessons, dependent: :destroy`, `has_many :students, through: :enrollments`. Получаем `course.lessons`, `user.courses.create(...)`.
Ленивая загрузка в цикле даёт N+1 запросов. `includes(:author)` загружает связи заранее; `strict_loading` или гем Bullet предупреждают о забытых includes.
Счётчики — `counter_cache: true` (столбец `lessons_count` обновляется сам) или `left_joins(:lessons).group(:id).count`.
```code
class Course < ApplicationRecord
  belongs_to :author, class_name: "User"
  has_many :lessons, -> { order(:position) }, dependent: :destroy
  has_many :enrollments, dependent: :destroy
  has_many :students, through: :enrollments, source: :user
end

class Lesson < ApplicationRecord
  belongs_to :course, counter_cache: true          # courses.lessons_count
end

class Enrollment < ApplicationRecord
  belongs_to :user
  belongs_to :course
  validates :user_id, uniqueness: { scope: :course_id }
end

# плохо — 1 + N:
# Course.all.each { |c| puts c.author.name }
# хорошо — 2 запроса:
# Course.includes(:author).each { |c| puts "#{c.title}: #{c.author.name}, уроков #{c.lessons_count}" }
```
! `includes` для всех связей, используемых в списке
! `dependent:` решает судьбу дочерних записей
! Уникальность пары — валидация + уникальный индекс

@lesson Запросы и транзакции
Запросы строят цепочкой: `where`, `where.not`, `order`, `limit`, `joins`, `group`, `having`, `pluck`, `select`. Они ленивые — SQL выполнится при первом обращении к результату. `to_sql` показывает запрос.
Условия передают параметрами: `where("price < ?", max)` или хешем — никогда не вставляйте ввод пользователя в строку SQL.
Связанные изменения — в `ActiveRecord::Base.transaction do ... end`; при исключении всё откатится. Большие таблицы обходят `find_each` пачками по 1000.
```code
# топ-5 курсов по числу студентов за месяц
# Course.joins(:enrollments)
#       .where(enrollments: { created_at: 1.month.ago.. })
#       .group(:id)
#       .order(Arel.sql("COUNT(enrollments.id) DESC"))
#       .limit(5)
#       .pluck(:title)

# безопасно:
# Course.where("title ILIKE ?", "%#{params[:q]}%")
# опасно (SQL-инъекция):
# Course.where("title ILIKE '%#{params[:q]}%'")

# покупка
# ActiveRecord::Base.transaction do
#   wallet = user.wallet.lock!
#   raise ActiveRecord::Rollback if wallet.balance < course.price
#   wallet.decrement!(:balance, course.price)
#   user.enrollments.create!(course:)
# end

# User.where(active: false).find_each { |u| u.update!(archived: true) }

counts = { 1 => 12, 2 => 30, 3 => 7 }
puts counts.sort_by { -_2 }.first(2).map(&:first).inspect    # [2, 1]
```
! Ввод пользователя — только через `?` или хеш
! `find_each` для обхода больших таблиц
! `pluck` вместо загрузки целых объектов, когда нужен столбец
