@lesson Модели SwiftData
SwiftData хранит объекты в локальной базе: класс с макросом `@Model` становится сущностью, его свойства — полями. Контейнер подключают модификатором `.modelContainer(for: Note.self)` у корневого View.
Объекты добавляют через `modelContext.insert(note)`, удаляют — `modelContext.delete(note)`. Изменения сохраняются автоматически, явный `try modelContext.save()` нужен, когда важно сохранить немедленно.
Связи описывают свойствами-ссылками и массивами; `@Relationship(deleteRule: .cascade)` удалит заметки вместе с папкой.
```code
import SwiftUI
import SwiftData

@Model
final class Folder {
    var name: String
    @Relationship(deleteRule: .cascade, inverse: \Note.folder) var notes: [Note] = []
    init(name: String) { self.name = name }
}

@Model
final class Note {
    var text: String
    var createdAt: Date
    var pinned: Bool
    var folder: Folder?
    init(text: String, pinned: Bool = false) {
        self.text = text
        self.createdAt = .now
        self.pinned = pinned
    }
}

@main
struct NotesApp: App {
    var body: some Scene {
        WindowGroup { NotesView() }
            .modelContainer(for: [Folder.self, Note.self])
    }
}
```
! `@Model` — класс, а не структура
! Контейнер подключают один раз у корня приложения
! Каскадное удаление — для зависимых объектов

@lesson Запросы @Query
Свойство `@Query` во View загружает объекты и автоматически обновляет экран при изменениях: `@Query(sort: \Note.createdAt, order: .reverse) var notes: [Note]`.
Фильтр — макрос `#Predicate`: `@Query(filter: #Predicate<Note> { $0.pinned })`. Для динамических фильтров (поиск по тексту) создают `@Query` в инициализаторе дочернего View с параметрами.
`modelContext` берут из окружения: `@Environment(\.modelContext) private var context` — через него добавляют и удаляют объекты.
```code
import SwiftUI
import SwiftData

struct NotesView: View {
    @Environment(\.modelContext) private var context
    @Query(sort: [SortDescriptor(\Note.pinned, order: .reverse), SortDescriptor(\Note.createdAt, order: .reverse)])
    private var notes: [Note]
    @State private var draft = ""

    var body: some View {
        NavigationStack {
            List {
                ForEach(notes) { note in
                    Label(note.text, systemImage: note.pinned ? "pin.fill" : "note.text")
                }
                .onDelete { offsets in offsets.map { notes[$0] }.forEach(context.delete) }
            }
            .safeAreaInset(edge: .bottom) {
                HStack {
                    TextField("Новая заметка", text: $draft).textFieldStyle(.roundedBorder)
                    Button("Добавить") {
                        context.insert(Note(text: draft))
                        draft = ""
                    }.disabled(draft.trimmingCharacters(in: .whitespaces).isEmpty)
                }.padding()
            }
            .navigationTitle("Заметки \(notes.count)")
        }
    }
}
```
! `@Query` сам обновляет экран при изменениях в базе
! Фильтры — через `#Predicate`, сортировка — через `SortDescriptor`
! Изменения делают через `modelContext` из окружения
? mc Что делает свойство с @Query?

@lesson Настройки, Keychain и офлайн
Мелкие настройки (тема, выбранный язык) хранят в UserDefaults через `@AppStorage("theme") var theme = "system"` — значение переживёт перезапуск и обновит интерфейс.
Секреты (токены, пароли) — только в Keychain. Большие файлы — в папке документов или кэша приложения.
Офлайн-подход: экран показывает данные из SwiftData, а сеть обновляет базу в фоне. При ошибке сети данные остаются на экране, а пользователь видит ненавязчивое сообщение.
```code
import SwiftUI

struct SettingsView: View {
    @AppStorage("dailyGoal") private var dailyGoal = 50
    @AppStorage("darkMode") private var darkMode = false

    var body: some View {
        Form {
            Stepper("Цель на день: \(dailyGoal) XP", value: $dailyGoal, in: 10...200, step: 10)
            Toggle("Тёмная тема", isOn: $darkMode)
        }
        .preferredColorScheme(darkMode ? .dark : nil)
    }
}

// синхронизация: сначала показываем кэш, потом обновляем
```

@lesson TestFlight и App Store
Для публикации нужен Apple Developer Program ($99 в год). В App Store Connect создают карточку приложения, в Xcode выбирают «Any iOS Device» и делают Product → Archive → Distribute App → App Store Connect.
TestFlight раздаёт сборки тестировщикам: внутренним — сразу, внешним (до 10 000 человек) — после короткой проверки Apple. Это лучший способ собрать отзывы до релиза.
Перед отправкой на проверку заполняют описание, скриншоты, политику конфиденциальности, раздел App Privacy и возрастной рейтинг. Частые причины отказа: падения, неработающие ссылки, нет удаления аккаунта при наличии регистрации, вход через сторонние сервисы без «Войти через Apple».
```code
// Перед архивом проверьте:
// 1. Bundle Identifier и версия (CFBundleShortVersionString) + номер сборки (CFBundleVersion)
// 2. Иконка 1024×1024 без прозрачности
// 3. Info.plist: описания разрешений, например
//    NSCameraUsageDescription = "Камера нужна, чтобы сфотографировать задачу"
// 4. PrivacyInfo.xcprivacy — манифест приватности
// 5. Release-сборка без отладочных экранов

// Номер сборки должен расти с каждой загрузкой:
let version = "1.2.0"
let build = 37
print("\(version) (\(build + 1))")      // 1.2.0 (38)
```
! Каждая загрузка — новый номер сборки
! TestFlight до релиза — обязательно
! Если есть регистрация — нужно удаление аккаунта в приложении
