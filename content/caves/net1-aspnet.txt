@lesson Minimal API и маршруты
Проект создают командой `dotnet new webapi -n Shop`. В `Program.cs` строится приложение: `var builder = WebApplication.CreateBuilder(args)`, регистрация сервисов, `var app = builder.Build()`, маршруты и `app.Run()`.
Minimal API описывает эндпоинты прямо лямбдами: `app.MapGet("/api/products/{id:int}", (int id) => ...)`. Параметры пути, строки запроса и тела привязываются автоматически по имени и типу.
Ответы с нужным статусом дают `Results.Ok(x)`, `Results.NotFound()`, `Results.Created(url, x)`, `Results.BadRequest(...)`; объекты сериализуются в JSON через System.Text.Json.
```code
var builder = WebApplication.CreateBuilder(args);
var app = builder.Build();

var products = new List<Product> { new(1, "Ноутбук", 450_000), new(2, "Мышь", 9_000) };

app.MapGet("/api/products", (int? minPrice) =>
    products.Where(p => p.Price >= (minPrice ?? 0)));

app.MapGet("/api/products/{id:int}", (int id) =>
    products.FirstOrDefault(p => p.Id == id) is { } p ? Results.Ok(p) : Results.NotFound());

app.MapPost("/api/products", (CreateProduct dto) =>
{
    if (string.IsNullOrWhiteSpace(dto.Name)) return Results.BadRequest(new { error = "name обязателен" });
    var p = new Product(products.Max(x => x.Id) + 1, dto.Name, dto.Price);
    products.Add(p);
    return Results.Created($"/api/products/{p.Id}", p);
});

app.Run();

record Product(int Id, string Name, int Price);
record CreateProduct(string Name, int Price);
```
! Ограничение `{id:int}` вернёт 404, если в пути не число
! `record` — короткий способ описать DTO
! `dotnet watch` перезапускает приложение при изменении кода

@lesson Внедрение зависимостей и слои
Сервисы регистрируют в `builder.Services`: `AddSingleton` — один экземпляр на приложение, `AddScoped` — один на HTTP-запрос (так работают контексты базы данных), `AddTransient` — новый при каждом запросе зависимости.
Зависимость получают параметром эндпоинта или конструктора контроллера: `(IOrderService orders) => ...`. Код зависит от интерфейса, реализацию выбирает регистрация — легко подменить в тестах.
Для больших API используют контроллеры: класс с `[ApiController]` и `[Route("api/[controller]")]`, методы с `[HttpGet]`, `[HttpPost]`; `[ApiController]` сам вернёт 400 при неверной модели.
```code
public interface IPriceService { decimal Total(decimal sum); }

public class DiscountPriceService : IPriceService
{
    public decimal Total(decimal sum) => sum >= 100_000 ? sum * 0.9m : sum;
}

// Program.cs
// builder.Services.AddScoped<IPriceService, DiscountPriceService>();
// builder.Services.AddControllers();
// app.MapControllers();

[ApiController]
[Route("api/[controller]")]
public class CartController : ControllerBase
{
    private readonly IPriceService _prices;
    public CartController(IPriceService prices) => _prices = prices;

    [HttpGet("total")]
    public ActionResult<decimal> Total([FromQuery] decimal sum)
        => sum < 0 ? BadRequest("sum >= 0") : Ok(_prices.Total(sum));
}
```

@lesson Конфигурация, логирование и ошибки
Настройки читают из `appsettings.json`, `appsettings.Development.json`, переменных окружения и секретов пользователя (`dotnet user-secrets`). Удобно привязывать секцию к классу через Options-паттерн: `builder.Services.Configure<ShopOptions>(builder.Configuration.GetSection("Shop"))`.
Логирование встроено: `ILogger<T>` внедряется в любой сервис, уровни `LogInformation`, `LogWarning`, `LogError`, структурированные параметры `{OrderId}`.
Ошибки обрабатывают глобально: `app.UseExceptionHandler()` и формат ProblemDetails (`builder.Services.AddProblemDetails()`) — единый JSON с полями `title`, `status`, `detail`.
```code
// appsettings.json
// { "Shop": { "FreeDeliveryFrom": 50000, "Currency": "KZT" },
//   "ConnectionStrings": { "Db": "Host=localhost;Database=shop;Username=shop" } }

public class ShopOptions
{
    public decimal FreeDeliveryFrom { get; set; }
    public string Currency { get; set; } = "KZT";
}

public class DeliveryService(IOptions<ShopOptions> options, ILogger<DeliveryService> log)
{
    public decimal Cost(decimal orderSum)
    {
        var free = orderSum >= options.Value.FreeDeliveryFrom;
        log.LogInformation("Доставка для заказа {Sum}: бесплатно={Free}", orderSum, free);
        return free ? 0 : 1500;
    }
}

// Program.cs
// builder.Services.Configure<ShopOptions>(builder.Configuration.GetSection("Shop"));
// builder.Services.AddScoped<DeliveryService>();
// builder.Services.AddProblemDetails();
// app.UseExceptionHandler();
```
! Секреты — в user-secrets и переменных окружения, не в appsettings.json в git
! Пишите логи с параметрами `{Name}`, а не склейкой строк — их удобно искать
! ProblemDetails — стандартный формат ошибок API

@lesson Аутентификация и авторизация
Аутентификация отвечает на вопрос «кто это?», авторизация — «что ему можно?». В API чаще всего используют JWT Bearer: `builder.Services.AddAuthentication().AddJwtBearer(...)` и `app.UseAuthentication(); app.UseAuthorization();`.
Доступ ограничивают атрибутом `[Authorize]` или `.RequireAuthorization()` у эндпоинта; роли — `[Authorize(Roles = "Admin")]`, сложные правила — политики `AddAuthorization(o => o.AddPolicy(...))`.
Готовые пользователи, хеши паролей и подтверждение почты — в ASP.NET Core Identity. Текущего пользователя получают из `ClaimsPrincipal user`.
```code
using System.Security.Claims;

var builder = WebApplication.CreateBuilder(args);
builder.Services.AddAuthentication().AddJwtBearer();      // параметры — в appsettings: Authentication:Schemes:Bearer
builder.Services.AddAuthorization(o =>
    o.AddPolicy("Adult", p => p.RequireClaim("age_verified", "true")));
var app = builder.Build();
app.UseAuthentication();
app.UseAuthorization();

app.MapGet("/api/me", (ClaimsPrincipal user) =>
    new { id = user.FindFirstValue(ClaimsTypes.NameIdentifier), name = user.Identity?.Name })
   .RequireAuthorization();

app.MapDelete("/api/admin/users/{id:int}", (int id) => Results.NoContent())
   .RequireAuthorization(p => p.RequireRole("Admin"));

app.Run();
```
! Порядок middleware: `UseAuthentication` перед `UseAuthorization`
! 401 — не вошёл, 403 — нет прав
! Для логинов и паролей не изобретайте своё — используйте Identity
? mc Чем аутентификация отличается от авторизации?
+ Аутентификация определяет, кто пользователь, авторизация — что ему разрешено
- Это одно и то же
- Авторизация происходит раньше
- Аутентификация только для админов
= Сначала узнаём пользователя, потом проверяем права.

+ 401 Unauthorized

- 200
= Пользователь не аутентифицирован.
