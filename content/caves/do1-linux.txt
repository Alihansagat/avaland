@lesson Командная строка и файлы
Терминал — главный инструмент DevOps. Навигация: `pwd` (где я), `ls -la` (файлы со скрытыми и правами), `cd`, `mkdir -p`, `cp -r`, `mv`, `rm -r` (без корзины — осторожно).
Чтение: `cat`, `less`, `head -n 20`, `tail -f app.log` (следить за логом). Поиск: `find . -name "*.log"`, `grep -rn "ERROR" logs/`.
Конвейер `|` передаёт вывод одной команды на вход другой: `cat access.log | grep 500 | wc -l`. Перенаправление: `>` перезаписать файл, `>>` дописать, `2>` — ошибки.
```code
# сколько раз встречается каждый код ответа в логе nginx
cut -d' ' -f9 /var/log/nginx/access.log | sort | uniq -c | sort -rn | head

# найти большие файлы
find /var/log -type f -size +100M -exec ls -lh {} \;

# 10 последних ошибок приложения
grep -n "ERROR" app.log | tail -n 10

# свободное место на дисках и размер папок
df -h
du -sh /var/* 2>/dev/null | sort -h | tail
```
! `rm -rf` не спрашивает и не кладёт в корзину
! Конвейеры из маленьких команд решают большие задачи
! `tail -f` — смотреть лог в реальном времени

@lesson Права, пользователи и процессы
Права файла — три тройки rwx для владельца, группы и остальных: `-rwxr-x---`. Числами: r=4, w=2, x=1 → `chmod 750 deploy.sh`. Владелец меняется `chown app:app file`. `sudo` — выполнить от администратора.
Процессы: `ps aux`, `top`/`htop`, `kill PID` (мягко, сигнал TERM), `kill -9 PID` (принудительно). Сервисы управляются systemd: `systemctl status nginx`, `restart`, `enable` (автозапуск), логи — `journalctl -u nginx -f`.
Приложения запускают не от root, а от отдельного пользователя с минимальными правами.
```code
# скрипт деплоя исполняемый только для владельца и группы
chmod 750 deploy.sh
ls -l deploy.sh        # -rwxr-x--- 1 app app 512 Oct 16 deploy.sh

# сервис приложения: /etc/systemd/system/avaland.service
# [Unit]
# Description=AVALAND API
# After=network.target
# [Service]
# User=app
# WorkingDirectory=/srv/avaland
# ExecStart=/usr/bin/node server.js
# Restart=always
# Environment=NODE_ENV=production
# [Install]
# WantedBy=multi-user.target

sudo systemctl daemon-reload
sudo systemctl enable --now avaland
journalctl -u avaland -f
```
! Сервисы — от отдельного пользователя, не от root
! `kill -9` — последний вариант, процесс не успеет сохраниться
! `Restart=always` перезапустит упавшее приложение

@lesson Сеть и SSH
SSH — безопасный вход на сервер: `ssh app@203.0.113.10`. Вместо паролей используют ключи: `ssh-keygen -t ed25519`, публичный ключ кладут в `~/.ssh/authorized_keys` сервера (`ssh-copy-id`). Вход по паролю и root-вход отключают.
Сетевые команды: `curl -I https://site` (заголовки ответа), `curl -s localhost:3000/health`, `ss -tlnp` (какие порты слушаются), `dig site.kz` (DNS), `ping`, `traceroute`.
Файрвол открывает только нужные порты: 22 (SSH), 80 и 443 (веб). Внутренние сервисы (база, Redis) не должны торчать в интернет.
```code
# на своём компьютере
ssh-keygen -t ed25519 -C "deploy@avaland"
ssh-copy-id app@203.0.113.10

# ~/.ssh/config — короткое имя для сервера
# Host prod
#   HostName 203.0.113.10
#   User app
#   IdentityFile ~/.ssh/id_ed25519
ssh prod

# на сервере
sudo ufw allow 22 && sudo ufw allow 80 && sudo ufw allow 443 && sudo ufw enable
ss -tlnp                       # кто слушает порты
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:3000/health
```
! Ключи вместо паролей, root-вход по SSH выключен
! Открыты только 22, 80 и 443
! База и Redis слушают только внутреннюю сеть

@lesson Скрипты на Bash
Скрипт начинается с `#!/usr/bin/env bash` и строки `set -euo pipefail`: остановиться при ошибке, при необъявленной переменной и при ошибке внутри конвейера.
Переменные: `NAME="avaland"`, использование — `"$NAME"` (всегда в кавычках). Аргументы — `$1`, `$2`, `$#` (количество). Условия `if [[ -f file ]]; then ... fi`, циклы `for f in *.log; do ... done`, функции.
Код возврата: 0 — успех, остальное — ошибка; `$?` хранит код последней команды, `&&` выполнит следующую только при успехе. Повторяющиеся задачи ставят в cron: `0 3 * * * /srv/backup.sh`.
```code
#!/usr/bin/env bash
set -euo pipefail

APP_DIR="/srv/avaland"
KEEP=5

backup() {
  local name="db-$(date +%F).sql.gz"
  pg_dump "$DATABASE_URL" | gzip > "$APP_DIR/backups/$name"
  echo "сохранён $name"
}

cleanup() {
  ls -1t "$APP_DIR"/backups/*.sql.gz | tail -n +$((KEEP + 1)) | xargs -r rm --
}

if [[ $# -gt 0 && "$1" == "--dry-run" ]]; then
  echo "будет сохранён бэкап, останется $KEEP последних"
  exit 0
fi

backup && cleanup
# crontab -e:  0 3 * * * /srv/avaland/backup.sh >> /var/log/backup.log 2>&1
```
! `set -euo pipefail` в начале каждого скрипта
! Переменные — всегда в двойных кавычках
! Бэкапы по cron + проверка, что из них можно восстановиться
