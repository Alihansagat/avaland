@lesson Модули, контроллеры и сервисы
Приложение NestJS делится на модули по функциям: `UsersModule`, `OrdersModule`. Контроллер (`@Controller`) принимает HTTP-запросы и вызывает сервис; сервис (`@Injectable`) содержит бизнес-логику и работу с данными.
Декораторы описывают маршруты: `@Get(":id")`, `@Post()`, параметры — `@Param("id")`, `@Body()`, `@Query()`. Контроллер не должен содержать логику — только принять запрос и вернуть результат сервиса.
Каркас создаёт CLI: `npx @nestjs/cli new shop`, затем `nest g resource books` сгенерирует модуль, контроллер, сервис и DTO.
```code
import { Controller, Get, Post, Param, Body, Injectable, Module, NotFoundException, ParseIntPipe } from "@nestjs/common";

@Injectable()
export class BooksService {
  private books = [{ id: 1, title: "SICP" }];
  findAll() { return this.books; }
  findOne(id: number) {
    const b = this.books.find(x => x.id === id);
    if (!b) throw new NotFoundException(`Книга ${id} не найдена`);
    return b;
  }
  create(title: string) {
    const b = { id: this.books.length + 1, title };
    this.books.push(b);
    return b;
  }
}

@Controller("books")
export class BooksController {
  constructor(private readonly books: BooksService) {}
  @Get() all() { return this.books.findAll(); }
  @Get(":id") one(@Param("id", ParseIntPipe) id: number) { return this.books.findOne(id); }
  @Post() create(@Body() dto: { title: string }) { return this.books.create(dto.title); }
}

@Module({ controllers: [BooksController], providers: [BooksService] })
export class BooksModule {}
```
! Контроллер тонкий, логика — в сервисе
! `NotFoundException` сам превратится в ответ 404
! Один модуль — одна функциональная область

@lesson Внедрение зависимостей
Dependency Injection: класс не создаёт свои зависимости через `new`, а получает их в конструкторе. NestJS сам создаёт сервисы и передаёт их тем, кто их просит, — достаточно указать тип в конструкторе и зарегистрировать провайдер в модуле.
Это упрощает тесты: в тесте можно подставить фальшивую реализацию (например, сервис базы в памяти) вместо настоящей. И заменять реализации: локально — почта в консоль, в проде — настоящий SMTP.
Модули обмениваются провайдерами через `exports` и `imports`. Конфигурацию берут через `ConfigModule` и `ConfigService` из переменных окружения.
```code
import { Injectable, Module } from "@nestjs/common";

export abstract class Mailer {
  abstract send(to: string, text: string): Promise<void>;
}

@Injectable()
export class ConsoleMailer extends Mailer {
  async send(to: string, text: string) { console.log(`письмо ${to}: ${text}`); }
}

@Injectable()
export class SignupService {
  constructor(private readonly mailer: Mailer) {}          // зависимость приходит снаружи
  async signup(email: string) {
    await this.mailer.send(email, "Добро пожаловать в AVALAND");
    return { email };
  }
}

@Module({
  providers: [SignupService, { provide: Mailer, useClass: ConsoleMailer }],
  exports: [SignupService],
})
export class SignupModule {}
```
! Зависимости — через конструктор, не через `new` внутри класса
! Подменяйте реализации через `{ provide, useClass }`
! Чтобы использовать сервис в другом модуле — `exports` здесь и `imports` там

@lesson DTO, валидация и Guards
DTO (Data Transfer Object) — класс, описывающий форму входных данных. С библиотекой class-validator поля размечают декораторами `@IsEmail()`, `@MinLength(8)`, а глобальный `ValidationPipe` сам вернёт 400 с описанием ошибок.
`whitelist: true` выкидывает лишние поля из тела — защита от подмены, например `isAdmin: true` в запросе регистрации.
Guard решает, пускать ли запрос дальше: проверка JWT, ролей, подписки. Его вешают декоратором `@UseGuards` на контроллер или метод.
```code
import { IsEmail, MinLength, IsOptional, IsString } from "class-validator";
import { CanActivate, ExecutionContext, Injectable, UseGuards, Controller, Post, Body, Get, ValidationPipe } from "@nestjs/common";

export class SignupDto {
  @IsEmail() email: string;
  @MinLength(8) password: string;
  @IsOptional() @IsString() name?: string;
}

@Injectable()
export class AdminGuard implements CanActivate {
  canActivate(ctx: ExecutionContext) {
    const req = ctx.switchToHttp().getRequest();
    return req.user?.role === "admin";            // false → 403
  }
}

@Controller("admin")
export class AdminController {
  @UseGuards(AdminGuard)
  @Get("stats") stats() { return { users: 1024 }; }
}

// main.ts
// app.useGlobalPipes(new ValidationPipe({ whitelist: true, forbidNonWhitelisted: true }));
```
! `ValidationPipe` с `whitelist: true` — в каждом проекте
! Guard возвращает true или false; false даёт 403
! DTO описывает контракт API и попадает в документацию Swagger

@lesson Тесты и документация API
Модульный тест сервиса создаёт тестовый модуль `Test.createTestingModule` и подменяет зависимости заглушками через `overrideProvider` или `useValue`. Так проверяют логику без базы и сети.
E2E-тест поднимает приложение целиком и отправляет HTTP-запросы через supertest: `request(app.getHttpServer()).get("/books").expect(200)`.
Документацию API генерирует `@nestjs/swagger`: по контроллерам и DTO строится страница `/docs`, где фронтенд видит все маршруты и может их вызвать. Это ускоряет работу всей команды.
```code
import { Test } from "@nestjs/testing";
import * as request from "supertest";

describe("SignupService", () => {
  it("отправляет приветственное письмо", async () => {
    const mailer = { send: jest.fn().mockResolvedValue(undefined) };
    const moduleRef = await Test.createTestingModule({
      providers: [SignupService, { provide: Mailer, useValue: mailer }],
    }).compile();
    const service = moduleRef.get(SignupService);

    await service.signup("ada@mail.kz");
    expect(mailer.send).toHaveBeenCalledWith("ada@mail.kz", expect.stringContaining("Добро пожаловать"));
  });
});

describe("Books e2e", () => {
  it("GET /books отдаёт список", async () => {
    const moduleRef = await Test.createTestingModule({ imports: [BooksModule] }).compile();
    const app = moduleRef.createNestApplication();
    await app.init();
    await request(app.getHttpServer()).get("/books").expect(200);
    await app.close();
  });
});

// main.ts: SwaggerModule.setup("docs", app, SwaggerModule.createDocument(app, new DocumentBuilder().setTitle("Shop API").build()));
```
! В модульных тестах подменяйте базу и внешние сервисы через `useValue`
! E2E проверяет маршруты, пайпы и guards вместе
! Swagger по DTO — бесплатная документация для фронтенда
