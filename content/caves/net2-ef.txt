@lesson DbContext и сущности
Сущности — обычные классы C#: свойство `Id` становится первичным ключом, остальные — столбцами. `DbContext` описывает базу: свойства `DbSet<Product>` — таблицы. Контекст регистрируют `builder.Services.AddDbContext<ShopDb>(o => o.UseNpgsql(cs))`.
Настройки моделей задают атрибутами (`[MaxLength(200)]`, `[Required]`) или Fluent API в `OnModelCreating`: уникальные индексы, точность decimal, имена таблиц.
DbContext — единица работы: изменения накапливаются в памяти и записываются одним вызовом `SaveChangesAsync()` в транзакции.
```code
using Microsoft.EntityFrameworkCore;

public class Product
{
    public int Id { get; set; }
    public string Name { get; set; } = "";
    public decimal Price { get; set; }
    public int CategoryId { get; set; }
    public Category Category { get; set; } = null!;
}

public class Category
{
    public int Id { get; set; }
    public string Title { get; set; } = "";
    public List<Product> Products { get; set; } = new();
}

public class ShopDb(DbContextOptions<ShopDb> options) : DbContext(options)
{
    public DbSet<Product> Products => Set<Product>();
    public DbSet<Category> Categories => Set<Category>();

    protected override void OnModelCreating(ModelBuilder b)
    {
        b.Entity<Product>().Property(p => p.Price).HasPrecision(12, 2);
        b.Entity<Product>().HasIndex(p => p.Name);
        b.Entity<Category>().HasIndex(c => c.Title).IsUnique();
    }
}
```
! Свойство `Id` или `<Класс>Id` EF Core считает ключом по соглашению
! Для денег — `decimal` с заданной точностью
! Все изменения уходят в базу только при `SaveChangesAsync()`
? mc Что представляет `DbSet<Product>` в DbContext?
+ Таблицу продуктов, к которой можно писать LINQ-запросы
- Один продукт
- Файл миграции
- Кэш в памяти без базы
= DbSet — точка входа в запросы к таблице.
? mc Когда изменения сущностей попадут в базу?
+ При вызове SaveChanges или SaveChangesAsync
- Сразу при изменении свойства
- При перезапуске приложения
- Никогда без ручного SQL
= Контекст отслеживает изменения и сохраняет их пачкой.


@lesson LINQ-запросы
Запросы к базе пишут на LINQ: `Where`, `OrderBy`, `Select`, `Skip`, `Take`, `Count`, `Any`, `GroupBy`. EF Core переводит их в SQL и выполняет, когда результат нужен: `ToListAsync()`, `FirstOrDefaultAsync()`, `CountAsync()`.
`Select` в анонимный тип или DTO загружает только нужные столбцы — так быстрее и безопаснее, чем тянуть целые сущности. Для чтения без изменений добавляют `AsNoTracking()`.
Условия, которые EF не может перевести в SQL, вызывают ошибку — не вызывайте внутри запроса свои C#-методы.
```code
// в эндпоинте или сервисе
var page = 1; var size = 20; var q = "ноут";

var items = await db.Products
    .AsNoTracking()
    .Where(p => p.Name.ToLower().Contains(q) && p.Price > 0)
    .OrderByDescending(p => p.Price)
    .Skip((page - 1) * size)
    .Take(size)
    .Select(p => new { p.Id, p.Name, p.Price, Category = p.Category.Title })
    .ToListAsync();

var stats = await db.Products
    .GroupBy(p => p.Category.Title)
    .Select(g => new { Category = g.Key, Count = g.Count(), Avg = g.Average(p => p.Price) })
    .ToListAsync();

bool hasExpensive = await db.Products.AnyAsync(p => p.Price > 1_000_000);
```
! Запрос выполняется только на `ToListAsync`, `FirstOrDefaultAsync` и подобных
! `AsNoTracking()` для запросов только на чтение
! `Select` в DTO вместо загрузки всей сущности
? mc Когда EF Core отправит SQL в базу?
+ При материализации: ToListAsync, FirstAsync, CountAsync и подобных
- При вызове Where
- При создании DbContext
- При компиляции
= LINQ-запрос строится лениво.
? out Что выведет код?

@lesson Связи, Include и N+1
Связи описывают навигационными свойствами: у продукта `Category`, у категории список `Products`. Внешний ключ `CategoryId` EF найдёт по соглашению. Многие-ко-многим EF Core 5+ поддерживает напрямую через два списка.
Связанные данные по умолчанию не загружаются. `Include(c => c.Products)` подгружает их в том же запросе, `ThenInclude` — следующий уровень. Без этого обращение к пустой навигации даст пустой список или null.
Ленивая загрузка (lazy loading) удобна, но в циклах порождает N+1 запросов. Включайте логирование SQL (`LogTo(Console.WriteLine)`) и смотрите, что реально уходит в базу.
```code
// плохо: N+1
var categories = await db.Categories.ToListAsync();
foreach (var c in categories)
{
    var count = await db.Products.CountAsync(p => p.CategoryId == c.Id);   // запрос на каждую категорию
}

// хорошо: один запрос
var withCounts = await db.Categories
    .Select(c => new { c.Title, Count = c.Products.Count })
    .ToListAsync();

// загрузить связанные сущности целиком
var category = await db.Categories
    .Include(c => c.Products.Where(p => p.Price > 0))
    .FirstOrDefaultAsync(c => c.Title == "Ноутбуки");

// Program.cs, разработка:
// builder.Services.AddDbContext<ShopDb>(o => o.UseNpgsql(cs).LogTo(Console.WriteLine, LogLevel.Information));
```
! Запрос внутри цикла — сигнал проблемы N+1
! `Select` с подсчётом связей — один SQL-запрос
! Смотрите сгенерированный SQL при разработке

@lesson Миграции и транзакции
Схему базы меняют миграциями: `dotnet ef migrations add AddProductStock` создаёт класс миграции из изменений модели, `dotnet ef database update` применяет её. Миграции хранят в репозитории и проверяют на ревью.
В продакшене применяют сгенерированный SQL-скрипт (`dotnet ef migrations script --idempotent`) или миграции при старте с осторожностью — не на нескольких экземплярах одновременно.
`SaveChanges` уже атомарен. Если нужно несколько `SaveChanges` или внешние действия как одно целое — явная транзакция `await using var tx = await db.Database.BeginTransactionAsync()`. Для одновременных изменений защищает `[ConcurrencyCheck]` или `RowVersion`.
```code
public async Task<IResult> ReserveAsync(ShopDb db, int productId, int qty)
{
    await using var tx = await db.Database.BeginTransactionAsync();
    var product = await db.Products.FindAsync(productId);
    if (product is null) return Results.NotFound();
    if (product.Stock < qty) return Results.Conflict(new { error = "Недостаточно на складе" });

    product.Stock -= qty;
    db.Reservations.Add(new Reservation { ProductId = productId, Qty = qty });
    await db.SaveChangesAsync();
    await tx.CommitAsync();
    return Results.Ok(new { left = product.Stock });
}

// терминал:
// dotnet ef migrations add AddStock
// dotnet ef database update
```
! Миграция на каждое изменение модели, миграции — в git
! Без `CommitAsync` транзакция откатится при выходе
! Для конкурентных изменений — токены параллелизма
? mc Что делает `dotnet ef migrations add Name`?

- Создаёт контроллер
