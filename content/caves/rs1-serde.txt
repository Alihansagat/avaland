@lesson Cargo и крейты
Cargo — менеджер пакетов и система сборки Rust. `cargo new shop` создаёт проект, зависимости (крейты с crates.io) пишут в `Cargo.toml` или добавляют командой `cargo add serde --features derive`. Точные версии фиксирует `Cargo.lock`.
Команды на каждый день: `cargo build` (`--release` — с оптимизациями), `cargo run`, `cargo test`, `cargo check` (быстрая проверка без сборки), `cargo clippy` (линтер), `cargo fmt` (форматирование).
Фичи (features) включают части крейта по необходимости: так Tokio не тянет всё подряд, а только нужные модули. Рабочее пространство (workspace) объединяет несколько крейтов одного проекта.
```code
# Cargo.toml
[package]
name = "shop"
version = "0.1.0"
edition = "2024"

[dependencies]
serde = { version = "1", features = ["derive"] }
serde_json = "1"
anyhow = "1"
thiserror = "2"

[dev-dependencies]
pretty_assertions = "1"

# терминал:
# cargo add tokio --features full
# cargo clippy -- -D warnings
# cargo build --release        → target/release/shop
```
! `cargo check` — самый быстрый способ увидеть ошибки компиляции
! `cargo clippy` подсказывает идиоматичный код — включайте в CI
! Включайте у крейтов только нужные features

@lesson Ошибки: anyhow и thiserror
В Rust ошибки — значения типа `Result<T, E>`, а оператор `?` пробрасывает их вверх. Для библиотек и слоёв с понятными ошибками заводят своё перечисление с `thiserror`: `#[derive(Error)]` и сообщение в `#[error("...")]`.
В приложении (main, CLI, обработчики верхнего уровня) удобен `anyhow::Result`: любая ошибка превращается в `anyhow::Error`, а `.context("что делали")` добавляет понятное описание.
`unwrap()` и `expect()` паникуют при ошибке — допустимы в тестах и прототипах, но не в коде сервиса.
```code
use std::fmt;
use std::num::ParseIntError;

#[derive(Debug)]
enum OrderError {
    BadQty(ParseIntError),
    OutOfStock { left: u32 },
}

impl fmt::Display for OrderError {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        match self {
            OrderError::BadQty(e) => write!(f, "неверное количество: {e}"),
            OrderError::OutOfStock { left } => write!(f, "на складе осталось {left}"),
        }
    }
}

impl From<ParseIntError> for OrderError {
    fn from(e: ParseIntError) -> Self { OrderError::BadQty(e) }
}

fn reserve(input: &str, stock: u32) -> Result<u32, OrderError> {
    let qty: u32 = input.trim().parse()?;          // ? превращает ParseIntError в OrderError
    if qty > stock {
        return Err(OrderError::OutOfStock { left: stock });
    }
    Ok(stock - qty)
}

fn main() {
    println!("{:?}", reserve("3", 10).ok());       // Some(7)
    for input in ["abc", "20"] {
        if let Err(e) = reserve(input, 10) {
            println!("{e}");
        }
    }
}
// с thiserror то же короче: #[derive(Debug, thiserror::Error)] enum OrderError { #[error("...")] ... #[from] ... }
```
! Свои ошибки — перечислением (thiserror), в main — anyhow с context
! `?` вызывает `From` и превращает одну ошибку в другую
! Никаких `unwrap()` в коде сервиса
? out Что выведет код?

@lesson Serde: JSON и структуры
Serde превращает структуры Rust в JSON и обратно: `#[derive(Serialize, Deserialize)]`, затем `serde_json::to_string(&x)` и `serde_json::from_str::<T>(s)`.
Атрибуты управляют форматом: `#[serde(rename_all = "camelCase")]` — стиль имён, `#[serde(default)]` — значение по умолчанию для отсутствующего поля, `#[serde(skip_serializing_if = "Option::is_none")]` — не выводить пустое, `#[serde(rename = "type")]` — для зарезервированных слов.
Неизвестную структуру разбирают в `serde_json::Value` и обращаются по ключам — удобно для внешних API, но типизированные структуры надёжнее.
```code
use serde::{Deserialize, Serialize};

#[derive(Debug, Serialize, Deserialize)]
#[serde(rename_all = "camelCase")]
struct Order {
    order_id: u64,
    customer_email: String,
    #[serde(default)]
    items: Vec<Item>,
    #[serde(skip_serializing_if = "Option::is_none")]
    promo_code: Option<String>,
}

#[derive(Debug, Serialize, Deserialize)]
struct Item { sku: String, qty: u32, price: u64 }

fn main() -> serde_json::Result<()> {
    let raw = r#"{"orderId": 7, "customerEmail": "ada@mail.kz", "items": [{"sku": "A1", "qty": 2, "price": 1500}]}"#;
    let order: Order = serde_json::from_str(raw)?;
    let total: u64 = order.items.iter().map(|i| i.qty as u64 * i.price).sum();
    println!("{} {}", order.order_id, total);                // 7 3000
    println!("{}", serde_json::to_string(&order)?);           // promoCode не выводится
    let v: serde_json::Value = serde_json::from_str(raw)?;
    println!("{}", v["items"][0]["sku"]);                     // "A1"
    Ok(())
}
```
! `rename_all = "camelCase"` — когда API в стиле JavaScript
! `Option<T>` — для необязательных полей
! Ошибка разбора JSON — это `Result`, обрабатывайте её
? mc Что делает `#[serde(default)]` у поля?
+ Если поля нет в JSON, берётся значение по умолчанию (например, пустой Vec)
- Делает поле обязательным
- Пропускает поле при сериализации
- Задаёт тип по умолчанию
= Удобно для необязательных списков и флагов.
? mc Как в Rust описать поле JSON, которого может не быть?
+ Option<T>
- Пустой строкой
- Через unsafe
- Через Box<T>
= None соответствует отсутствующему или null значению.

@lesson Конфигурация, логи и тесты
Конфигурацию собирают из переменных окружения в структуру при старте (крейты `envy`, `config` или вручную через `std::env::var`). Если обязательной настройки нет — приложение сразу завершается с понятной ошибкой.
Логи и трейсы в Rust — крейт `tracing`: `tracing::info!(order_id, total, "заказ создан")`, формат и уровни настраивает `tracing-subscriber` (например, через `RUST_LOG=info`).
Тесты пишут в том же файле в модуле `#[cfg(test)] mod tests` с функциями `#[test]`; интеграционные — в папке `tests/`. Запуск — `cargo test`.
```code
use std::env;

#[derive(Debug)]
struct Config {
    port: u16,
    database_url: String,
}

fn load_config_from(get: impl Fn(&str) -> Option<String>) -> Result<Config, String> {
    let port = get("PORT").unwrap_or_else(|| "8080".into()).parse::<u16>().map_err(|e| format!("PORT: {e}"))?;
    let database_url = get("DATABASE_URL").ok_or("DATABASE_URL не задан")?;
    Ok(Config { port, database_url })
}

fn main() {
    let cfg = load_config_from(|k| env::var(k).ok());
    println!("{}", cfg.is_err());        // true, если DATABASE_URL не задан
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn default_port_and_required_db() {
        let cfg = load_config_from(|k| (k == "DATABASE_URL").then(|| "postgres://x".to_string())).unwrap();
        assert_eq!(cfg.port, 8080);
    }

    #[test]
    fn missing_db_is_error() {
        assert!(load_config_from(|_| None).is_err());
    }
}
```
! Проверяйте конфигурацию при старте, а не при первом запросе
! Передавайте источник настроек параметром — так конфиг легко тестировать
! `tracing` вместо `println!` в сервисах
