@lesson Переменные, типы и сравнение
`const` объявляет переменную, которую нельзя переприсвоить, `let` — обычную. `var` устарел: у него функциональная область видимости и всплытие, из-за чего появляются ошибки.
Примитивные типы: `number`, `string`, `boolean`, `null`, `undefined`, `bigint`, `symbol`. Всё остальное — объекты, включая массивы и функции.
`==` сравнивает с приведением типов и даёт неожиданные результаты, поэтому всегда используйте `===`. `NaN` не равен даже самому себе: проверяйте через `Number.isNaN()`.
```code
const user = "Ада";
let score = 10;
score += 5;

console.log(typeof score);       // "number"
console.log(typeof null);        // "object" (историческая ошибка)
console.log(0 == "", 0 === "");  // true false
console.log(0.1 + 0.2 === 0.3);  // false
console.log(Number.isNaN(NaN));  // true
```
! Используйте const по умолчанию, let — когда значение меняется
! Дробные числа хранятся неточно: `0.1 + 0.2` не равно `0.3`
! `typeof null === "object"` — известная особенность языка

@lesson Условия и циклы
Ложными считаются `false`, `0`, `""`, `null`, `undefined`, `NaN`. Всё остальное, включая `[]` и `{}`, истинно.
`for...of` перебирает значения массива или строки, `for...in` — ключи объекта. Классический `for (let i = 0; ...)` нужен, когда важен индекс.
Оператор `??` подставляет значение по умолчанию только для `null` и `undefined`, а `||` — для любого ложного значения. Опциональная цепочка `?.` не падает, если объекта нет.
```code
const items = ["a", "b"];
for (const item of items) console.log(item);

const user = { name: "Ада", settings: null };
console.log(user.settings?.theme ?? "light"); // "light"

const count = 0;
console.log(count || 10);  // 10
console.log(count ?? 10);  // 0

switch (true) {
  case count > 5: console.log("много"); break;
  default: console.log("мало");
}
```
! `[]` и `{}` истинны — пустоту массива проверяют через `.length`
! `??` лучше `||`, когда 0 или пустая строка — допустимые значения
! Не забывайте break в switch

```code

```

= || реагирует на ложные значения, ?? — только на null и undefined.

@lesson Функции и замыкания
Функцию можно объявить через `function`, функциональное выражение или стрелку `=>`. Объявления `function` всплывают и доступны до строки объявления.
Замыкание — функция, которая помнит переменные места, где её создали. На замыканиях строятся счётчики, приватные данные и колбэки.
У стрелочных функций нет своего `this`: они берут его из внешней области. Поэтому стрелки удобны в колбэках, но не подходят как методы объекта, которым нужен `this`.
```code
function makeCounter() {
  let count = 0;
  return () => ++count;
}
const next = makeCounter();
next(); next();
console.log(next());           // 3

const greet = (name = "гость") => `Привет, ${name}`;
const sum = (...nums) => nums.reduce((a, b) => a + b, 0);
console.log(greet(), sum(1, 2, 3)); // Привет, гость 6
```
! Каждый вызов makeCounter создаёт новое замыкание с собственным count
! Параметр по умолчанию срабатывает только для undefined
! `...rest` собирает аргументы в настоящий массив
? out Что выведет код?
```code

console.log(add(2)(3));
```
> 5
= add(2) возвращает функцию, которая помнит a = 2.

@lesson Массивы и их методы
`map` преобразует каждый элемент, `filter` отбирает, `reduce` сворачивает в одно значение, `find` возвращает первый подходящий элемент, `some` и `every` проверяют условие.
Методы `push`, `pop`, `splice`, `sort`, `reverse` меняют исходный массив. `map`, `filter`, `slice`, `concat` и новые `toSorted` возвращают новый.
`sort()` без функции сравнивает элементы как строки, поэтому числа сортируют так: `arr.sort((a, b) => a - b)`.
```code
const orders = [
  { id: 1, total: 120, paid: true },
  { id: 2, total: 80,  paid: false },
  { id: 3, total: 200, paid: true },
];
const revenue = orders
  .filter(o => o.paid)
  .reduce((sum, o) => sum + o.total, 0);   // 320
const ids = orders.map(o => o.id);         // [1, 2, 3]
const big = orders.find(o => o.total > 150);
console.log([10, 9, 1].sort());            // [1, 10, 9]
console.log([10, 9, 1].sort((a, b) => a - b)); // [1, 9, 10]
```
! sort без компаратора ломает числа
! forEach ничего не возвращает, для преобразования нужен map
! Цепочки filter → map → reduce читаются лучше вложенных циклов
? out Что выведет код?
```code

```
> [100, 20, 3]
> 100,20,3
= Сравнение как строк: "100" < "20" < "3".

> [10, 30]
= Нечётные 1 и 3, умноженные на 10.

@lesson Объекты, деструктуризация и JSON
Объект хранит пары ключ–значение. Деструктуризация достаёт поля в переменные: `const { name, age } = user`. Можно задать значение по умолчанию и переименовать поле.
Spread `...` копирует поля в новый объект или элементы в новый массив. Это поверхностная копия: вложенные объекты остаются общими. Глубокую копию делает `structuredClone`.
`JSON.stringify` превращает объект в строку для отправки или хранения, `JSON.parse` — обратно. Функции и `undefined` в JSON не попадают.
```code
const user = { name: "Ада", role: "admin", meta: { visits: 3 } };
const { name, role: position, age = 18 } = user;
console.log(name, position, age);      // Ада admin 18

const copy = { ...user, name: "Алан" };
copy.meta.visits = 100;
console.log(user.meta.visits);         // 100: вложенный объект общий

const json = JSON.stringify({ a: 1, f() {} });
console.log(json);                     // {"a":1}
```
! Spread копирует только верхний уровень
! Два разных объекта с одинаковыми полями не равны по ===
! `Object.entries(obj)` удобно перебирать через for...of
? out Что выведет код?

@lesson Классы и прототипы
Класс в JavaScript — удобный синтаксис над прототипами. `constructor` заполняет объект, методы попадают в прототип и общие для всех экземпляров.
`extends` наследует класс, `super()` вызывает конструктор родителя и обязателен до обращения к `this`. Поля с `#` приватные: снаружи их не прочитать.
`static` методы принадлежат самому классу. Геттер `get` позволяет читать вычисляемое значение как свойство.
```code
class Account {
  #balance = 0;
  constructor(owner) { this.owner = owner; }
  deposit(sum) {
    if (sum <= 0) throw new Error("Сумма должна быть больше 0");
    this.#balance += sum;
    return this;
  }
  get balance() { return this.#balance; }
  static fromJSON(data) { return new Account(data.owner); }
}

class Savings extends Account {
  constructor(owner, rate) {
    super(owner);
    this.rate = rate;
  }
}
const s = new Savings("Ада", 0.1).deposit(100);
console.log(s.balance, s instanceof Account); // 100 true
```
! В наследнике вызовите super() до первого this
! `return this` позволяет строить цепочки вызовов
! Приватное поле #x нельзя прочитать как obj.#x снаружи класса

@lesson Асинхронность и event loop
JavaScript выполняет код в одном потоке. Долгие операции (сеть, таймеры) уходят в фон, а их колбэки возвращаются через очередь event loop.
Микрозадачи (`Promise.then`, `await`) выполняются раньше макрозадач (`setTimeout`). Поэтому `setTimeout(fn, 0)` сработает после всех готовых промисов.
`Promise.all` ждёт все промисы и падает на первой ошибке, `Promise.allSettled` ждёт все и сообщает результат каждого. Независимые запросы запускайте параллельно, а не последовательными await.
```code
console.log("1");
setTimeout(() => console.log("2"), 0);
Promise.resolve().then(() => console.log("3"));
console.log("4");
// 1 4 3 2

async function loadAll(ids) {
  const res = await Promise.all(
    ids.map(id => fetch(`/api/items/${id}`).then(r => r.json()))
  );
  return res;
}
```
! await в цикле for делает запросы по очереди — это медленно
! fetch не отклоняет промис на 404: проверяйте `res.ok`
! Необработанный отклонённый промис — ошибка в продакшене
? out Что выведет код?
```code
setTimeout(() => console.log("A"), 0);
Promise.resolve().then(() => console.log("B"));
console.log("C");
```
> C B A
= Сначала синхронный код, потом микрозадачи, потом таймеры.

- Выбросит исключение
+ Успешно вернёт Response с ok = false
- Вернёт undefined
- Повторит запрос
= Промис отклоняется только при сетевой ошибке.

+ Ждёт все промисы и не падает на первой ошибке
- Возвращает самый быстрый результат
- Выполняет промисы по очереди
- Ничем

@lesson DOM и события
DOM — дерево элементов страницы, доступное из JavaScript. Элементы находят через `querySelector`, создают через `createElement`, а текст меняют через `textContent`.
Пользовательские данные вставляйте через `textContent`, а не `innerHTML`: иначе через ввод можно внедрить чужой скрипт (XSS).
`addEventListener` подписывает на событие. Делегирование: один обработчик на родителе ловит клики по всем дочерним элементам, даже добавленным позже. `event.preventDefault()` отменяет действие по умолчанию, например отправку формы.
```code
const list = document.querySelector("#todos");
const form = document.querySelector("#add");

form.addEventListener("submit", (e) => {
  e.preventDefault();
  const li = document.createElement("li");
  li.textContent = form.title.value;     // безопасно
  list.append(li);
  form.reset();
});

list.addEventListener("click", (e) => {
  const item = e.target.closest("li");
  if (item) item.classList.toggle("done");
});
```
! innerHTML с данными пользователя — дыра XSS
! Скрипт с type="module" выполняется после разбора HTML
! Делегирование экономит обработчики и работает для новых элементов
? mc Почему нельзя вставлять ввод пользователя через innerHTML?
- Это медленно
+ Можно внедрить вредоносный HTML и скрипты (XSS)
- innerHTML не работает с формами
- Текст потеряет пробелы
= textContent вставляет текст как есть.
? mc Что делает `event.preventDefault()` в обработчике submit?
+ Отменяет отправку формы и перезагрузку страницы
- Останавливает всплытие события
- Удаляет форму
- Очищает поля
= Всплытие останавливает stopPropagation.
