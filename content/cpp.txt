@lesson Основы: типы, ввод-вывод, компиляция
C++ компилируется в машинный код: компилятор (g++, clang++) превращает исходники в исполняемый файл. Ошибки типов ловятся при компиляции.
Основные типы: `int`, `long long`, `double`, `bool`, `char`, а строки — `std::string`. `auto` выводит тип из инициализатора. Неинициализированная локальная переменная содержит мусор.
Ввод-вывод через потоки: `std::cin >> x`, `std::cout << x`. `'\n'` быстрее `std::endl`, потому что не сбрасывает буфер.
```cpp
#include <iostream>
#include <string>

int main() {
    std::string name;
    int age = 0;                       // всегда инициализируйте
    std::cin >> name >> age;
    auto years = age + 1;              // int
    std::cout << name << ": " << years << '\n';
    std::cout << 7 / 2 << ' ' << 7 / 2.0 << '\n';  // 3 3.5
    return 0;
}
// g++ -std=c++20 -Wall -Wextra main.cpp -o app
```

@lesson Условия, циклы и строки
Условия `if` / `else if` / `else` и `switch` для целых и перечислений. В switch без `break` выполнение проваливается в следующий case. `if` с инициализатором (C++17): `if (auto it = m.find(k); it != m.end())`.
Циклы `for`, `while`, `do-while` и range-based for: `for (const auto& x : v)`. Используйте `const auto&`, чтобы не копировать элементы.
`std::string` — изменяемая строка: `size()`, `substr`, `find` (возвращает `npos`, если не нашлось), `+=`. Для числа из строки — `std::stoi`, обратно — `std::to_string`.
```cpp
#include <string>

std::string s = "hello, world";
auto pos = s.find(',');
if (pos != std::string::npos) {
    std::string first = s.substr(0, pos);     // "hello"
    std::cout << first << '\n';
}

for (char& c : s) c = std::toupper(static_cast<unsigned char>(c));

int sum = 0;
for (int i = 1; i <= 10; ++i) {
    if (i % 2) continue;
    sum += i;                                  // 30
}

switch (sum / 10) {
    case 3: std::cout << "тридцать\n"; break;
    default: std::cout << "другое\n";
}
std::cout << std::stoi("42") + 1 << ' ' << std::to_string(3.5) << '\n';
```

@lesson Функции, ссылки и указатели
Аргументы по умолчанию передаются по значению — копируются. Большие объекты передают по константной ссылке `const T&`: без копии и без права изменить.
Ссылка `T&` — псевдоним существующего объекта, она не бывает пустой. Указатель `T*` хранит адрес, может быть `nullptr` и переназначаться. `&x` берёт адрес, `*p` разыменовывает.
Нельзя возвращать ссылку или указатель на локальную переменную: после выхода из функции она уничтожена.
```cpp
void increment(int& n) { ++n; }
int sumAll(const std::vector<int>& v) {
    int s = 0;
    for (int x : v) s += x;
    return s;
}

int main() {
    int a = 5;
    increment(a);                    // a = 6
    int* p = &a;
    *p = 10;                         // a = 10
    int* none = nullptr;
    if (none) { /* не выполнится */ }
    std::cout << a << ' ' << sumAll({1, 2, 3}) << '\n';  // 10 6
}
```

@lesson Классы и RAII
Класс объединяет данные и методы. `public` члены доступны всем, `private` — только классу. Конструктор инициализирует объект, лучше через список инициализации.
RAII: ресурс захватывают в конструкторе и освобождают в деструкторе `~Class()`. Объект вышел из области видимости — ресурс освободился, даже при исключении.
Правило нуля: если класс хранит ресурсы через стандартные типы (`std::string`, `std::vector`, умные указатели), не пишите деструктор и копирование вручную.
```cpp
class Account {
public:
    explicit Account(std::string owner, double balance = 0)
        : owner_(std::move(owner)), balance_(balance) {}

    void deposit(double sum) {
        if (sum <= 0) throw std::invalid_argument("sum <= 0");
        balance_ += sum;
    }
    double balance() const { return balance_; }

private:
    std::string owner_;
    double balance_;
};

class Timer {
public:
    Timer()  { start_ = std::chrono::steady_clock::now(); }
    ~Timer() { /* вывести затраченное время */ }
private:
    std::chrono::steady_clock::time_point start_;
};
```
! Методы, не меняющие объект, помечайте const
! explicit запрещает неявные преобразования
! Порядок инициализации полей — порядок объявления, а не списка

@lesson Динамическая память и умные указатели
`new` выделяет память в куче, `delete` освобождает. Забыли delete — утечка, удалили дважды — неопределённое поведение. В современном C++ ручной new/delete почти не нужен.
`std::unique_ptr` единолично владеет объектом и удаляет его сам. Его нельзя копировать, только перемещать через `std::move`. Создают через `std::make_unique`.
`std::shared_ptr` — совместное владение со счётчиком ссылок. Циклические ссылки shared_ptr не освобождаются — разрывают их через `std::weak_ptr`.
```cpp
#include <memory>

struct Node { int value; };

auto a = std::make_unique<Node>(Node{42});
// auto b = a;               // ошибка: копирование запрещено
auto b = std::move(a);       // владение передано, a == nullptr

auto s1 = std::make_shared<Node>(Node{7});
auto s2 = s1;
std::cout << s1.use_count();  // 2

std::weak_ptr<Node> w = s1;
if (auto locked = w.lock()) std::cout << locked->value;
```
! По умолчанию — unique_ptr, shared_ptr только когда владение реально общее
! После std::move старым объектом пользоваться нельзя
! Обращение к удалённой памяти — неопределённое поведение

@lesson STL: контейнеры
`std::vector` — динамический массив и выбор по умолчанию. `std::map` — отсортированный словарь (дерево, O(log n)), `std::unordered_map` — хэш-таблица (O(1) в среднем). `std::set` хранит уникальные отсортированные значения.
`operator[]` у map создаёт элемент, если ключа нет. Для проверки используйте `find` или `contains` (C++20).
При вставке в vector итераторы и ссылки на элементы могут стать недействительными — вектор перевыделяет память. `reserve` заранее выделяет место.
```cpp
std::vector<int> v;
v.reserve(100);
for (int i = 0; i < 5; ++i) v.push_back(i * i);

std::unordered_map<std::string, int> count;
for (const auto& w : {"a", "b", "a"}) ++count[w];
std::cout << count["a"] << '\n';            // 2
std::cout << count.contains("z") << '\n';   // 0

std::map<std::string, int> sorted(count.begin(), count.end());
for (const auto& [key, val] : sorted)       // структурная привязка
    std::cout << key << '=' << val << ' ';
```

! vector почти всегда быстрее list из-за кэша процессора
! Структурные привязки `auto [k, v]` делают перебор map читаемым

@lesson STL: алгоритмы и лямбды
Заголовок `<algorithm>` содержит готовые алгоритмы: `sort`, `find_if`, `count_if`, `transform`, `accumulate` (в `<numeric>`), `remove_if`. Используйте их вместо ручных циклов.
Лямбда `[захват](параметры) { тело }` создаёт функцию на месте. `[=]` захватывает по значению, `[&]` — по ссылке, можно перечислить переменные явно.
`remove_if` не удаляет элементы, а сдвигает их и возвращает новый конец. Удаление — идиома erase-remove или `std::erase_if` в C++20. С C++20 есть ranges: `std::ranges::sort(v)`.
```cpp
#include <algorithm>
#include <numeric>

std::vector<int> v{5, 3, 8, 1, 9, 2};
std::sort(v.begin(), v.end(), [](int a, int b) { return a > b; });

int limit = 4;
auto big = std::count_if(v.begin(), v.end(), [limit](int x) { return x > limit; });
int sum = std::accumulate(v.begin(), v.end(), 0);

std::erase_if(v, [](int x) { return x % 2 == 0; });   // C++20

auto it = std::find_if(v.begin(), v.end(), [](int x) { return x < 3; });
if (it != v.end()) std::cout << *it;
```
! Захват [&] опасен, если лямбда переживёт переменные
! remove_if без erase не уменьшает размер контейнера
! find возвращает end(), если ничего не нашлось

@lesson Шаблоны, move-семантика и сборка
Шаблоны пишут код один раз для разных типов: `template <typename T> T maxOf(T a, T b)`. Компилятор генерирует версию для каждого типа. Концепты C++20 (`std::integral`) ограничивают допустимые типы.
Move-семантика передаёт ресурсы вместо копирования. `std::move` превращает объект в rvalue, и вызывается конструктор перемещения — вектор из миллиона элементов «переедет» за O(1).
Проекты собирают через CMake. Код делят на заголовки (.h, объявления) и исходники (.cpp, реализация). Заголовок защищают от двойного включения `#pragma once`.
```cpp
#include <concepts>

template <std::integral T>
T gcd(T a, T b) {
    while (b != 0) { T t = a % b; a = b; b = t; }
    return a;
}

std::vector<std::string> make() {
    std::vector<std::string> v(1'000'000, "x");
    return v;                    // перемещение или elision, не копия
}

// CMakeLists.txt
// cmake_minimum_required(VERSION 3.20)
// project(tasks CXX)
// set(CMAKE_CXX_STANDARD 20)
// add_executable(tasks main.cpp task.cpp)
```
! Реализацию шаблонов обычно держат в заголовке
! Не пишите `return std::move(local);` — это мешает оптимизации
! Санитайзеры -fsanitize=address,undefined находят ошибки памяти

? mc Что такое data race?
+ Доступ из нескольких потоков к одной памяти, где хотя бы один пишет, без синхронизации
- Медленная работа потока
- Ошибка компиляции
- Утечка памяти
= Это неопределённое поведение. Защищают std::mutex или std::atomic.
? mc Что делает `std::lock_guard<std::mutex> lock(m);`?

- Создаёт новый поток
- Блокирует программу навсегда
- Копирует мьютекс
= Это RAII для мьютексов.
