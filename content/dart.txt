@lesson Переменные, типы и null safety
`var` выводит тип, `final` задаёт значение один раз во время выполнения, `const` — константа времени компиляции. Предпочитайте final и const.
Dart имеет строгую null-безопасность: тип `String` не может быть null, `String?` — может. Операторы `?.`, `??` и `??=` работают с nullable значениями, `!` утверждает «здесь не null».
Строковая интерполяция: `'$name'` или `'${user.name}'`. Целочисленное деление — оператор `~/`.
```dart
void main() {
  final name = 'Ада';
  const pi = 3.14;
  var score = 10;
  score += 5;

  String? nickname;
  print(nickname ?? 'Гость');        // Гость
  nickname ??= 'ada';                // присвоить, если null
  print('$name: ${score * 2}, ${nickname.length}');
  print(7 ~/ 2);                     // 3
  print(7 / 2);                      // 3.5
}
```
! final — значение известно при запуске, const — при компиляции
! `/` всегда даёт double, для целого деления `~/`
! late откладывает инициализацию non-null переменной
? out Что выведет код?
```dart
print(9 ~/ 4 + 9 % 4);
```
> 3
= 9 ~/ 4 = 2, 9 % 4 = 1.
? mc Чем const отличается от final?
+ const вычисляется при компиляции, final — один раз во время выполнения
- Ничем
- final быстрее
- const можно менять
= DateTime.now() можно сохранить в final, но не в const.


= Если cache уже не null, ничего не произойдёт.

```dart

```
> -1
= s равно null.

@lesson Функции и коллекции
Функции могут иметь именованные параметры в фигурных скобках `{required String name, int age = 0}` и необязательные позиционные в квадратных. Короткая функция пишется через `=>`.
Коллекции: `List`, `Set`, `Map`. Методы `map`, `where`, `fold`, `any`, `firstWhere` работают с Iterable и ленивы, пока не вызван `toList()`.
Collection if и for позволяют строить списки прямо в литерале — это часто используется при построении виджетов. Spread `...` вставляет элементы другого списка.
```dart
String greet({required String name, String greeting = 'Привет'}) =>
    '$greeting, $name!';

void main() {
  print(greet(name: 'Ада'));

  final nums = [1, 2, 3, 4, 5];
  final evens = nums.where((n) => n.isEven).map((n) => n * 10).toList();
  final sum = nums.fold(0, (a, b) => a + b);

  final isAdmin = true;
  final menu = ['Главная', if (isAdmin) 'Админка', for (var i in [1, 2]) 'Пункт $i'];
  final ages = {'Ада': 36, 'Алан': 41};

  print('$evens $sum $menu ${ages['Ада']}');
  // [20, 40] 15 [Главная, Админка, Пункт 1, Пункт 2] 36
}
```
! required делает именованный параметр обязательным
! where и map возвращают ленивый Iterable — добавьте toList()
! map[key] вернёт null для отсутствующего ключа
? out Что выведет код?

@lesson Классы и конструкторы
Классы в Dart лаконичны: `User(this.name, this.age)` присваивает поля прямо из параметров. Именованные конструкторы `User.guest()` создают объекты по-разному. `factory` может вернуть уже существующий объект или подкласс.
Поля с `final` делают объект неизменяемым — так пишут модели данных. Метод `copyWith` возвращает копию с изменёнными полями.
`extends` наследует, `implements` реализует интерфейс (любой класс может быть интерфейсом), `with` подмешивает mixin.
```dart
class User {
  final String name;
  final int age;
  const User(this.name, this.age);

  User.guest() : name = 'Гость', age = 0;

  factory User.fromJson(Map<String, dynamic> json) =>
      User(json['name'] as String, json['age'] as int);

  User copyWith({String? name, int? age}) =>
      User(name ?? this.name, age ?? this.age);

  @override
  String toString() => 'User($name, $age)';
}

mixin Logger { void log(String m) => print('[LOG] $m'); }
class Service with Logger { void run() => log('запуск'); }
```
! Модели делайте неизменяемыми: final поля и copyWith
! fromJson обычно factory-конструктор
! Для генерации ==, copyWith и JSON используют freezed и json_serializable

@lesson Records, pattern matching и sealed
Dart 3 добавил records — лёгкие неизменяемые кортежи: `(String, int)` или с именованными полями `({String name, int age})`. Функция может вернуть сразу несколько значений.
Pattern matching работает в `switch`, `if-case` и при деструктуризации: `var (name, age) = person;`. Switch-выражение возвращает значение и проверяет полноту.
`sealed class` закрывает набор наследников внутри файла. Switch по sealed-типу без default компилятор проверит на полноту — идеально для состояний экрана.
```dart
(String, int) parse(String line) {
  final parts = line.split(':');
  return (parts[0], int.parse(parts[1]));
}

sealed class LoadState {}
class Loading extends LoadState {}
class Loaded extends LoadState { final List<String> items; Loaded(this.items); }
class Failed extends LoadState { final String message; Failed(this.message); }

String render(LoadState s) => switch (s) {
  Loading() => 'Загрузка…',
  Loaded(:final items) when items.isEmpty => 'Пусто',
  Loaded(:final items) => 'Элементов: ${items.length}',
  Failed(:final message) => 'Ошибка: $message',
};

void main() {
  final (name, score) = parse('Ада:90');
  print('$name $score ${render(Loaded(['a']))}');   // Ада 90 Элементов: 1
}
```
! Records сравниваются по значению
! sealed + switch без default ловит забытые состояния
! when в шаблоне добавляет условие
? out Что выведет код?
```dart
final r = (1, b: 'x');
print('${r.$1}${r.b}');
```
> 1x
= Позиционные поля доступны как $1, $2, именованные — по имени.
? mc Что даёт sealed class?
+ Закрытый набор наследников и проверку полноты switch
- Запрет на создание объектов
- Неизменяемость полей
- Автоматический toString
= Наследники объявляются в том же файле.
? fill Впишите ключевое слово условия внутри шаблона switch.
```dart

```
> when
= Охранное условие.


@lesson Асинхронность: Future и Stream
`Future<T>` — результат, который появится позже. Функция `async` возвращает Future, а `await` ждёт его. Ошибки ловят обычным try/catch.
`Future.wait` запускает несколько операций параллельно. Dart однопоточный с event loop; тяжёлые вычисления выносят в изолят (`Isolate.run`), чтобы не тормозил интерфейс.
`Stream<T>` — последовательность значений во времени: события, сообщения чата, изменения базы. Подписываются через `listen` или `await for`.
```dart
Future<String> loadUser() async {
  await Future.delayed(const Duration(milliseconds: 300));
  return 'Ада';
}

Future<void> main() async {
  try {
    final results = await Future.wait([loadUser(), loadUser()]);
    print(results);                       // [Ада, Ада]
  } catch (e) {
    print('Ошибка: $e');
  }

  final ticks = Stream.periodic(const Duration(seconds: 1), (i) => i).take(3);
  await for (final t in ticks) {
    print('Тик $t');
  }
}
```
! Забытый await — частая ошибка: операция не дождётся
! Future.wait быстрее последовательных await для независимых задач
! Isolate.run для парсинга больших JSON

@lesson Виджеты Flutter
Во Flutter всё — виджеты. `StatelessWidget` рисует интерфейс по параметрам, `StatefulWidget` хранит состояние в объекте `State`, а `setState` запрашивает перерисовку.
Раскладка строится из вложенных виджетов: `Column`, `Row`, `Stack`, `Padding`, `Expanded`, `ListView.builder` для длинных списков.
Метод `build` вызывается часто, поэтому он должен быть быстрым и без побочных эффектов. Используйте `const` конструкторы — Flutter не будет пересоздавать такие виджеты.
```dart
import 'package:flutter/material.dart';

class Counter extends StatefulWidget {
  const Counter({super.key});
  @override
  State<Counter> createState() => _CounterState();
}

class _CounterState extends State<Counter> {
  int _count = 0;

  @override
  Widget build(BuildContext context) {
    return Column(
      mainAxisAlignment: MainAxisAlignment.center,
      children: [
        Text('Нажатий: $_count', style: Theme.of(context).textTheme.headlineSmall),
        const SizedBox(height: 12),
        FilledButton(
          onPressed: () => setState(() => _count++),
          child: const Text('Ещё'),
        ),
      ],
    );
  }
}
```

! Не вызывайте сетевые запросы в build

@lesson Состояние и архитектура
Локальное состояние живёт в StatefulWidget, а общее (пользователь, корзина) выносят в менеджер состояния. Популярные решения: Riverpod, Bloc, Provider.
Слои приложения: UI (виджеты) → контроллер/Notifier (логика и состояние) → репозиторий (откуда брать данные) → источники данных (API, база). UI не знает про HTTP.
Состояние экрана описывают явно: загрузка, данные, ошибка. В Riverpod `AsyncValue` уже содержит эти варианты, а `ref.watch` перерисовывает виджет при изменении.
```dart
final ratesProvider = FutureProvider<List<Rate>>((ref) async {
  final repo = ref.watch(ratesRepositoryProvider);
  return repo.fetchRates();
});

class RatesScreen extends ConsumerWidget {
  const RatesScreen({super.key});

  @override
  Widget build(BuildContext context, WidgetRef ref) {
    final rates = ref.watch(ratesProvider);
    return rates.when(
      loading: () => const Center(child: CircularProgressIndicator()),
      error: (e, _) => Center(child: Text('Ошибка: $e')),
      data: (list) => ListView.builder(
        itemCount: list.length,
        itemBuilder: (_, i) => ListTile(title: Text(list[i].code)),
      ),
    );
  }
}
```
! Всегда показывайте состояния загрузки и ошибки
! Репозиторий позволяет подменить API в тестах
! Не храните бизнес-логику в виджетах
